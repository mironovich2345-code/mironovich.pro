# Блог: как добавить статью

Каждая статья — один файл `content/blog/<slug>.md`. Больше ничего менять не нужно:
страница статьи, карточка в `/blog`, sitemap, canonical, OpenGraph и BlogPosting JSON-LD
собираются автоматически. Этот README и файлы, имя которых начинается с `_`, в блог не попадают.

Если в папке нет ни одной статьи со `status: published`, `/blog` показывает пустое
состояние — фейковых материалов нет.

## Шаблон

```md
---
title: Как выстроить адаптацию новичка, чтобы она не зависела от одного руководителя
description: Одно-два предложения для поисковой выдачи и превью в мессенджерах, до 160 символов.
slug: adaptatsiya-novichka-bez-zavisimosti-ot-rukovoditelya
publishDate: 2026-10-01
category: Адаптация
excerpt: Короткий анонс для карточки на странице /blog. Если не указан — берётся description.
status: draft
coverImage: /blog/adaptatsiya-novichka.png
coverImageAlt: Что описывает картинка — одной фразой
---

Первый абзац статьи.

## Заголовок раздела

Текст раздела.

![Что описывает картинка](/blog/adaptatsiya-novichka.png "Подпись под картинкой")
```

## Поля frontmatter

| Поле | Обязательно | Что это |
|---|---|---|
| `title` | да | H1 страницы и основа `<title>`. Единственный H1 на странице |
| `seoTitle` | нет | Заголовок для `<title>` (без « | MIRONOVICH» — суффикс добавится сам), если он должен отличаться от H1, например когда H1 слишком длинный для выдачи. OG и JSON-LD остаются с `title` |
| `description` | да | meta description, OpenGraph, JSON-LD |
| `slug` | да | URL: `/blog/<slug>`. Латиница в нижнем регистре, цифры, дефисы. Уникальный |
| `publishDate` | да | `ГГГГ-ММ-ДД` — `datePublished` |
| `category` | да | Метка над заголовком: «Адаптация», «Базы знаний», «AI» и т. п. |
| `status` | да | `draft` — черновик, `published` — опубликована |
| `excerpt` | нет | Анонс для списка `/blog`. По умолчанию — `description` |
| `updatedDate` | нет | `ГГГГ-ММ-ДД` — `dateModified`. Указывать, только когда статью реально правили |
| `readingTime` | нет | Минуты, целое число. По умолчанию считается по тексту (200 слов в минуту) |
| `coverImage` | нет | Путь к картинке в `public/`, например `/blog/scheme.png`. Превью на `/blog`, Open Graph и `image` в JSON-LD. Без неё работает общая картинка сайта |
| `coverImageAlt` | если есть `coverImage` | Описание картинки для OG и скринридеров |
| `order` | нет | Целое число. Порядок среди статей с одинаковой `publishDate`: меньше — выше. Иначе такие статьи идут по алфавиту slug |

Значение — всё после первого `:` в строке; кавычки не нужны (можно, если в тексте есть `"`).
Неизвестное поле, пустое обязательное, неверная дата или повторяющийся slug **остановят сборку**
с понятным сообщением — статья не может тихо опубликоваться с ошибкой.

## Что можно писать в тексте

- `##` и `###` — заголовки. `#` не используется: H1 берётся из `title`.
- Абзацы, `- ` маркированные и `1. ` нумерованные списки (без вложенности).
- `> ` цитаты.
- `**жирный**`, `*курсив*`, `` `код` ``, блоки кода в тройных обратных кавычках.
- `[ссылка](/about)`, `[ссылка](https://...)`, `[якорь](#id)`. Внешние ссылки открываются в новой вкладке.
- `---` — разделитель.
- Картинка — отдельной строкой: `![alt](/blog/file.png "подпись")`. Файл должен лежать в `public/`
  (png, jpg, webp), alt обязателен, подпись (в кавычках) необязательна и выводится мелким текстом под картинкой.
  Размеры читаются из файла сами. Рендер через `next/image`; на телефоне картинка занимает всю ширину,
  на десктопе чуть шире текста, по клику открывается оригинал. Картинку внутри строки текста ставить нельзя.

Сырого HTML нет. `coverImage` на странице статьи сам не показывается — чтобы картинка была в тексте,
поставьте её строкой `![…](…)` в нужное место.

## Черновик и публикация

1. Создать файл со `status: draft`. Черновик виден **только** в `npm run dev` по прямому адресу
   `/blog/<slug>` (с пометкой и `noindex`). В `/blog`, sitemap и production-сборку он не попадает,
   по адресу на боевом сайте отдаёт 404.
2. Для публикации сменить на `status: published`, проверить `publishDate`, задеплоить.

## Чек-лист перед публикацией

- [ ] `title` осмысленный и уникальный, не длиннее ~60 символов
- [ ] `description` 120–160 символов, без кликбейта
- [ ] `slug` не меняется после публикации (это URL)
- [ ] картинка лежит в `public/`, есть `coverImageAlt`, оригинал не подменён
- [ ] нет выдуманных клиентов, цифр, кейсов и отзывов
- [ ] `npm run typecheck` и `npm run build` проходят
