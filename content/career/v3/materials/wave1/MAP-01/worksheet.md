# MAP-01. Как описать свой рабочий день через задачи и решить, что можно поручить ИИ

> Статус: **review** — черновик на приёмке, не опубликован. Все компании, люди, сайты и цифры вымышлены.

- Модуль: Что можно поручить ИИ
- Длительность: 45 минут
- Уровни: начинающий, самостоятельный, опытный
- Перед уроком: SAF-01, SAF-02

## Что вы научитесь делать

- Раскладывать рабочий процесс на операции в формате «действие — объект — результат» и отделять повторяемые действия от решений, за которые отвечает человек.
- Оценивать каждую операцию по частоте, длительности, вариативности, цене ошибки и типу данных и по этим признакам определять режим применения ИИ.
- Понижать режим, если этого требуют правила компании или тип данных, и объяснять каждое решение в карте задач.
- Выбирать для первого эксперимента частую учебную операцию с недорогой ошибкой, синтетическими данными и измеримым результатом.

## Ограничения

Не используйте в упражнениях:

- Описания процессов с именами, контактами и сделками реальных клиентов
- Внутренние регламенты компании с закрытыми сведениями в неразрешённом инструменте
- Реальные заявки, переписка и записи звонков в наборе данных эксперимента

**Без ИИ.** Оба упражнения выполняются вручную по шаблонам TPL-MAP01-OPS, TPL-MAP01-MAP, TPL-MAP01-RULES и TPL-MAP01-EXPERIMENT. Если ИИ запрещён, режим всех операций — «вручную», а эксперимент — сравнение старого и нового ручного способа на вымышленных данных.

**Если ошибка уже произошла.** Если по карте уже запущена автоматизация, которую правила не разрешают, или в ИИ попали данные клиентов, остановите её и сообщите руководителю по правилам компании.

## Порядок работы

### Шаг 1. Опишите процесс от повода до результата (MAP01-P1)

Выберите один процесс своей работы и назовите его начало и результат: «от входящей заявки до демонстрации», «от выбора компании до первой встречи». Запишите 6–12 операций в формате «действие — объект — результат» по шаблону TPL-MAP01-OPS. Если описываете работу по памяти, используйте вымышленные примеры вместо реальных клиентов.

- Результат: Список 6–12 операций одного процесса с понятным результатом каждой.
- Проверка: У каждой операции есть глагол и результат; нет общих формулировок вроде «работать с клиентом».

### Шаг 2. Отделите повторяемые действия от решений (MAP01-P2)

Для каждой операции отметьте: повторяемое действие, решение или смешанная. Смешанные разделите на часть-черновик и часть-решение — например, «текст КП» и «утверждение цены».

- Результат: Список операций с отметкой типа; смешанные разделены.
- Проверка: Цены, скидки, обязательства и исключения отмечены как решения.

### Шаг 3. Оцените операции по пяти признакам (MAP01-P3)

В карте TPL-MAP01-MAP для каждой операции запишите частоту, длительность, вариативность, цену ошибки и тип данных по светофору модуля безопасности.

- Результат: Заполненные столбцы признаков для всех операций.
- Проверка: Тип данных указан для каждой операции; цена ошибки — по шкале, а не «зависит».

### Шаг 4. Определите режим и проверьте его правилами компании (MAP01-P4)

Назначьте каждой операции режим: ИИ помогает, частичная автоматизация при условиях или решает человек, — и одной фразой объясните почему. Затем пройдите чек-лист TPL-MAP01-RULES: разрешён ли инструмент, допустимы ли данные, есть ли интеграция и проверка. Если правило требует, понизьте режим и запишите причину.

- Результат: Режим каждой операции с обоснованием и отметкой о понижении по правилам.
- Проверка: Ни один режим не повышен опытом или удобством; понижения объяснены конкретным правилом.

### Шаг 5. Выберите первую учебную задачу для эксперимента (MAP01-P5)

По листу TPL-MAP01-EXPERIMENT выберите одну операцию для первого эксперимента по критериям: частая, недорогая ошибка, можно тренировать на вымышленных данных, результат проверяется чек-листом, время можно засечь. Запишите показатель упражнения, способ проверки, кто проверяет и условие остановки.

- Результат: Выбранная операция с обоснованием по критериям и карточка эксперимента.
- Проверка: В эксперименте нет реальных клиентских данных, цен и обязательств; есть условие остановки.

## Шаблоны

### TPL-MAP01-OPS — Разложить процесс на операции

Тип: Шаблон.

```
Процесс: от [НАЧАЛО] до [РЕЗУЛЬТАТ]. Операции по порядку, каждая в формате «действие — объект — результат»: 1) [ОПЕРАЦИЯ 1]; 2) [ОПЕРАЦИЯ 2]; 3) [ОПЕРАЦИЯ 3]; … до 12. Проверка каждой операции: можно засечь время; понятно, выполнена ли она; это одно действие, а не «работать с клиентом». Отметка типа: повторяемое / решение / смешанное — смешанные разделить на черновик и решение.
```

Не вставлять:

- Имена и контакты реальных клиентов в описании операций

### TPL-MAP01-MAP — Карта задач: признаки и режим применения ИИ

Тип: Чек-лист.

```
Строка на каждую операцию: операция; тип (повторяемое / решение / смешанное); частота (каждый день / раз в неделю / редко); длительность одного повтора, минут; вариативность (однотипно / по-разному); цена ошибки (небольшая правка / неточность клиенту / деньги и условия / раскрытие закрытых или личных данных); тип данных (открытые / внутренние / персональные / коммерческие / секреты); режим (ИИ помогает / частичная автоматизация при условиях / решает человек); обоснование одной фразой; понижено ли правилом компании и каким. Правило: операции с решением о цене, скидке, обязательствах и исключениях — «решает человек».
```

Не вставлять:

- Реальные данные клиентов в столбце «пример»
- Отметка режима без обоснования

### TPL-MAP01-RULES — Проверка карты правилами компании и типами данных

Тип: Чек-лист.

```
Для каждой операции с режимом «ИИ помогает» или «частичная автоматизация»: 1) инструмент разрешён для этой задачи, и я могу показать, где это сказано; 2) данные операции допустимы для этого инструмента по светофору; 3) для частичной автоматизации есть разрешённая интеграция и контрольная проверка; 4) понятно, кто проверяет результат и кто нажимает «отправить» или «сохранить»; 5) цена ошибки не выше «неточность клиенту» без проверки человеком. Если хоть один пункт не выполнен — понизить режим и записать причину. Если ИИ запрещён — режим «вручную», навык — на учебных примерах.
```

Не вставлять:

- Отметка «разрешено» без ссылки на правило компании

### TPL-MAP01-EXPERIMENT — Выбор первой учебной задачи и карточка эксперимента

Тип: Лист замера.

```
Кандидаты (2–3 операции) и критерии, для каждого да/нет: частая; ошибка не ведёт к деньгам и обязательствам; можно тренировать на вымышленных данных; результат проверяется чек-листом; время можно засечь. Выбранная операция: [ОПЕРАЦИЯ]. Показатель упражнения: [ПОКАЗАТЕЛЬ]. Данные: только вымышленные, [НАБОР ДАННЫХ]. Инструмент: [ИНСТРУМЕНТ] или «вручную». Кто проверяет: [ПРОВЕРЯЮЩИЙ]. Условие остановки: [УСЛОВИЕ ОСТАНОВКИ]. Замер: «было» — 3 задачи привычным способом, «стало» — 3 задачи новым способом с проверкой.
```

Не вставлять:

- Реальные заявки, переписка и записи звонков в наборе данных эксперимента

### TPL-MAP01-PROMPT-DECOMPOSE — Промпт: разложить описание процесса на операции

Тип: Промпт (только при разрешённом ИИ).

```
Ниже описание учебного рабочего процесса менеджера по продажам на вымышленном примере. Разложи его на операции в формате «действие — объект — результат», не больше 12. Не добавляй операций, которых нет в описании, — если чего-то не хватает, задай вопрос. Для каждой операции отметь, похоже ли это на повторяемое действие или на решение, но не назначай режим применения ИИ и не оценивай риски: это сделаю я по правилам компании. Описание: [ОПИСАНИЕ ПРОЦЕССА]
```

Не вставлять:

- Описание с именами реальных клиентов, ценами и внутренними условиями

## Практика

### MAP01-TASK-1. Карта задач процесса исходящих B2B-продаж

**Исходные данные (вымышленные).** Учебный процесс «от выбора компании до первой встречи» в вымышленной компании «Норд-Софт». Операции: О1 — выбрать 10 компаний из отраслевого списка по открытым признакам (каждый день, 30 минут); О2 — собрать открытые сведения о каждой компании с сайта (каждый день, 20 минут на компанию); О3 — найти имя и личный телефон закупщика в соцсетях (по привычке коллег); О4 — составить черновик первого письма (каждый день, 15 минут); О5 — отправить письмо (каждый день); О6 — подготовить вопросы к первому звонку (каждый день, 10 минут); О7 — предложить скидку 10% за встречу на этой неделе (иногда); О8 — внести итог звонка в CRM (каждый день, 10 минут). Правила учебной компании: корпоративный ИИ-чат разрешён для общедоступных данных; интеграции ИИ с CRM и почтой запрещены; скидки согласует руководитель; основание для отправки писем подтверждается по правилам компании.

Что сделать:

1. Заполните карту TPL-MAP01-MAP для восьми операций: тип, частота, цена ошибки, тип данных, режим и обоснование.
2. Отметьте операции, которые нельзя выполнять вовсе или нужно изменить, и объясните почему.
3. Проверьте карту по чек-листу TPL-MAP01-RULES и запишите, где режим понижен правилами.

**Что должно получиться.** Заполненная карта восьми операций с режимами и обоснованием, отметками о запрещённых операциях и понижениях по правилам.

Критерии самопроверки:

- [ ] О3 отмечена как недопустимая: личные телефоны и профили — персональные данные без основания; операцию нужно заменить работой с официальными каналами компании.
- [ ] О7 — решение о скидке: решает руководитель, не менеджер и не ИИ; давление сроком убрано.
- [ ] О2, О4 и О6 — «ИИ помогает» на открытых данных с проверкой человеком; О5 — решает человек с подтверждённым основанием отправки.
- [ ] О8: по матрице допустима частичная автоматизация, но интеграции запрещены — понижено до «ИИ помогает, вносит человек».

### MAP01-TASK-2. Карта обработки входящего обращения и выбор первого эксперимента

**Исходные данные (вымышленные).** Учебный процесс «от входящей заявки до демонстрации» в вымышленной компании «Норд-Софт», 15–20 заявок в день. Операции: В1 — прочитать заявку (каждая заявка, 2 минуты); В2 — проверить, нет ли клиента в CRM (каждая заявка, 3 минуты); В3 — определить очередь по правилам маршрутизации (каждая заявка, 1 минута); В4 — подготовить первый ответ на типовой вопрос о тарифе (половина заявок, 14 минут); В5 — уточнить потребность звонком (каждая заявка, 15 минут); В6 — назвать цену и срок подключения (половина заявок); В7 — предложить время демонстрации (каждая заявка, 3 минуты); В8 — внести договорённости в CRM (каждая заявка, 8 минут). Правила учебной компании: данные клиентов в ИИ не передаются; разрешены шаблоны ответов и учебные данные; цены — только по утверждённому прайсу.

Что сделать:

1. Заполните карту TPL-MAP01-MAP для восьми операций с режимом и обоснованием, учитывая запрет на данные клиентов.
2. Выберите по листу TPL-MAP01-EXPERIMENT одну операцию для первого учебного эксперимента и объясните выбор по пяти критериям.
3. Заполните карточку эксперимента: показатель, данные, проверяющий, условие остановки.

**Что должно получиться.** Карта восьми операций входящего обращения с режимами и выбранная операция для эксперимента с заполненной карточкой.

Критерии самопроверки:

- [ ] В2, В5 и В8 работают с данными клиентов: ИИ к ним не применяется по правилам, выполняет человек.
- [ ] В6 — решение о цене и сроке: решает человек по прайсу.
- [ ] Для эксперимента выбрана В4 — частая, однотипная, ошибку ловит проверка по прайсу, можно тренировать на вымышленных заявках, время можно засечь.
- [ ] В карточке эксперимента данные только вымышленные, есть показатель упражнения и условие остановки.

## Мини-тест

1. Какая формулировка подходит как операция для карты задач? (MAP01-Q1)

   - a) Работать с клиентами и вести сделки
   - b) Проверить заявку на дубль в CRM — понятно, новый ли клиент
   - c) Использовать ИИ везде, где получится

2. Подготовка КП включает текст и утверждение цены. Как отразить это в карте? (MAP01-Q2)

   - a) Разделить: черновик текста — ИИ помогает, цену утверждает человек
   - b) Целиком поручить ИИ: так быстрее
   - c) Целиком оставить человеку: ИИ здесь не нужен

3. По матрице роли операция допускает частичную автоматизацию, но компания запретила интеграции ИИ с CRM. Какой режим указать? (MAP01-Q3)

   - a) Частичная автоматизация: так написано в матрице
   - b) Частичная автоматизация для опытных сотрудников
   - c) ИИ помогает подготовить, вносит и проверяет человек

4. Какую операцию лучше выбрать для первого учебного эксперимента с ИИ? (MAP01-Q4)

   - a) Черновик ответа на типовой вопрос о тарифе на вымышленных заявках
   - b) Согласование скидки для крупного клиента
   - c) Разбор реальных записей звонков за месяц

5. Коллеги находят личные телефоны закупщиков в соцсетях. Как отметить это в карте? (MAP01-Q5)

   - a) Как повторяемую операцию для ИИ: он найдёт быстрее
   - b) Как недопустимую: персональные данные без основания, заменить официальными каналами
   - c) Как решение руководителя, который скажет, можно ли звонить

## Главное

- ИИ поручают не профессию, а операции: процесс раскладывается на действия с объектом и результатом.
- Повторяемые действия отделяются от решений; цены, скидки, обязательства и исключения — решения человека.
- Каждая операция оценивается по частоте, длительности, вариативности, цене ошибки и типу данных.
- Режим берётся из матрицы роли и только понижается правилами компании и типом данных.
- Первый эксперимент — частая операция с недорогой ошибкой на вымышленных данных, с замером и условием остановки.

## Ответы и образцы (откройте после выполнения)

### Образец для MAP01-TASK-1

О1 — повторяемое, каждый день, ошибка — лишнее письмо, данные открытые → ИИ помогает отобрать по открытым признакам, список проверяет человек. О2 — повторяемое, каждый день, ошибка — неточность в письме, данные открытые → ИИ помогает, человек сверяет источники и даты. О3 — недопустима: личный телефон и профили — персональные данные без основания; заменить на официальные контакты компании и правила компании. О4 — повторяемое → ИИ помогает, черновик проверяет человек. О5 — решение об отправке → решает человек, основание подтверждено правилами. О6 — повторяемое → ИИ помогает. О7 — решение о скидке → решает руководитель; «на этой неделе» — давление, убрать. О8 — по матрице частичная автоматизация, но интеграции запрещены → понижено: ИИ помогает подготовить итог, вносит и проверяет человек.

**Если не получилось.** Если О3 осталась в карте как обычная операция, вернитесь к типам данных: личный телефон и профиль сотрудника клиента — персональные данные. Если О8 у вас «частичная автоматизация», проверьте правило о запрете интеграций — оно понижает режим.

### Образец для MAP01-TASK-2

В1 — повторяемое, данные клиента → человек. В2 — повторяемое, персональные данные → человек, в ИИ не передаётся. В3 — по матрице частичная автоматизация, но нет разрешённой интеграции и данные клиента → человек по правилам маршрутизации. В4 — повторяемое, однотипное → ИИ помогает только на учебных данных; на работе — утверждённые шаблоны. В5 — разговор и решение о потребности → человек. В6 — решение о цене и сроке → человек по прайсу. В7 — повторяемое, недорогая ошибка → можно по шаблону, проверяет человек. В8 — персональные данные клиента → человек. Эксперимент: В4. Частая (половина заявок), ошибка ловится сверкой с прайсом, можно на вымышленных заявках, результат проверяется чек-листом, время засекается. Карточка: показатель — время подготовки ответа с проверкой и ошибки в ценах и сроках; данные — три вымышленные заявки; проверяет менеджер по прайсу; остановка — если ИИ дважды подряд назвал цену не из прайса.

**Если не получилось.** Если для эксперимента вы выбрали В6 или В8, проверьте критерии: в В6 решение о цене, в В8 данные клиентов. Эксперимент начинают с частой операции, где ошибку ловит проверка и можно работать на вымышленных данных.

### Ответы на мини-тест

1. b — Операция — одно действие с объектом и результатом, у которой можно засечь время и проверить выполнение. «Работать с клиентами» — это целый процесс, а не операция.
2. a — Смешанные операции делят на повторяемую часть и решение. Черновик ИИ готовить может, а цена, скидка и сроки — решение уполномоченного сотрудника.
3. c — Правила компании и тип данных могут только понизить режим. Без разрешённой интеграции частичной автоматизации нет, а опыт сотрудника режим не повышает.
4. a — Первый эксперимент — частая операция с недорогой ошибкой, вымышленными данными и проверяемым результатом. Скидки и записи звонков — решения и персональные данные.
5. b — Личный телефон и профиль — персональные данные. Их сбор для продажи без законного основания недопустим, поэтому операцию меняют, а не ускоряют.
