# ЮKassa — подготовка сайта к проверке по реально предлагаемым услугам

Состояние: ветка feature/yookassa-merchant-review-services-20261117, основной сайт не обновлён. **НЕ ОТПРАВЛЯТЬ НА ПРОВЕРКУ ДО ПУБЛИКАЦИИ И КОНТРОЛЬНОГО СПИСКА НИЖЕ.**

## Выбранный сценарий
- Модерация сайта как исполнителя **действительно доступных услуг** по разработке, автоматизации, техническому сопровождению и экспертизе, а не магазина с готовыми цифровыми товарами.
- Показаны действующие из main коммерческие предложения: CTO 150 000 ₽/мес., до 30 часов; 5 пилотов с базовыми ценами 65 000, 69 000, 89 000, 99 000 и 180 000 ₽. Цена каждого пилота — «от», точная смета после согласования.
- Заказ текущих услуг — по заявке и индивидуальному письменному согласованию объёма, цены и сроков. Онлайн-оплата за них **не подключена**. Первичное обсуждение бесплатно.
- Цифровые продукты из /products (включая диагностику за 1 990 ₽) по-прежнему **не продаются**. На время проверки услуг они исключены из первичной навигации и sitemap, но доступны по прямым ссылкам с честным статусом «Готовится» и robots noindex.
- Никакие тестовые продажи, фиктивные отзывы или несуществующие цифровые продукты не обозначены доступными.

## Какие маршруты подготовлены в ветке
1. /service-prices — состав и стартовая цена каждой услуги.
2. /service-delivery — порядок заявки, индивидуального предложения, дистанционного выполнения и передачи результата.
3. /service-terms — пользовательское соглашение/общие условия услуг с механизмом отдельного заказа.
4. /service-refunds — отказ и возврат именно **за услуги**; ст. 32 ЗоЗПП для потребителей, обязательные нормы для недостатков; не путать с семидневным отказом за будущий цифровой товар.
5. /requisites — ФИО физлица на НПД, ИНН, публично подтверждённый телефон, email, адрес, без несуществующего ОГРН.
6. /services и /contact — ссылки на порядок заказа и контакты.
7. Footer — навигация по документам и телефон/email.

## СТОП-факторы перед отправкой адреса mironovich.pro
- [ ] **Утвердить фактическую возможность исполнения услуг и указанные цены.** Это не фиктивные товары. Для индивидуальных проектов цены «от» требуют реального стартового объёма; менеджер ЮKassa может запросить уточнения.
- [ ] **Подтвердить текущий статус НПД в ФНС** и пригодность всех заявленных операций для этого режима. Годовой лимит НПД 2,4 млн ₽ и иные ограничения по № 422-ФЗ; при необходимости скорректировать форму деятельности и реквизиты.
- [ ] **Идентифицировать кошелёк ЮMoney** и открыть заявку ЮKassa для самозанятого (на момент оформления владелец сообщил, что кошелька нет).
- [ ] **Проверить юридическую корректность** /service-terms, /service-refunds и /requisites; эти страницы подготовлены как редакции для владельца/юриста, не юридическое заключение.
- [ ] **Локализация и политика ПД:** текущая /privacy и /consent описывают прежнюю схему, которая не полностью соответствует фактическим Railway → Telegram и Yandex Metrica. Новые черновики содержат блокирующие placeholders. Перед публикацией исправить фактические расхождения и выполнить законные обязанности по 152-ФЗ (локализация, уведомление РКН и при необходимости трансграничная передача). Выбор Яндекс Облака для будущей диагностики не решает вопрос существующей формы.
- [ ] Нужен **почтовый индекс** и подтверждение пригодности публичного адреса, если запрошен ЮKassa.
- [ ] Выполнить npm run lint, npm run typecheck, npm test, npm run build, browser E2E с проверкой всех новых страниц на мобильном и desktop; этот PR ещё не имеет этих подтверждений.
- [ ] Отдельно утвердить merge/deploy и проверить HTTPS-версию всех маршрутов на живом домене с мобильного и десктопа. Проверить все ссылки, цены и контактную форму.
- [ ] Только после этого перейти в форму проверки ЮKassa.
- [ ] Примирить PR №17 (документы будущего продукта за 1 990 ₽) с этим PR при последующем объединении; страницы /requisites, Footer, sitemap требуют аккуратного merge.

## Дополнительные замечания
- ЮKassa проверяет сайт на этапе заключения договора, но **прохождение не гарантировано**: решение за провайдером.
- Получение доступа к ЮKassa для оказываемых услуг не означает автоматического разрешения продавать будущий цифровой продукт с ИИ: понадобится актуальная информация и соответствующий сценарий оплаты/выдачи.
- При текущем статусе НПД не выдавать себе реквизиты ИП/юрлица и не публиковать ОГРН/ОГРНИП, которого нет.
- Отчёт о выполнении инфраструктурных проверок подготовить отдельно; без реального доступа к окружению это не проверить по коду.
