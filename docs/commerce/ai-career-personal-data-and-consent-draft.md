# Данные покупателей MIRONOVICH.PRO: проект для юриста и Codex
Дата: 17.11.2026. **Не действующая политика и не готовое к использованию согласие.**
Редактирование PR №17 не означает, что инфраструктура соответствует 152-ФЗ. Действующая форма лидов пока отправляет данные с Railway в Telegram.

## Проектируемая схема, ещё НЕ внедрена

1. Регион хранения для данных граждан РФ: Яндекс Облако, РФ, `ru-central1`.
2. Предполагаемые сервисы (подтвердить после выбора тарифа): Yandex Managed Service for PostgreSQL — аккаунты, заказы, ответы диагностики, результаты, контроль срока доступа; Yandex Object Storage — экспортируемые отчёты PDF, только приватные бакеты с короткоживущими подписанными ссылками.
3. Первичная запись, систематизация и хранение персональных данных в базах РФ; **не отправлять необработанные персональные данные через зарубежное API, Telegram или логи, пока не определены и не выполнены законные основания и процедуры**.
4. **Внешний ИИ-провайдер не выбран**. Подключение запрещено до инвентаризации стран получателей, договоров, перечня отправляемых данных и проверки трансграничной передачи. Вариант российского ИИ-провайдера рассмотреть как отдельную опцию, не считать его уже выбранным.
5. Секреты не хранить в GitHub. Минимум прав, сетевой доступ к БД без публичного открытого подключения, шифрование, аудит доступа и удаление, резервные копии с правилами жизни.
6. Оператора данных назвать в финальной политике после согласования; проверить состав поручения обработки Яндексу и применимых договорных условий https://yandex.cloud/ru/docs/troubleshooting/legal/how-to/fl-152

## Сроки
- Доступ после первой покупки — 90 дней; одно создание персонального анализа.
- Дополнительная покупка за 1 490 ₽ — отдельные 12 месяцев **с момента оплаты**, без суммирования оставшегося срока, без нового анализа.
- Результаты после истечения оплаченного доступа — ещё 30 дней, затем удаление из активного пользовательского хранилища. Срок хранения резервных копий, чека и бухгалтерских записей — **определить отдельно**. Срок обработки данных для поддержки и юридических обязанностей не обязательно совпадает со сроком отчёта.
- Удаление / отзыв согласия до истечения 90 дней: разработать UX, законные основания дальнейшей обработки и предупреждение о потере результата; нельзя обещать, что отзыв удалит законно сохраняемые данные.

## Что требуется для финальных юридических текстов
1. Подтверждённая конфигурация Яндекс Облака: ID папки/облака (без ключей), регион, перечень сервисов, размещение серверного приложения, резервные копии, получатели.
2. Документирование маршрутов данных: браузер → сервер → PostgreSQL / Object Storage → (если разрешено) ИИ → пользователь. Существующий Railway → Telegram отдельно.
3. Зафиксировать каждую цель обработки и законное основание: договор, налоговая обязанность, безопасность; согласия, только где требуются. Не объединять техническое исполнение договора и маркетинг в одну обязательную галочку.
4. Подготовить политику и отдельные тексты согласий для формы заявки, аналитики и, если необходимо, ИИ-обработки; зафиксировать версию согласия и доказательства акцепта без ненужного сбора данных.
5. Проверить подачу уведомления в РКН по ст. 22 ФЗ № 152-ФЗ и отдельное уведомление о трансграничной передаче, если актуально.
6. Правовое заключение специалиста по защите ПД + после проверки удалить блокирующие заполнители из действующей редакции.

## Примеры формулировок — только будущий вариант
**Политика:** «Для предоставления доступа к диагностике планируется использование облачной инфраструктуры Яндекс Облако в России. Информация о фактическом размещении, доступах и передаче другим операторам будет опубликована после проведения технической проверки». Это НЕ формулировка для документа уже запущенного магазина.

**Экран оплаты:** «Мне исполнилось 18 лет» и «Я ознакомился(лась) и согласен(сна) с условиями публичной оферты» — отдельные подтверждения без объединения с маркетинговым согласием. Предусмотреть воспроизводимый журнал акцептов с версией оферты.

**Диагностика:** короткое понятное объяснение, что информация о рабочей задаче будет использована для персонального анализа, а запрещённые персональные/конфиденциальные сведения третьих лиц вводить нельзя. Отдельное согласие, если его требует выбранная юридическая модель.

**Сбор платежей:** при передаче заказов через ЮKassa учитывать провайдера в перечне получателей данных, сформировать чек НПД через «Мой налог», не считать электронную квитанцию ЮKassa фискальным чеком.
