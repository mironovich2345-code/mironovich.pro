# Закрытый ИИ-пилот для продукта сотрудников

Дата: 18.11.2026. Основание: PR #28 (тестовый кабинет). Этот этап не включает публичный запуск.

## Что реализовано

- Отдельный серверный адаптер OpenAI Responses API: `lib/server/career/ai-provider.ts`, модель `gpt-6-luna`.
- **Только 18 строго перечисленных ответов и 1–5 заранее заданных учебных задач**. Ни email, ни ID пользователя, ни текстов работодателя, ни свободных вопросов в запросе модели нет.
- Три направления развития, рекомендации к выбранным учебным задачам и четыре индивидуальных акцента для заранее заданного плана из 30 шагов.
- Ответ модели валидируется после Structured Outputs: точные ключи, все выбранные задачи без повторов, ровно три направления и четыре фокуса; запрет URL, контактов, обещаний дохода и неприемлемого ответа.
- Базовая оценка рисков, правило обязательной человеческой проверки, количество и последовательность шагов **не редактируются моделью**.
- Если данные помечены как restricted или инструменты не разрешены — никакого внешнего вызова; только детерминированный учебный отчёт, с объяснением пользователю.
- Режим по умолчанию `CAREER_AI_MODE=rules`, внешний ИИ **только** при `CAREER_AI_MODE=openai` + `CAREER_AI_ENABLED=1` + секретном `OPENAI_API_KEY` и явном synthetic-only окружении на **127.0.0.1**, не на Railway/production.
- `store:false`, timeout 20 секунд, `max_output_tokens=1800`, без web-search/tools, без автоматических повторных вызовов и без сохранения промптов/ответов в логи.
- В тестовой БД отдельная таблица только для метаданных попыток, с ограничением **3 попытки на аккаунт за жизнь** и **25 вызовов за сутки UTC**. Неудачные внешние попытки тоже учитываются, чтобы ограничить расходы. Очистка этих метаданных через 90 дней.
- Ошибки провайдера, валидации или PDF не расходуют право на один успешный персональный анализ; retry контролируется лимитом.
- Учебный PDF и личный кабинет различают настоящий ИИ-пилот на вымышленных данных и детерминированный генератор.

## Безопасность и ограничения

- Сайт и продукт **не разрешены к продаже**, `salesEnabled=false`, `legalApproved=false`.
- Ни один пользовательский аккаунт с настоящими контактами, личными данными или данными работодателя не должен использоваться в текущем тестовом контуре.
- Интеграция написана и тестируется с подставным `fetch`, **живой ключ и настоящие запросы API не используются в CI**.
- `store:false` — не юридическое подтверждение локализации данных: вопрос законности обработки данных жителей РФ и размещения инфраструктуры остаётся открытым.
- Это ограниченный технический пилот, а не завершённая коммерческая система с real-AI доступом для пользователей.

## Сценарии приёмки

1. Запуск с флагами по умолчанию → детерминированный 30-шаговый отчёт, ноль запросов к OpenAI.
2. Попытка открыть ИИ на Railway/production без явной конфигурации → ошибка до сетевого запроса.
3. Вымышленные разрешённые ответы → один Responses запрос, строго ограниченный и проверенный JSON.
4. Запрещённые/конфиденциальные условия → без сетевого вызова.
5. Неверный JSON, поддельная идентичность задачи, URL/контакты, отказ модели, HTTP 429, превышение лимита → без выдачи результата и без расхода успешного анализа.
6. PDF, порядок 30 шагов и сохранение прогресса остаются совместимыми с текущим кабинетом.
7. Запустить `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`, а также интеграционный и браузерный QA только на синтетическом стенде.

## Следующее до запуска

Техническая приёмка **не заменяет** выбор юрисдикции и конфигурации хранения ПД, независимую юридическую проверку, реальные тесты API (с явным бюджетом), правила выдачи и удаления данных, оплату/чеки и проверку реальными устройствами.
