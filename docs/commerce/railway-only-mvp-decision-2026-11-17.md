# Актуальное решение владельца — Railway-only MVP (17.11.2026)

**Это актуальный источник для Codex, заменяет решения об Яндекс Облаке.**

## Цель и границы

Весь технический прототип продукта «Как стать ценнее для компании с помощью ИИ» (18+, 1 990 ₽, один анализ, 30-дневный план, PDF, 90 дней доступа) разрабатываем на **Railway**, без Яндекс Облака. Тестируем ЮKassa в тестовом магазине, реальную оплату пока не включаем. Публичный сайт `mironovich.pro` уже размещён на Railway. Не трогать прочие направления B2B и закрытый PR №18.

## Предполагаемая техническая схема

- Next.js 15 в проекте Railway `mironovich.pro`: публичная страница продукта; под защитой feature flags — кабинет и серверные API для будущих покупателей.
- PostgreSQL Railway (отдельный приватный сервис внутри проекта/окружения) — **пока только синтетические тестовые пользователи, заказы, статусы оплаты и ответы на учебные вопросы**. Нужны миграции, индексы, внешние ключи, запрет хранения секретов/OTP в открытом виде, идемпотентность платежей.
- PDF: для испытаний приватное хранилище или защищённое долговременное файловое хранилище; без открытых public URL. Не полагаться на локальную файловую систему контейнера без постоянного volume.
- Корпоративная почта через SMTP (поставщик и доменная настройка уточняются); OTP с хэшем, TTL 5 минут, лимитами попыток и повторных отправок. Реальные email граждан РФ пока не собирать; для разработки использовать тестовые адреса, разрешённые к применению.
- ЮKassa sandbox: модуль `lib/server/commerce/yookassa-sandbox.ts`, ShopID из конфигурации, перевыпущенный test secret только в переменных Railway (не в GitHub, чате или скриншотах), `return_url` на `https://mironovich.pro/payment/result` **после создания такого маршрута**. Создание заказа/вебхуки — только сервер; нельзя доверять redirect или webhook без проверки GET /v3/payments/{id}.
- **Нельзя:** пока нет юридического Go активировать `salesEnabled`, `legalApproved`, `published`, отправлять настоящие платежи, генерировать реальные entitlement, включать сбор ПД граждан РФ в Railway или предоставлять диагностику с реальными сведениями.

## Юридический стоп-фактор

Официальные регионы Railway — США (Калифорния, Вирджиния), Нидерланды (Амстердам), Сингапур; **региона размещения серверов/базы в России нет**: https://docs.railway.com/deployments/regions .

Статья 18 ч. 5 152-ФЗ (редакция с 01.07.2025) запрещает при сборе данных граждан РФ запись, систематизацию, накопление, хранение, уточнение и извлечение с использованием баз данных за пределами РФ, кроме предусмотренных законом исключений: https://www.consultant.ru/document/cons_doc_LAW_61801/cbf4e15b7c330f9372e876cdf2bc928bad7950ef/ .

Поэтому размещение PostgreSQL Railway **само по себе не соответствует обычному сценарию сбора ПД граждан РФ**. Формального согласия пользователя и уведомления РКН недостаточно, чтобы сделать зарубежную базу законной. Прежде чем принимать реальные анкеты, email, заказы и оплату, надо согласовать с юристом соответствующую закону схему локализации (например, хранить первичные ПД/платёжные сведения в российской инфраструктуре и оставить на Railway только неперсонализированный публичный слой) либо документально подтвердить применимое законное исключение; наличие исключения не предполагается.

Существующий маршрут публичной формы Railway → Telegram также требует отдельной правовой и технической проверки. Не писать в политике, что данные в РФ, пока это не подтверждено. При необходимости провести уведомление/актуализацию оператора РКН и проверку трансграничной передачи, но это НЕ заменяет первичную локализацию.

## Передать Codex: следующий этап

1. Создать **изолированный** тестовый контур/флаги в текущем Next.js на Railway, без затрагивания текущих посетителей.
2. Проект БД, миграции, сервисные интерфейсы для OTP, кабинета, 18 вопросов, AI-анализа, 30-дневного плана, PDF и учёта 90-дневного доступа. Сейчас только synthetic fixtures.
3. Подготовить sandbox checkout и webhook/status polling, idempotency, rate-limit, валидацию суммы 1 990 ₽, тесты повторных событий. `/payment/result` создать после готовности тестового API.
4. Все реальные данные и платежи запрещены; секреты только из окружения Railway; логирование без ПД и secret.
5. Локальные тесты Node/TypeScript/ESLint, browser E2E для мобильного и desktop. Показать план миграции на разрешённую инфраструктуру, если не будет документально подтверждённого исключения.
6. **Не делать merge, deploy или запуск реальных покупок без согласования владельца.** Платёжный модуль в PR №17 пока не интегрирован в HTTP API и не делает настоящих запросов.
