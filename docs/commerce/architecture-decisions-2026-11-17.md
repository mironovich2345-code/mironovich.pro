# Решения владельца: быстрый запуск продукта сотрудников — 17.11.2026

Статус: архитектурные решения и задания. **Не утверждение фактического запуска или юридического соответствия.** PR №17 остаётся draft; `main` не изменять, продажи отключены.

## Утверждено
1. **НПД:** владелец проверил в кабинете ФНС статус «Вы поставлены на учёт в качестве налогоплательщика налога на профессиональный доход». На дату оплаты проверить статус заново. Подготовить справку КНД 1122035 отдельно, не публиковать в GitHub. Правовую квалификацию лицензии / услуги / смешанного договора проверить.
2. **Предмет:** модель на проверку юристу — личное право доступа к собственной платформе 90 дней плюс один автоматизированный персональный анализ, план на 30 дней и PDF, 1 990 ₽; покупатели 18+. Возврат в течение 7 дней не считая дня покупки без удержаний, дополнительные обязательные сроки — по закону. Продление 1 490 ₽ на 12 месяцев с отдельной оплаты без нового анализа и автосписаний.
3. **Railway остаётся для публичного сайта, маркетинга и материалов.** НЕ переносить сайт целиком. Личный кабинет + регистрация + API заказов/диагностики + первоначальная обработка и сохранение ПД граждан РФ — **Яндекс Облако (регион РФ `ru-central1`)** по адресу `app.mironovich.pro`, если доступ к этому поддомену подтвердится.
4. На стороне Яндекс Облака планируется PostgreSQL для учётных записей/ответов/анализа/платежных статусов; приватное объектное хранилище для PDF; российский сервер для API и авторизации, защищённый доступ и резервные копии. Не считать это развёрнутым до фактического подтверждения.
5. **Нельзя** маршрутизировать emails покупателей, разовые коды, ответы диагностики, токены сессий, заказы, персональный результат через Railway или Telegram. Кнопка публичного сайта ведёт в отдельное приложение; формы кабинета общаются с API Яндекс Облака напрямую. Не включать PII в URL, аналитические события или рефереры. Существующую общую форму контактов Railway → Telegram требуется отдельно проверить/переработать: перенос продукта не легализует существующий маршрут.
6. **Почта:** владелец выбрал корпоративную почту домена `mironovich.pro` и SMTP. Предложение — Яндекс 360 для бизнеса, адрес отправителя `support@mironovich.pro` (конкретное имя адреса ещё не утверждено владельцем). Проверить подключение домена и MX/SPF/DKIM/DMARC без нарушения A/CNAME сайта. SMTP `smtp.yandex.ru`, порт 465 TLS или 587 STARTTLS в соответствии с поддержкой поставщика; полный email как логин, пароль приложения/поддерживаемая авторизация — только в защищённых переменных Яндекс Облака, никогда в исходниках.
7. **OTP по email:** одноразовый код с ограниченным сроком жизни (рекомендуется 5 минут), хэш на сервере, ограничение повторных запросов и попыток, привязка к email, истечение после успешного входа, HttpOnly Secure cookies; не логировать ни коды, ни пароль SMTP. Сценарии: вход, подтверждение адреса, восстановление доступа, письма об оплате/доступе/возвратах и служебные уведомления. Для PDF использовать приватную ссылку в личном кабинете вместо вложения с ПД в письмо.
8. **ИИ-провайдер пока не выбран.** Не отправлять реальную персональную диагностику в ИИ до определения юридического лица, страны, обработки, хранения, обучения модели и основания возможной трансграничной передачи.
9. **РКН:** необходимо проверить запись в реестре операторов; при отсутствии применимого исключения подать уведомление об обработке ПД. Провести инвентаризацию фактических текущих и планируемых маршрутов и определить необходимость отдельного уведомления о трансграничной передаче и других обязанностей по 152-ФЗ.
10. **ЮKassa только для продукта сотрудников.** Другая бизнес-услуга и закрытый PR №18 не входят в scope. Не создавать фальшивую готовность сервиса.

## Действия Codex в следующем этапе
- Составить карту данных и схему Railway public → ссылка → Yandex `app` (кабинет, API, БД, Object Storage). Проверить DNS/сессионные cookies/cross-origin, лимиты, сервисы/оценку затрат и локализацию.
- Спроектировать SMTP и минимально необходимый email OTP: 5 минут, 1 использование, throttling/rate-limit, защита от enumeration, антиспам, безопасный повторный запрос, доступность и восстановление. Включить тесты ошибочных и повторных запросов.
- Подготовить шаблоны транзакционных писем и пользовательский путь без оплаты в черновой версии. Не обещать выдачу без реализации.
- Обновить юридические черновики, описав выбранные **планируемые** сервисы, не выдавать их за уже активные. Обнаружить несовместимые утверждения о существующей Railway → Telegram форме.
- Составить черновик набора сведений для уведомления РКН, который проверит и подаст владелец.
- Сохранить `salesEnabled=false`, `legalApproved=false`, `published=false` и все release guards; не писать секреты в Git; без merge/deploy без отдельной авторизации.

## Что делает владелец
- Зарегистрировать/активировать Яндекс Облако, настроить биллинг и права доступа.
- Подключить Яндекс 360 для бизнеса к домену mironovich.pro, создать корпоративный email, настроить необходимые DNS-записи и пароль приложения; не пересылать секреты в чат.
- При необходимости подтвердить доступ к редактированию DNS и сообщить выбранный публичный адрес почты (без паролей).
- Подать/актуализировать уведомление в РКН на основе проверенной карты обработки.
- Получить справку НПД и пройти идентификацию ЮMoney; проверить договор с юристом по ПО и персональным данным.
