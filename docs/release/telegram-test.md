# Staging-проверка доставки заявок в Telegram

Цель: проверить реальную доставку заявки, ошибки, лимиты и резервную ссылку на
отдельной копии сайта, **не затрагивая production** и не засоряя боевой чат.

Выполняет владелец. Claude окружения Railway не создаёт и не меняет. Токены и
chat_id никуда не пересылать — ни в чат с Claude, ни в issue, ни в коммиты.

Названия пунктов меню Railway могут немного отличаться в текущей версии
интерфейса — ориентируйтесь на смысл шага.

## Шаг 1. Тестовый бот и чат (5 минут)

1. В Telegram открыть **@BotFather** → `/newbot`.
   - Имя: `MIRONOVICH staging`
   - Username: например `mironovich_staging_bot` (должен заканчиваться на `bot`)
   - BotFather выдаст **токен** — сохраните его у себя, это `TELEGRAM_BOT_TOKEN`
     для staging.
2. Открыть нового бота и нажать **Start** (без этого бот не может вам писать).
3. Узнать chat_id: в браузере открыть
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — в ответе
   `result[0].message.chat.id`. Это `TELEGRAM_CHAT_ID` для staging. Адрес с
   токеном никому не отправлять.

Боевой бот и боевой чат не используются.

## Шаг 2. Отдельное окружение Railway (10 минут)

1. Railway → проект сайта → переключатель окружений (вверху, обычно
   `production`) → **New Environment**.
2. Выбрать **пустое окружение** (Empty), назвать `staging`.
   **Не выбирать «Duplicate production»:** копия перенесёт боевой токен бота и
   ID счётчиков — тестовые заявки попадут в боевой чат, а визиты — в статистику.
3. В окружении `staging` добавить сервис из того же GitHub-репозитория
   (**New → GitHub Repo → mironovich.pro**).
4. Сервис → **Settings → Source → Branch**: `claude/busy-carson-4j9hr7`.
5. Сервис → **Settings → Networking → Generate Domain** — получить адрес вида
   `*.up.railway.app`. **Не подключать** `mironovich.pro`.
6. Сервис → **Variables** — задать (значения только тестовые):

   | Переменная | Значение |
   |---|---|
   | `NEXT_PUBLIC_SITE_URL` | адрес из п. 5, `https://…up.railway.app`, без слэша |
   | `TELEGRAM_BOT_TOKEN` | токен **тестового** бота (шаг 1) |
   | `TELEGRAM_CHAT_ID` | chat_id **тестового** чата (шаг 1) |
   | `SITE_NOINDEX` | `1` — staging не попадёт в поиск |
   | `LEGAL_PREVIEW` | `1` — по желанию: увидеть проекты политики и согласия на `/privacy`, `/consent` |

   **Не задавать** в staging: `NEXT_PUBLIC_YANDEX_METRICA_ID`,
   `NEXT_PUBLIC_GA_ID` (тест не попадёт в статистику),
   `NEXT_PUBLIC_LEAD_FORM_EXTENDED`. По желанию для отдельной проверки баннера:
   `NEXT_PUBLIC_ANALYTICS_CONSENT=required` (без ID счётчиков баннер не
   появится — для проверки баннера нужны тестовые ID, см. шаг 4).
7. Дождаться статуса деплоя **Active / Success**.

Production при этом не меняется: другое окружение, другой домен, другие
переменные.

## Шаг 3. Сценарий проверки

Все заявки — со своими данными, текст начинается с «ТЕСТ».

| # | Действие | Ожидаемый результат |
|---|---|---|
| 1 | `https://<staging>/robots.txt` | `Disallow: /` |
| 2 | `curl -sI https://<staging>/` | Есть `X-Robots-Tag: noindex, nofollow` |
| 3 | `/contact`: имя, `@ваш_username`, «ТЕСТ контакт», согласие → «Отправить задачу» | На сайте «Заявка отправлена». В тестовом чате: имя, контакт, задача, «Страница: /contact», дата по Москве, блок ИСТОЧНИК |
| 4 | В **приватном окне**: `/services/apps?utm_source=test&utm_medium=manual&utm_campaign=h&email=a@b.c` → отправить «ТЕСТ услуга» | В адресной строке `email` исчез. В чате: «Страница: /services/apps», Source test, Medium manual, Campaign h, Landing /services/apps |
| 5 | В новом приватном окне: `/?utm_source=ivan@mail.ru` → отправить заявку с главной | В чате `Source: unknown` (значение с email не сохранилось), «Страница: /» |
| 6 | Отправить ещё заявки подряд, чтобы получилось 6 за минуту с одного устройства | 6-я: на сайте ошибка и ссылка `t.me/mironovich_pro`; в чат пришло не больше 5 |
| 7 | Railway → staging → Variables → временно изменить `TELEGRAM_CHAT_ID` на неверный (например, `1`) → дождаться передеплоя → отправить заявку | На сайте «Не получилось доставить заявку…» и ссылка `t.me/mironovich_pro`; **нет** «Заявка отправлена»; в Railway → Logs строка `[lead] telegram rejected the message` без данных заявки |
| 8 | Вернуть верный `TELEGRAM_CHAT_ID`, передеплой, одна заявка | Снова доставляется |
| 9 | Пустая форма → «Отправить задачу» | Фокус на поле «Имя», сообщения об ошибках, в чат ничего не пришло |
| 10 | Нажать на ссылку Telegram в футере | Открывается `t.me/mironovich_pro` |

Что прислать Claude после теста: только таблицу «✓ / ✗» по пунктам и, если
что-то не так, текст ошибки с сайта или из логов **без токена и chat_id**.

## Шаг 4 (по желанию). Баннер согласия на staging

Для проверки баннера нужны **тестовые** ID счётчиков, которые не принадлежат
боевым счётчикам. Без них баннер не показывается (нечего загружать). Если
тестовых счётчиков нет — пропустить: баннер проверен локально с заглушками
(`docs/release/analytics.md`).

## Шаг 5. После теста

1. Удалить тестовые сообщения из чата.
2. Окружение `staging` можно **оставить** (удобно для следующих релизов) или
   удалить: Railway → staging → Settings → Delete Environment.
3. Тестового бота можно оставить или удалить в @BotFather (`/deletebot`).
