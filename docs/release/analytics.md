# Аналитика: аудит и настройка к релизу

Проверено по коду ветки `claude/busy-carson-4j9hr7`. Доступа к интерфейсам Яндекс
Метрики и GA4 нет: ничего из раздела «Ручная настройка» не сделано, цели и ключевые
события нужно создать вручную.

## Что было до аудита

| | Состояние |
|---|---|
| Где подключались | `components/Analytics.tsx`, в `app/layout.tsx` — один раз на весь сайт |
| Переменные | `NEXT_PUBLIC_YANDEX_METRICA_ID`, `NEXT_PUBLIC_GA_ID` (на действующем сайте заданы, значения не проверялись) |
| Двойная загрузка | Нет: каждый счётчик подключался одним `<Script>` с `id`, Метрика дополнительно проверяет, не загружен ли `tag.js` |
| Просмотры при переходах App Router | Метрика: только первый просмотр, переходы внутри сайта не отправлялись. GA4: первый просмотр из `config` и, если включено в настройках потока, переходы через Enhanced Measurement |
| События | `cta_click`, `form_start`, `lead_submit_success`, `lead_submit_error`, `telegram_fallback_click` |
| Успешная заявка | Отправлялась только после ответа API `ok && delivered` — корректно |
| Персональные данные | В события не передавались; параметры UTM уходили без очистки |
| Отладочный след | Объекты событий пушились в `window.dataLayer` — тот же массив, который читает gtag.js |
| Согласие | Механизма не было: счётчики загружались сразу, если задан ID |
| Consent Mode GA4 | Не использовался |

## Что изменено

1. **Единый модуль** `lib/analytics.ts` отправляет события в обе системы. Только
   фиксированный список событий и разрешённых параметров, значения очищаются до
   коротких токенов `[a-z0-9_./-]`, страница — нормализованный путь сайта.
2. **Просмотры без двойного учёта.**
   - Метрика: `init` с `defer: true` (автоматический хит выключен); первый просмотр
     отправляет сам скрипт инициализации, каждый следующий переход App Router —
     `PageViewTracker` (`ym(id, "hit", url, { title, referer })`).
   - GA4: `page_view` отправляет только сам GA (`config` + Enhanced Measurement).
     Сайт не отправляет в GA собственный `page_view`.
3. **Новые события:** `service_view` (страница услуги), `contact_click` (ссылки на
   Telegram и Instagram). `telegram_fallback_click` заменён на `contact_click` с
   `location: form_fallback`.
4. **GA4 Consent Mode** (по умолчанию): `analytics_storage: granted`,
   `ad_storage`, `ad_user_data`, `ad_personalization`: `denied`; в `config`
   выключены `allow_google_signals` и `allow_ad_personalization_signals`. Рекламные
   функции не включаются.
5. **Режим согласия** `NEXT_PUBLIC_ANALYTICS_CONSENT=required` — счётчики не
   загружаются до нажатия «Разрешить» в баннере; выбор хранится в `localStorage`
   (`mrnv_analytics_consent_v1`). **Выключен** до утверждения текста баннера и
   политики.
6. **Проверка ID:** Метрика — только цифры, GA4 — `G-XXXX`. Некорректный ID
   отключает счётчик и не открывает его домены в CSP.
7. Отладочный след событий перенесён в `window.mrnvEvents`, `dataLayer` gtag не
   засоряется.
8. **Очистка URL до загрузки счётчиков:** встроенный скрипт оставляет в адресной
   строке только `utm_*` (без e-mail/телефона), `yclid`, `gclid`, `_ym_debug`;
   хит Метрики получает путь `/redacted`, если путь похож на персональные данные,
   и referrer без параметров. UTM-значения с e-mail/телефоном в событиях
   заменяются на `redacted`.
9. **Отзыв согласия** (только в режиме `required`): «Настройки аналитики» в
   подвале открывают баннер; «Отклонить» после согласия удаляет cookie `_ym*`,
   `_ga*` и перезагружает страницу без счётчиков.

## События

| Событие | Когда | Параметры (только эти) | Метрика | GA4 |
|---|---|---|---|---|
| page_view | загрузка страницы и каждый переход | — | `hit` | автоматически (`config` + Enhanced Measurement) |
| service_view | открыта страница услуги | `service`: automation / apps / training, `page` | `reachGoal` | `event` |
| cta_click | клик по кнопке «Обсудить задачу…» | `location` (hero, sticky, header, services, diagnostics, service_page, services_index, about, blog, article, projects, not_found), `page` | `reachGoal` | `event` |
| form_start | первое касание поля формы за сессию | `page` | `reachGoal` | `event` |
| lead_submit_success | **только** после ответа API `ok: true, delivered: true` | `page`, `utm_source`, `utm_medium`, `utm_campaign` (очищены) | `reachGoal` | `event` |
| lead_submit_error | ошибка валидации, доставки или сети | `reason`: validation / delivery / network, `page` | `reachGoal` | `event` |
| contact_click | клик по Telegram или Instagram | `channel`: telegram / instagram, `location`: footer / contact_page / form_fallback, `page` | `reachGoal` | `event` |

Имя, контакт, текст задачи, компания и любые значения полей формы в аналитику не
передаются — проверено тестом (см. ниже).

## Ручная настройка

### Яндекс Метрика

1. **Цели → Добавить цель → JavaScript-событие**, идентификатор цели
   `lead_submit_success`, название «Заявка отправлена». Отметить как основную
   (ключевую) цель.
2. Для анализа воронки — такие же JavaScript-цели: `cta_click`, `form_start`,
   `lead_submit_error`, `service_view`, `contact_click`. Составная цель
   «Воронка заявки»: `cta_click` → `form_start` → `lead_submit_success`.
3. **Настройки счётчика:** «Отслеживание хеша» не нужно. Вебвизор не используется
   кодом сайта; если включён в интерфейсе — он записывает действия посетителей,
   это нужно отразить в политике или выключить.
4. **Проверка:** открыть сайт с `?_ym_debug=1`, в консоли браузера должен быть
   один `PageView` на загрузку и по одному на каждый переход, `Reach goal` при
   событиях.

### GA4

1. **Администратор → Поток данных → Улучшенная статистика → Просмотры страниц →
   Расширенные настройки:** включено «Изменения страниц на основе событий истории
   браузера». От этого зависит учёт переходов внутри сайта. Если выключено —
   переходы App Router не будут считаться (двойного учёта при этом не будет).
2. **Администратор → События**: после появления событий в отчётах отметить
   `lead_submit_success` как **ключевое событие**.
3. **Пользовательские параметры** (по желанию, для отчётов): `location`,
   `service`, `channel`, `reason` — уровень «событие».
4. **Google Signals** — не включать. Сайт явно передаёт
   `allow_google_signals: false`.
5. **Администратор → Поток данных → Редактирование данных (Data redaction):**
   включить для e-mail и параметров запроса — страховка на случай, если GA4 сам
   прочитает адрес или referrer с персональными данными (сайт чистит адресную
   строку, но GA берёт referrer из браузера).
5. **Проверка:** DebugView (расширение Google Tag Assistant): `page_view` один на
   загрузку и на переход, `lead_submit_success` один на успешную заявку.

## Атрибуция заявок

Хранится только в браузере посетителя (`localStorage`, `mrnv_attr_v1`), первый
визит не перезаписывается, уходит только вместе с отправленной заявкой — в
аналитику не передаётся (кроме очищенных `utm_source/medium/campaign` в
`lead_submit_success`).

| Поле | Как сохраняется |
|---|---|
| utm_source, utm_medium, utm_campaign, utm_content, utm_term | Из URL первого визита, печатные символы, до 100 знаков; на сервере проверяются повторно |
| Страница первого входа | Только путь, без параметров запроса; на сервере — только известный маршрут сайта, иначе `unknown` |
| Страница отправки | Путь текущей страницы; на сервере — только известный маршрут |
| Referrer | Только домен (`https://example.com`), без пути и параметров; внутренние переходы не считаются |

Атрибуция работает и без согласия на аналитику: это данные заявки, а не
аналитики. Это нужно указать в политике (см. `docs/legal/`).

## Результаты проверки

Сборка с тестовыми ID (`12345678`, `G-TEST1234`); `tag.js` и `gtag.js` подменены
заглушками, которые записывают вызовы. Реальные серверы Метрики и Google не
вызывались.

| Проверка | Результат |
|---|---|
| Загрузка главной | 1 `init` (defer), 1 `hit`; 1 `config` GA, 0 собственных `page_view` в GA |
| Переход App Router на услугу | +1 `hit`, 0 повторных загрузок скриптов, `service_view` 1 раз в обе системы |
| Второй переход | +1 `hit`, `service_view` 1 раз |
| CTA на 3 страницах услуг и `/services` | `cta_click` с `service_page` / `services_index` |
| Ссылки Telegram / Instagram | `contact_click` с каналом и местом |
| Успешная заявка | `form_start` → `lead_submit_success` один раз |
| Ошибка доставки (API 502) | `lead_submit_error` (`delivery`), **нет** `lead_submit_success` |
| Ошибка валидации | `lead_submit_error` (`validation`) |
| Персональные данные в вызовах ym / gtag | Не найдены (имя, телефон, текст задачи) |
| Режим согласия: без выбора | Баннер показан, 0 запросов к счётчикам |

**Ограничения:** не проверено, как настоящие `tag.js` и `gtag.js` обрабатывают эти
вызовы, и не проверены настройки счётчиков в интерфейсах. Это нужно подтвердить
после деплоя через `?_ym_debug=1` и GA DebugView.
