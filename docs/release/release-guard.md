# Проверка production-релиза (release guard)

Код — `lib/release-guard.mjs`, запуск — `next.config.mjs` (в начале `next
build`) и `npm run release:check`. Тесты — `tests/release-guard.test.mjs`.

**Техническая проверка не заменяет юридическое одобрение.** Она проверяет, что
в сборку не попадут старые или незаполненные тексты и что аналитика совпадает
с баннером. Решение о публикации текстов принимают владелец и юрист;
фиксируется в `docs/release/go-no-go.md`.

## Когда сборка считается production

**Fail-closed: любая сборка — production, пока явно не указано обратное.**
Сборка считается не production, только если одновременно:
- `NEXT_PUBLIC_SITE_URL` задан и это **не** `https://mironovich.pro` /
  `https://www.mironovich.pro` (staging — `https://…up.railway.app`, локально —
  `http://localhost:3000`);
- Railway, если передал в сборку имя окружения (`RAILWAY_ENVIRONMENT_NAME` или
  старое `RAILWAY_ENVIRONMENT`), не называет его `production`.

Почему так: если переменные окружения не попадут в сборку, сайт всё равно
соберётся с адресом по умолчанию `https://mironovich.pro`, то есть станет
production-сборкой. Такая сборка проверяется, а не пропускается.

| Ситуация | Цель |
|---|---|
| Railway production, переменные переданы в сборку | PRODUCTION (по обоим признакам) |
| Railway production, переменные **не** переданы в сборку | PRODUCTION (адрес по умолчанию) |
| Railway production, по ошибке задан адрес staging | PRODUCTION (по имени окружения, если оно передано) |
| Railway staging с адресом `*.up.railway.app` | не production |
| Railway staging **без** `NEXT_PUBLIC_SITE_URL` | PRODUCTION — задайте адрес staging (он и так обязателен) |
| `npm run build` без переменных | PRODUCTION — для локальной сборки есть `npm run build:local` |
| `npm run build:local` | не production (`http://localhost:3000`) |
| `next dev` | проверка не запускается |

В начале каждой сборки печатается строка, по которой видно, что увидела
проверка, — её нужно найти в логе сборки Railway:

```
[release-guard] цель сборки: PRODUCTION (NEXT_PUBLIC_SITE_URL=https://mironovich.pro; RAILWAY_ENVIRONMENT_NAME=production)
```

`не передана в сборку` вместо имени окружения означает, что Railway не передаёт
свои переменные на этапе сборки; защита при этом продолжает работать по адресу
сайта.

### Переменные на этапе сборки Railway

В репозитории нет `Dockerfile`, `railway.json`, `nixpacks.toml`: Railway
собирает стандартным сборщиком. По документации Railway он передаёт переменные
сервиса в сборку (при сборке из `Dockerfile` их пришлось бы объявлять через
`ARG`). Косвенное подтверждение — сайт уже собирается с `NEXT_PUBLIC_*`,
которые существуют только на этапе сборки. **Прямое подтверждение** — строка
`цель сборки` в логе staging-сборки (`owner-quickstart.md`, п. 1, строка 9).

## Что блокирует production-сборку

| Проверка | Почему |
|---|---|
| `config/legal.json`: `published` не `true` | Старые тексты не соответствуют фактической обработке (`go-no-go.md`, «Правило») |
| В `content/legal/*.md` остались `[УТОЧНИТЬ …]`, `[ОПИСАТЬ …]`, `⟦…⟧` | Незаполненные поля |
| `edition` в документе ≠ `config/legal.json` | Редакция в заявках и на сайте разойдётся |
| `LEGAL_PREVIEW=1` | Проекты с пометкой «Проект» не для production |
| `SITE_NOINDEX=1` | Production закрыт от поиска |
| `RATE_LIMIT_CLIENT_IP` не пусто и не `x-real-ip` / `x-forwarded-for` | Опечатка молча выключит лимит по IP |
| ID Метрики в неверном формате | Счётчик молча не загрузится |
| Метрика включена, а политика её не называет | Политика не описывает реальный сервис |
| Политика или согласие упоминают Google Analytics / GA4 / `_ga*` | GA4 отключён — тексты не должны его описывать |

Предупреждения (не блокируют): политика называет Метрику, а её ID не задан;
`RATE_LIMIT_CLIENT_IP` не задан (безопасный режим — только общий лимит);
остались `NEXT_PUBLIC_GA_ID` или `NEXT_PUBLIC_ANALYTICS_CONSENT` — не читаются,
их можно удалить. **Отсутствие GA4 сборку не блокирует.**

Согласие на Метрику — не настройка: код (`lib/consent.ts`) всегда показывает
баннер при ID Метрики и загружает её только после «Разрешить», поэтому
отдельной проверки режима согласия больше нет.

Плюс проверки, которые и раньше работали при рендере страниц (`lib/legal.ts`):
те же поля и редакция, если `published: true`.

## Обхода нет

- Переменной-исключения нет намеренно. Прежний внутренний флаг, через который
  проверку можно было случайно пропустить, если он оказался в окружении,
  удалён; тест проверяет, что посторонние переменные (`SKIP_…`, `CI`,
  `NODE_ENV`) не меняют результат.
- Проверка встроена в `next.config.mjs`, поэтому срабатывает при любой команде
  сборки, которая вызывает `next build` (`npm run build`, `npx next build`).
- Если нужно срочно пересобрать production до юридического Go — это решение
  владельца вне кода: откат в Railway (Redeploy предыдущей сборки,
  `release-plan.md`, «Откат»), а не отключение проверки. Неудачная сборка в
  Railway не заменяет работающий деплой.

## Как пользоваться

```bash
npm run release:check -- --production
```

Код 1 и список причин — релиз невозможен; код 0 и «технические условия
выполнены… Это не юридическое одобрение» — можно переходить к остальным
пунктам Go / No-Go.

Без `--production` проверяется текущее окружение (как при сборке).

## Проверено

| Сборка | Результат |
|---|---|
| `npm run build` без переменных | **Остановлена** — fail-closed (адрес по умолчанию) |
| Прежний флаг `__MRNV_RELEASE_GUARD_DONE=1` + адрес production | **Остановлена** — флага больше нет |
| `RAILWAY_ENVIRONMENT_NAME=production` + адрес staging | **Остановлена** |
| `NEXT_PUBLIC_SITE_URL=https://mironovich.pro`, текущие тексты | **Остановлена**: published=false, 7 + 2 поля |
| Staging: окружение `staging`, адрес `*.up.railway.app`, `SITE_NOINDEX=1` | Собрана, список — предупреждением |
| `npm run build:local` | Собрана |
| `next dev` с production-переменными | Работает, проверка не запускается |
| Копия: поля заполнены, `published: true`, ID Метрики (GA и переменная согласия не нужны) | Собрана, «Это не юридическое одобрение» |
| Модульные тесты | 18 сценариев |
