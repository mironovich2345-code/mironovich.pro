# Проверка production-релиза (release guard)

Код — `lib/release-guard.mjs`, запуск — `next.config.mjs` (в начале `next
build`) и `npm run release:check`. Тесты — `tests/release-guard.test.mjs`.

**Техническая проверка не заменяет юридическое одобрение.** Она проверяет, что
в сборку не попадут старые или незаполненные тексты и что аналитика совпадает
с баннером. Решение о публикации текстов принимают владелец и юрист;
фиксируется в `docs/release/go-no-go.md`.

## Когда сборка считается production

Достаточно любого из признаков:
- `RAILWAY_ENVIRONMENT_NAME=production` (Railway передаёт его в сборку
  стандартным сборщиком);
- `NEXT_PUBLIC_SITE_URL` = `https://mironovich.pro` или
  `https://www.mironovich.pro` (без учёта регистра и `/` в конце).

Второй признак страхует первый: если Railway не передаст переменную, сборка с
публичным адресом всё равно проверяется.

Не production — и **никогда не блокируются**: `next dev`, локальная `npm run
build` без публичного адреса, staging (`*.up.railway.app`, окружение не
`production`). Им выводится тот же список как предупреждение.

## Что блокирует production-сборку

| Проверка | Почему |
|---|---|
| `config/legal.json`: `published` не `true` | Старые тексты не соответствуют фактической обработке (`go-no-go.md`, «Правило») |
| В `content/legal/*.md` остались `[УТОЧНИТЬ …]`, `[ОПИСАТЬ …]`, `⟦…⟧` | Незаполненные поля |
| `edition` в документе ≠ `config/legal.json` | Редакция в заявках и на сайте разойдётся |
| `LEGAL_PREVIEW=1` | Проекты с пометкой «Проект» не для production |
| `SITE_NOINDEX=1` | Production закрыт от поиска |
| `NEXT_PUBLIC_ANALYTICS_CONSENT` не пусто и не `required` | Опечатка выключит баннер |
| ID Метрики или GA4 в неверном формате | Счётчик молча не загрузится |
| Счётчик задан, а `NEXT_PUBLIC_ANALYTICS_CONSENT≠required` | Аналитика загрузится без согласия, вопреки политике и баннеру |
| Метрика / GA4 включены, а политика их не называет | Политика не описывает реальный сервис |

Предупреждения (не блокируют): режим согласия без счётчиков (баннер не
появится); политика называет сервис, которого нет в настройках.

Плюс проверки, которые и раньше работали при рендере страниц (`lib/legal.ts`):
те же поля и редакция, если `published: true`.

## Обхода нет

Переменной-исключения нет намеренно. Если нужно срочно пересобрать production
до юридического Go — это решение владельца вне кода: откат в Railway
(Redeploy предыдущей сборки, `release-plan.md`, «Откат»), а не отключение
проверки. Неудачная сборка в Railway не заменяет работающий деплой.

## Как пользоваться

```bash
npm run release:check -- --production
```

Код 1 и список причин — релиз невозможен; код 0 и «технические условия
выполнены… Это не юридическое одобрение» — можно переходить к остальным
пунктам Go / No-Go.

Без `--production` проверяется текущее окружение (как при сборке).

## Проверено

| Сборка | Результат |
|---|---|
| `NEXT_PUBLIC_SITE_URL=https://mironovich.pro`, текущие тексты | Остановлена: published=false, 7 + 2 поля |
| `RAILWAY_ENVIRONMENT_NAME=production`, адрес staging | Остановлена |
| Staging: адрес `*.up.railway.app`, `SITE_NOINDEX=1`, `LEGAL_PREVIEW=1`, окружение `staging` | Собрана, список — предупреждением |
| Локальная без переменных | Собрана, список — предупреждением |
| `next dev` с production-переменными | Работает, проверка не запускается |
| Копия репозитория: поля заполнены, `published: true`, счётчики + `required` | Собрана, «Это не юридическое одобрение» |
| То же без `required` | Остановлена: аналитика без согласия |
| Модульные тесты | 14 сценариев, все проходят |
