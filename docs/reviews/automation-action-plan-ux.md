# Этап 3D: компактный экспресс-план и CTA

База: `bc38a1e4c149f7907d843f7e88435c99a687b4aa`.
Ветка: `feature/automation-action-plan`. PR: https://github.com/mironovich2345-code/mironovich.pro/pull/4.

## Изменения

Видимая часть результата содержит название подхода, объяснение и предупреждение о предварительном характере плана. Убран повтор вводной фразы перед названием решения.

Все подробности сохранены в пяти нативных `details/summary`:

1. Какую проблему решаем — процесс, цель, программы, подход.
2. План внедрения — шесть персонализированных шагов.
3. Что необходимо проверить — пять проверок и пояснение потребности в ИИ.
4. Экономический контекст — перенесённые показатели или ссылка на калькулятор ручного труда.
5. Подробнее о расчёте — сложность, часы по этапам, версия модели и ограничения.

По умолчанию все разделы закрыты. Их можно независимо открывать одновременно. Индикатор «+ / −» исключён из доступного имени секции. Нативное управление поддерживает Enter и пробел; области нажатия имеют высоту не менее 56 px. Дополнительных библиотек, состояния accordion и сложных анимаций нет.

Основной CTA — «Запросить подробный разбор», на всю ширину карточки. Над ним: «Проверю вашу задачу, уточню детали и предложу следующий шаг. Первичное обсуждение — бесплатно».

Обновлены заголовок, пояснение и начальное описание внутри существующей формы. Бесплатным названо только первичное обсуждение; формат и условия подробного разбора согласуются отдельно. Автоматический PDF, сроки ответа и стоимость услуг не обещаются. Вторичное действие «Изменить ответы» сохранено.

## Изменённые файлы

- `components/tools/AutomationResult.tsx` — пять свёрнутых разделов, видимое предупреждение и компактная иерархия результата.
- `components/tools/ToolLead.tsx` — новый CTA и тексты формы только для экспресс-плана. Вариант формы калькулятора ручного труда сохранён.
- Этот отчёт и два скриншота результата.

Расчёты, вопросы, рекомендации, генерация плана, серверный контекст, API, защита заявок, UTM, хранение, SEO и юридические документы не изменены. `approvedByOwner` и `publicPricingEnabled` остаются `false`.

## Проверки

- `npm test`: 148 из 148 тестов пройдены.
- `npm run lint`: успешно, без предупреждений.
- `npm run typecheck`: успешно.
- `npm run build`: успешно, 45 страниц.
- Chromium / Playwright: обычная интеграция и ИИ с серьёзными последствиями ошибки на каждой ширине 320, 375, 768, 1024, 1440 px — десять полных сценариев.
- В каждом сценарии проверены валидация, «Назад», персональный результат, все пять секций, одновременное раскрытие, закрытие, индикаторы, Enter/пробел и сохранение фокуса. Ширина карточки при раскрытии не меняется.
- Проверены изменение сохранённых ответов, повторное получение результата со свёрнутыми секциями, длинное название программы без пробелов на 320 px, открытие формы с клавиатуры и фокус на имени.
- На всех пяти ширинах проверены калькулятор ручного труда, возврат между шагами, вторичная форма, пример 66 ч / 39 600 ₽ в месяц и перенос 33 потенциально высвобождаемых часов в экономический раздел.
- До согласия и отправки формы запросов `/api/lead` нет. Описание отсутствует в sessionStorage, URL и аналитических событиях.
- На 375 px для ИИ и на 1440 px для интеграции форма отправлена в реальный локальный `/api/lead` с тестовой заглушкой Telegram. Подтверждены цель, последствия ошибки, параметры диагностики, серверный план, экранирование HTML и сохранение first-touch UTM после перехода с другой страницы.
- Ошибок JavaScript и горизонтального переполнения нет.
