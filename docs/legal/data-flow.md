# Движение персональных данных: браузер → Railway → Telegram

Технический анализ по коду ветки `claude/busy-carson-4j9hr7`. Термины «сбор»,
«запись», «хранение», «передача» использованы в бытовом техническом смысле;
квалификацию по 152-ФЗ даёт юрист. Регион Railway и юрлица сервисов по коду
не определяются — их нужно проверить в интерфейсе и условиях сервисов.

## Схема

```
[1] Браузер посетителя (устройство посетителя)
    │ форма: имя, контакт, текст задачи, согласие (галочка)
    │ + атрибуция из localStorage: UTM, домен referrer, страница входа
    │
    │ HTTPS POST /api/lead (JSON, ≤ 10 000 символов)
    ▼
[2] Railway — приложение Next.js (app/api/lead/route.ts)
    │ проверка Origin, размера, лимит 5 запросов/мин на IP, валидация,
    │ очистка атрибуции, сборка текста сообщения
    │ базы данных нет, на диск ничего не пишется
    │
    │ HTTPS POST api.telegram.org/bot…/sendMessage
    ▼
[3] Telegram Bot API → закрытый чат оператора
    │ сообщение хранится в облаке Telegram
    ▼
[4] Устройства оператора (приложения Telegram) — копии сообщения
```

## По этапам

| Этап | Где физически | Какие данные | Что происходит | Сколько хранится |
|---|---|---|---|---|
| **1. Ввод** | Устройство посетителя | Имя, контакт, текст | Значения живут в памяти страницы (React state). Черновик **не сохраняется** в localStorage/cookies | До закрытия вкладки |
| 1а. Атрибуция | Устройство посетителя, `localStorage` `mrnv_attr_v1` | UTM-метки (до 100 символов, значения с e-mail/телефоном отбрасываются), домен referrer, путь страницы входа, время первого визита | Записывается при первом визите, **уходит на сервер только вместе с заявкой** | Пока посетитель не очистит хранилище |
| 1б. Факт начала формы | `sessionStorage` `mrnv_form_start_v1` | Только флаг | Чтобы `form_start` отправлялся один раз | До закрытия вкладки |
| **2. Первичный приём** | Сервер Railway (регион сервиса — см. Railway → сервис → Settings → Region) | Всё из п. 1 и 1а + IP-адрес и заголовки запроса | **Первое место, где данные заявки оказываются вне устройства посетителя.** Проверка, очистка, формирование текста — в оперативной памяти процесса | Тело заявки — только на время обработки запроса (доли секунды), на диск и в базу не пишется |
| 2а. Лимит запросов | Память процесса Railway | IP-адрес + до 6 отметок времени | Только в памяти, не пишется на диск, в логи и в Telegram (`docs/release/rate-limit.md`) | **Не дольше 1 минуты** после последнего запроса с адреса; не больше 5000 адресов |
| 2б. Логи приложения | Логи Railway | Только при ошибке: «TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID are not set», «telegram rejected the message» + код HTTP, «telegram request failed» + текст сетевой ошибки | **Данные заявки в логи не пишутся** (проверено по коду: в `console.error` передаются только код статуса или объект ошибки fetch) | По сроку хранения логов Railway |
| 2в. Логи платформы | Инфраструктура Railway (edge / HTTP logs) | Обычно IP, путь, метод, статус, user-agent — **тело запроса не логируется** | Делает платформа, не код сайта; это относится ко **всем** страницам сайта, а не только к форме | По правилам Railway — проверить |
| **3. Передача** | Railway → серверы Telegram Bot API | Текст сообщения: имя, контакт, задача, страница, дата (МСК), «Согласие на обработку ПД: получено, редакция …», UTM, домен referrer, страница входа. **IP не передаётся** | HTTPS-запрос с токеном бота. Ответ Telegram «ok» — единственное условие, при котором посетитель видит «Заявка отправлена» | — |
| **4. Хранение** | Облако Telegram (закрытый чат оператора) + устройства оператора | Полный текст сообщения | **Единственное постоянное хранилище заявок.** Здесь же — единственная запись о факте и версии согласия | Бессрочно, пока оператор не удалит сообщение |
| 5. Резервный канал | Посетитель → Telegram напрямую | Что посетитель сам напишет | При ошибке доставки форма показывает ссылку `t.me/mironovich_pro`; переписка идёт вне сайта | В Telegram |

**Итог для юриста:**
- *Первоначальный сбор* (получение данных от посетителя в информационную систему
  оператора) — на сервере Railway.
- *Запись в постоянное хранилище* и *хранение* — в Telegram.
- *Передача* — Railway → Telegram (и между устройствами оператора внутри
  Telegram).
- Ни один этап технически не находится в РФ, кроме устройства посетителя и
  устройств оператора; это зависит от региона Railway и инфраструктуры Telegram,
  что нужно подтвердить по их условиям.

## Аналитика (отдельный поток, не связан с заявкой)

Только после «Разрешить» в баннере (обязательно всегда, `lib/consent.ts`):
браузер напрямую → Яндекс Метрика (ООО «Яндекс», РФ). Google Analytics 4
отключён 01.11.2026 — запросов к Google нет.
Через Railway не проходит. Данные формы в события не передаются (проверено
тестом); передаются очищенные путь страницы, событие и UTM (`docs/release/analytics.md`).
**На действующем сайте (`main`, до релиза) Метрика и GA4 загружаются сразу, без баннера.**

## Технические замечания

1. ~~IP в памяти лимитера не удаляются по таймеру~~ — **исправлено**: адрес
   удаляется не позже чем через минуту после последнего запроса
   (`docs/release/rate-limit.md`).
2. **Факт согласия хранится только в Telegram.** Если сообщение удалено — подтверждения
   согласия не остаётся. При варианте с записью в РФ это решается полем в базе.
3. Railway HTTP-логи и регион сервиса проверяются владельцем в интерфейсе Railway.
