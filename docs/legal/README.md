# Юридические тексты — ПРОЕКТ, НЕ ПУБЛИКОВАТЬ

Статус: черновики для проверки юристом. На сайте опубликованы прежние тексты
(`app/privacy/page.tsx`, `app/consent/page.tsx`); в них заменена только ссылка на
Telegram (на подтверждённую `t.me/mironovich_pro`), формулировки не менялись.

Это технический аудит фактической обработки данных по коду ветки
`claude/busy-carson-4j9hr7`, а не юридическая консультация. Реквизиты оператора
не заполнены намеренно.

## 1. Что собирает форма заявки

| Поле | Обязательно | Ограничения | Комментарий |
|---|---|---|---|
| Имя | да | 2–100 символов | |
| Телефон или имя пользователя Telegram | да | до 40 символов | Опубликованная политика упоминает только телефон — **неточно** |
| Описание задачи | да | 10–2000 символов | Свободный текст: посетитель может указать в нём что угодно |
| Согласие на обработку ПД | да | чекбокс | Без него сервер отклоняет заявку (422) |
| Компания | нет | до 120 | **Выключено** (`NEXT_PUBLIC_LEAD_FORM_EXTENDED`); сервер игнорирует поле |
| Направление | — | список | **Выключено** там же |
| Скрытое поле-ловушка `website` | — | — | Для защиты от ботов, человеку не видно |

## 2. Технические данные, которые уходят вместе с заявкой

| Данные | Откуда | Ограничения |
|---|---|---|
| utm_source, utm_medium, utm_campaign, utm_content, utm_term | URL первого визита | Печатные символы, до 100 знаков |
| Referrer | `document.referrer` первого визита | **Только домен** (`https://example.com`); внутренние переходы не учитываются |
| Страница первого входа | Первый визит | Только путь, без параметров; на сервере — только маршрут сайта, иначе `unknown` |
| Страница отправки | Текущая страница | Только маршрут сайта, иначе `unknown` |
| Дата и время | Сервер | Часовой пояс `LEAD_TIMEZONE` (по умолчанию Москва) |

Атрибуция хранится в браузере посетителя (`localStorage`, ключ `mrnv_attr_v1`)
с первого визита и отправляется **только** вместе с заявкой.

## 3. Куда и как передаются данные

1. Браузер → `POST /api/lead` на сервере сайта (HTTPS).
2. Сервер → Telegram Bot API (`api.telegram.org`, HTTPS) → закрытый чат
   владельца. Telegram — иностранный сервис.
3. Сайт **не ведёт** собственной базы заявок и не пишет содержимое заявок в логи
   (в логах — только факт ошибки доставки без данных заявки).
4. Хостинг — Railway (по DEPLOYMENT.md): запрос проходит через инфраструктуру
   иностранного провайдера.
5. IP-адрес посетителя (заголовки `x-real-ip` / `x-forwarded-for`) используется
   для ограничения частоты отправки и хранится только в оперативной памяти
   сервера до перезапуска приложения; в Telegram не передаётся.

## 4. Cookies, хранилище браузера и аналитика

На действующем сайте, по словам владельца, подключены **Яндекс Метрика и GA4**.

| Что | Кто ставит | Назначение |
|---|---|---|
| `_ym_uid`, `_ym_d`, `_ym_isad` и др. `_ym_*` | Яндекс Метрика | Различение посетителей, статистика |
| `_ga`, `_ga_<ID>` | Google Analytics 4 | Различение посетителей, статистика |
| `mrnv_attr_v1` (localStorage) | Сайт | Атрибуция заявки (раздел 2) |
| `mrnv_form_start_v1` (sessionStorage) | Сайт | Чтобы событие «начало заполнения» ушло один раз |
| `mrnv_analytics_consent_v1` (localStorage) | Сайт | Выбор посетителя — только при включённом режиме согласия |

Точный список cookies счётчиков нужно сверить на живом сайте (DevTools →
Application → Cookies): он зависит от настроек счётчиков в их интерфейсах
(например, включён ли Вебвизор).

Настройки в коде: Метрика — `clickmap`, `trackLinks`, `accurateTrackBounce`,
**без Вебвизора**. GA4 — рекламное хранилище и персонализация запрещены
(`ad_storage`, `ad_user_data`, `ad_personalization: denied`), Google Signals
выключены. В аналитику не передаются имя, контакт, текст задачи и другие поля
формы.

## 5. Где нужно согласие посетителя

| Обработка | Сейчас | Нужно решение |
|---|---|---|
| Данные формы | Чекбокс согласия, без него заявка не уходит | Обновить тексты согласия и политики (составы данных выше) |
| Передача через Telegram (иностранный сервис) | Не описана | Юрист: трансграничная передача, уведомление РКН, формулировка в согласии |
| Аналитические cookies (Метрика, GA4) | Загружаются сразу, без баннера | Юрист: нужен ли баннер согласия. Механизм готов: `NEXT_PUBLIC_ANALYTICS_CONSENT=required` + баннер (текст — черновик) |
| GA4 (передача данных Google) | Описания нет | Юрист: трансграничная передача; при необходимости — только после согласия |
| Атрибуция в localStorage | Описания нет | Описать в политике |

## 6. Что блокирует публикацию новых текстов

1. Реквизиты оператора: ФИО, статус (ИП / самозанятый / физлицо), ИНН/ОГРНИП,
   email для обращений.
2. Ответы юриста по пунктам раздела 5.
3. Решение по баннеру согласия на аналитику (включать ли режим `required` и
   утверждённый текст баннера).
4. Включение полей «Компания» и «Направление» — только вместе с утверждёнными
   текстами.
