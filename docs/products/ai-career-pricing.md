# AI Career 3.0: управление ценой по периодам

Статус: подготовка. Продажи выключены (`salesEnabled=false`, `legalApproved=false`), оплата не подключена. Тексты оферты и связанных документов обновлены, но остаются проектом до юридического утверждения.

## Правила

- **Допустимые цены:** 1 993 ₽, 3 990 ₽ и 5 900 ₽ (`config/ai-career-pricing.ts`). Другие цены отклоняет и код, и `CHECK` в базе.
- **Действующая цена** — одно из трёх значений:
  - **акция:** цена с датой начала и датой окончания;
  - **базовая цена:** последняя начавшаяся, действует без срока;
  - **стартовая цена 1 993 ₽**, пока ничего не задано.
- После окончания акции снова действует базовая цена.
- Акции не пересекаются, поэтому в каждый момент цена одна.
- Никаких лимитов мест, счётчиков, зачёркнутых цен и вымышленных скидок.

## Как владелец меняет цену

Цена хранится в базе магазина (`COMMERCE_DATABASE_URL`). Правка кода и новый деплой не нужны: страница читает цену на сервере и обновляется не позже чем через минуту (`revalidate = 60`).

```bash
npm run commerce:price -- current                                    # что сейчас показывает сайт
npm run commerce:price -- set 3990                                   # базовая цена 3 990 ₽ с этого момента
npm run commerce:price -- set 5900 "2026-12-15 00:00" "тест 5 900"   # базовая цена с даты (время МСК)
npm run commerce:price -- promo 1993 "2026-12-01 00:00" "2026-12-08 00:00" "неделя 1 993"
npm run commerce:price -- list                                       # вся история, включая отменённые периоды
npm run commerce:price -- stop 7                                     # отменить будущий период / завершить акцию сейчас
npm run commerce:price -- report                                     # результаты по периодам
```

**Защита от ошибок:**
- цена, не входящая в список трёх, отклоняется;
- дата в прошлом отклоняется, чтобы история не переписывалась;
- пересекающиеся акции и окончание раньше начала отклоняются.

**История не удаляется:**
- отменённый период остаётся в списке с отметкой;
- досрочно завершённая акция сохраняет фактическое окончание;
- изменения записываются под блокировкой транзакции.

**На странице:**
- для акции с датой окончания: «Цена действует до 7 декабря 2026 г., 23:59 МСК включительно», а если задана базовая цена — «После окончания периода — 3 990 ₽»;
- если база недоступна, сайт не угадывает цену. Он пишет, что действующая цена (1 993, 3 990 или 5 900 ₽) будет показана при оформлении заказа до оплаты.

## Цена заказа

При оформлении `quoteOrder(orderId)` записывает в `commerce_order_prices` цену и период, действующие в этот момент. Повторный вызов возвращает ту же цену.

- Сумма платежа ЮKassa берётся из этой записи и показывается до подтверждения оплаты.
- Уведомление об оплате принимается, только если сумма совпадает с суммой заказа (проверка через `GET /payments/{id}`).
- Повторные уведомления ничего не меняют. Второй платёж по тому же заказу отклоняется.
- Последующее изменение цены на сайте не меняет сумму созданного заказа. Изменение цены у заказа в коде не предусмотрено вовсе.
- Отмена и возврат записываются в статусе заказа.

## Данные для сравнения ценовых периодов

Команда `report` (`periodReport`) выводит по каждому периоду:
- цену и вид периода;
- фактические даты начала и окончания (базовая цена действует до начала следующей);
- число созданных заказов, оплат и возвратов;
- долю оплаченных среди созданных;
- выручку: оплаченные минус возвращённые.

Эти данные дают конверсию «оформление → оплата» и выручку по каждой цене. Для конверсии «просмотр страницы → заказ» берутся посещения страницы продукта за те же даты из веб-аналитики. Она учитывает только посетителей, давших согласие, поэтому это оценка.

Корректно сравнивать периоды сопоставимой длины и без пересечения с другими изменениями: сезонность, рекламные кампании, новые материалы.
