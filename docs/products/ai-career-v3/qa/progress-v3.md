# Кабинет AI Career 3.0 — сохранение прогресса по 30 шагам

Статус: **работает в синтетическом тестовом контуре на тестовой библиотеке-заглушке**. Это не готовый продукт:
- утверждённых уроков нет, поэтому на настоящем контенте маршрут по-прежнему «не готов»;
- 30 шагов проходятся только на синтетической библиотеке, которая включается локально флагом;
- «Мои результаты» (#47) не реализованы.

Продажи, реальные платежи и письма выключены. `salesEnabled`, `legalApproved` и статусы уроков не менялись, review-уроки не публиковались, production не затрагивался.

## Что сделано

| Требование | Реализация |
| --- | --- |
| Серверное хранение каждого из 30 шагов | Миграция `007_v3_progress.sql`: `career_v3_plan_versions`, `career_v3_step_progress` (30 строк на версию плана), `career_v3_quiz_results` |
| Состояния | `not_started` «Не начат», `in_progress` «Изучается», `self_checked` «Проверка пройдена», `done` «Завершён»; состояние вычисляет сервер (`lib/career-v3/progress.ts`), клиент его не передаёт |
| Завершение только по условиям | «Проверка пройдена» — все критерии упражнения отмечены и мини-тест урока пройден полностью (ответы проверяет сервер по версии урока); «Завершён» — плюс подтверждены все критерии выполнения шага. Ограничение в БД: `done` ⇔ есть `completed_at` |
| Результаты самопроверки и позиция | Отметки критериев (только `true`/`false`), выбранные варианты мини-теста (только ID вариантов), позиция `cursor_position` |
| Возобновление | После повторного входа кабинет сам открывает «Мой маршрут» с кнопкой «Продолжить: шаг N» (сохранённая позиция или первый незавершённый шаг) |
| Количество и процент | «Завершено N из 30 шагов · P%», полоса прогресса (`role="progressbar"`) |
| Повторное начисление | Повторное завершение возвращает `alreadyDone` и ничего не меняет; параллельные запросы проходят через блокировку строки — засчитывается ровно одно |
| Подмена аккаунта и шага | Аккаунт — только из сессии; версия плана — только активная версия этого аккаунта; шаг адресуется позицией и стабильным ID, несовпадение → 409; внешний ключ `(plan_version_id, account_id)` не даёт записать строку в чужой план |
| Привязка к версиям | Версия плана хранит версии диагностики, матрицы, программы, библиотеки и каждого урока; строка прогресса хранит версию урока; мини-тест засчитывается только для той же версии урока |
| Устаревший план | Если изменилась версия урока, урок снят, обновилась анкета или диагностика пройдена заново, план становится «устаревшим»: виден только для чтения, действия возвращают 409. Новый маршрут собирается только по кнопке «Собрать новый маршрут»; прежний остаётся в «Истории прежних маршрутов» с числом завершённых шагов и не переносится |
| Синтетический режим | Существующая локальная тестовая библиотека (`CAREER_V3_FIXTURE_LIBRARY=1`, только `127.0.0.1` + симулятор оплаты); уроки помечены как заглушки |
| Без свободного текста | API принимает только списки булевых отметок, ID вариантов и позицию с ID шага; лишние поля → 400 |

Повторная сборка маршрута без изменений контента не создаёт новую версию: отпечаток плана строится по версиям и стабильным ID шагов без даты сборки. Раньше экран маршрута пересобирал план при каждом открытии; теперь он читает сохранённую версию.

## API (только синтетический контур)

| Запрос | Тело | Что делает |
| --- | --- | --- |
| `GET progress` | — | Активная версия плана, состояния 30 шагов, мини-тесты, сводка, позиция, признак «устарел» и история |
| `POST plan` | `{ rebuild?: boolean }` | Первая сборка; актуальная версия переиспользуется; устаревшая заменяется только при `rebuild: true` |
| `POST progress/steps/{n}/start` | `{ stableId }` | «Изучается», позиция = n |
| `POST progress/steps/{n}/self-check` | `{ stableId, criteriaMet: boolean[] }` | Отметки критериев упражнения |
| `POST progress/lessons/{id}/quiz` | `{ answers: { [questionId]: optionId } }` | Проверка мини-теста; пройденный тест не «отменяется» поздней ошибкой |
| `POST progress/steps/{n}/complete` | `{ stableId, completionMet: boolean[] }` | Завершение шага; повтор — `alreadyDone` |

## Что ещё нужно для #47 «Мои результаты»

1. Ввод замеров «было → стало» пользователем по контракту `MeasurementV3`: числа, единицы, размер выборки, время проверки, ошибки — без свободного текста о работодателе и клиентах; таблица и миграция.
2. Привязка замеров к шагам этапа «Измерение» и показателям маршрута, версия показателя и метода.
3. Расчёт разницы по правилам урока VAL-02 (минуты, процент от «было», процентные пункты), обязательные оговорки и запрет атрибуции выручки и конверсии ИИ (`attribution: "not_claimed"`).
4. Экран «Мои результаты»: завершённые шаги и артефакты-чек-листы, мини-тесты, замеры, история прежних маршрутов.
5. Экспорт отчёта для руководителя (PDF или текст) только из проверенных полей, с отметкой «учебные данные».
6. Сроки хранения и удаления прогресса и замеров (сейчас удаляются каскадом вместе с диагностикой при очистке через 30 дней после окончания доступа) — согласовать с правовой частью.
7. Настоящий маршрут: утверждённые уроки, публикация слотов и правовая приёмка — без них «Мои результаты» на реальном контенте пусты.
