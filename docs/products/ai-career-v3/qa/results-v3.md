# Кабинет AI Career 3.0 — «Мои результаты» (#47)

Статус: **работает в синтетическом тестовом контуре на тестовой библиотеке-заглушке**. Это не готовый продукт: утверждённых уроков нет, поэтому на настоящем контенте маршрута, а значит и результатов, нет. `salesEnabled`, `legalApproved`, платежи и статусы уроков не менялись, review-уроки не публиковались, production не затрагивался.

## Что сделано

| Требование | Реализация |
| --- | --- |
| Хранение замеров | Миграция `008_v3_measurements.sql`, таблица `career_v3_measurements`: одна строка на шаг версии маршрута; связь с аккаунтом (только из сессии), версией маршрута, шагом (внешний ключ на строку прогресса), учебной метрикой роли (`metric_kind = 'exercise'`) и режимом практики |
| Только структурированные данные | Значения «было» и «стало» (число, число задач, дата), единица из списка, время проверки и исправления, число найденных ошибок, пять заранее заданных условий сопоставимости и коды ограничений. Свободного текста нет ни в API, ни в базе |
| Прогресс не дублируется | Завершённые шаги, мини-тесты и история читаются из таблиц миграции 007 через `progress-store` |
| Формулы на сервере | `lib/career-v3/results.ts`: «стало» для минут = работа + проверка + исправление; абсолютная разница; процент от «было»; разница долей в процентных пунктах; при нулевом «было» — объяснение вместо процента |
| Когда вывода нет | Нет «было» или «стало», не подтверждено любое условие сопоставимости, меньше 3 задач в замере, для минут не указано время проверки, показатель рабочий — показывается «Недостаточно оснований для вывода» с причинами |
| Рабочие показатели | Доля ответов, время первого ответа, продления, скорость решения вопросов (`workplace_outcome`) не записываются и не сравниваются: сервер возвращает 409, база не примет строку |
| Экран «Мои результаты» | Завершено N из 30 шагов, пройденные уроки и мини-тесты, замеры «было → стало» с формулами, что именно измерено, история прежних маршрутов с числом замеров, пометки «урок обновлён» и «урок снят», предупреждение об устаревшем маршруте; явная оговорка, что отметки — самопроверка, а не подтверждение навыка |
| Кейс для руководителя | `lib/career-v3/report.ts`: шесть разделов из сохранённых полей; три варианта — отчёт о результатах, предложение двухнедельного пилота, просьба обсудить развитие |
| Экспорт | Копирование текста и PDF (шрифт DejaVu, только текст отчёта). В каждом отчёте — учебный характер данных, даты замеров и отсутствие доказанной связи с бизнес-результатами; email, ID аккаунта и маршрута, токены не попадают |
| Процент прогресса | Округление до целого: 2 из 30 — «≈7%» (раньше 6%), точное число шагов показывается рядом |

## API (только синтетический контур)

| Запрос | Что делает |
| --- | --- |
| `GET results` | Сводка, уроки, мини-тесты, слоты замеров с расчётами, история |
| `POST results/measurements/{n}` | `{ stableId, metricId, measurement }` — сохранить или заменить замер шага (повтор обновляет ту же строку, `revision + 1`) |
| `GET results/report?kind=results\|pilot\|development` | Отчёт для руководителя |
| `GET results/report.pdf?kind=…` | Тот же отчёт в PDF |

## Три примера сформированных отчётов

Сформированы сервером для аккаунта браузерного теста (2 завершённых шага, один полный замер, один замер без «было»), тестовая библиотека-заглушка.

### 1. Отчёт о результатах обучения

```text

Учебные данные: результаты получены на вымышленных задачах в учебном контуре, а не на рабочих данных.
Даты замеров: 10.11.2026–18.11.2026.
Связь с выручкой, конверсией, продлениями и другими бизнес-результатами не доказана и не утверждается.
Сформировано на тестовой библиотеке-заглушке для проверки интерфейса — это не учебные материалы.

1. Какую задачу я изучал
— Коротко о пройденном в учебной программе «Менеджер по продажам»: завершено 2 из 30 шагов.
— «Какие данные нельзя передавать ИИ» — завершено шагов: 1 из 1.
— «Правила работодателя и согласование инструмента» — завершено шагов: 1 из 1.

2. Какой безопасный способ работы проверял
— Режим практики: разрешённые инструменты, общедоступные и учебные данные.
— Каждый учебный результат проверен мной по критериям урока; решения и действия оставались за мной, данные — только вымышленные.
— Мини-тесты пройдены: 2 из 2.
— Отметки о выполнении — самопроверка, а не объективное подтверждение профессионального навыка.

3. Что измерил
— Доля ошибок в результате: Число значимых ошибок / число проверенных учебных артефактов.
— Качество и время КП: Минуты + доля предложений без ошибок в ценах, сроках и обязательствах.

4. Что изменилось на учебных данных
— Доля ошибок в результате: недостаточно оснований для вывода — нет исходного замера «было»; не подтверждены условия сопоставимости: задачи «было» и «стало» одного типа и объёма; один и тот же способ замера и чек-лист качества; замер делал один и тот же человек; только вымышленные учебные данные; время «стало» включает проверку и исправление.
— Качество и время КП. На учебных задачах: было 19 мин (4 задачи), стало 13 мин (4 задачи) (стало = работа 2,5 + проверка 7 + исправление 3,5 мин); изменение −6 мин, −32% от «было». Это наблюдение на учебных данных, а не доказанный эффект.

5. Ограничения результата
— Учебные данные на вымышленных задачах, а не рабочие показатели
— Связь с выручкой, конверсией, продлениями и другими бизнес-результатами не доказана и не утверждается
— Мало задач в замере

6. Какой следующий эксперимент предлагаю согласовать
— Повторить замер тем же способом на большем числе сопоставимых учебных задач, чтобы понять, устойчиво ли изменение.
— Решение о любом применении на рабочих задачах остаётся за руководителем и правилами компании.

Сформировано 19.11.2026 в учебном кабинете.
```

## Ограничения системы

- Единицы измерения для учебных метрик заданы в коде (`METRIC_UNITS`) для пилотной профессии; для новых профессий их нужно вынести в конфигурацию профессии.
- Минимальный размер выборки (3 задачи) и правило округления (до целого процента, половина вверх) — методические решения, требуют приёмки владельцем.
- Сопоставимость подтверждает сам пользователь отметками; система не может проверить, что задачи действительно сопоставимы.
- Значения вводит пользователь; система не проверяет их по артефактам.
- PDF содержит только текст отчёта, без графиков; шрифт встраивается подмножеством.
- Отчёт на тестовой библиотеке содержит названия уроков-заглушек и пометку об этом.

## Что остаётся до сквозного пилота на реально утверждённых уроках

1. Редакционная, методическая и правовая приёмка уроков (14 написаны, утверждённых 0) и публикация слотов.
2. Слияние цепочки PR движка и кабинета (#60 → #61 → #63 → #67 → этот PR) после ревью.
3. Методическая приёмка правил замеров: единицы, минимальная выборка, условия сопоставимости, тексты трёх отчётов.
4. Правовая проверка: сроки хранения прогресса и замеров, формулировки отчёта для руководителя, оферта (`legalApproved`).
5. Решение владельца о `salesEnabled` и настоящих платежах — вне рамок тестового контура.
6. Пилот с реальными пользователями только после этих решений; до этого — синтетический контур.
