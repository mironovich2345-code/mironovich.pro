# Экономическая модель Business Map v1

Продукт: «Карта автоматизации бизнеса», цена 4 934 ₽. Цена покупки не является стоимостью внедрения и не подставляется в окупаемость. Основной вход — `calculateBusinessMap(input, model?)`; все числа вычисляет обычный TypeScript без ИИ, сети и новых зависимостей.

## Величины и источники

| Показатель | Формула | Смысл |
| --- | --- | --- |
| n | N команды × k периода | Выполнений в месяц; B2 повторно не умножает объём |
| H | n × t / 60 | Текущие человеко-часы |
| w | S × λ / h; либо введённая ставка | Стоимость часа; прямую ставку не нагружаем λ повторно |
| C | H × w | Стоимость рабочего времени, **не снижение расходов** |
| G | H × m × (1 − e) | Автоматизируемая механическая часть до проверки |
| F | G × (1 − ρ) | Потенциал высвобождения после проверки человеком |
| R | H − F | Остаточный ручной труд |
| FTE | F / h | Эквивалент рабочего времени, не рекомендация сократить штат |
| V_time | F × w | Стоимость потенциальной ёмкости, **не деньги на счёте** |
| D | min(F, H_repl) × w_repl + X | Только отменяемый внешний ресурс/сверхурочные и подтверждённые пользователем платежи |
| Z | Внедрение + обучение | Разовые расходы пользователя |
| O | Лицензии + поддержка + внешние расходы | Ежемесячные расходы пользователя |
| Θ | Z / (D − O), только D − O > 0 | Окупаемость по прямому снижению расходов |

Если сотрудники сохраняют зарплату, освобождённое время не даёт сокращения фонда оплаты. При `cash.disposition=retained` часть `min(F,H_repl) × w_repl` равна нулю. X — отдельно названные отменяемые платежи; по умолчанию D=0. `capacityRevenue` — отдельная оценка пользователя C5, не прибавляется к D и не участвует в Θ.

Формулировка «избежим найма» — заявление пользователя, не бухгалтерски доказанная экономия. Ядро не проверяет договоры и не подтверждает намерения самостоятельно.

## Версионируемые гипотезы

Все значения собраны в `config/business-map-model.ts`, версия `business-map-v1`: λ=1,3; h=165; k=21, 52/12, 1; бакеты m/e; ρ=0,30/0,20/0,10; веса и пороги сложности/риска/ценности; матрица; порядок групп и уверенности; правила округления; контроль низкой повторяемости; порог долгой окупаемости. Конфигурация передаётся в чистую функцию, поэтому для калибровки не нужно переписывать формулы. Любое изменение требует новой версии и обновления контрольных примеров. Пользовательские λ и h сохраняются во входе. Для h порядок приоритета: процесс (например фактические смены импорта), компания, конфигурация.

| Сценарий | m | e | ρ | Z, O | Длительность C1 |
| --- | --- | --- | --- | --- | --- |
| Консервативный | Низ бакета | Верх бакета | 0,30 | Верх диапазона | Минимум |
| Базовый | Середина | Середина | 0,20 | Среднее границ | Введённая точка B4 |
| Оптимистичный | Верх | Низ | 0,10 | Низ | Максимум |

Без C1 во всех сценариях используется B4. Границы C1 — уточнение сценарной нагрузки, а не доверительный интервал из наблюдений. Сценарные допущения — гипотезы [Г], не вероятность успеха и не процент, вычисленный из баллов.

## Неизвестные и нулевые данные

- B2–B4 могут быть null: G1 запрашивает соответствующие поля. При известных B3/B4 H можно показать, но без B2 ранжирование не назначается.
- Без зарплаты и ставки остаются H, F, FTE, D и затраты; C и V_time равны null. Известный ноль зарплаты/ставки — настоящий ноль, не отсутствие данных.
- Неизвестная механическая доля или исключения — нет F. При исключениях >50% F запрещён (G3).
- Незаданные статьи затрат не равны нулю. Каждая статья — `[min,max]`; только `[0,0]` означает известное отсутствие. При частичном вводе у payback есть перечень недостающих статей.
- При известных O и D−O≤0 статус `not-recoverable`, даже если Z неизвестны: конечная неотрицательная инвестиция не окупится за счёт неположительного потока. Иначе без Z/O статус `not-calculated`.
- Проверка человеком уже учтена в F. Повторное вычитание стоимости всего R из D запрещено; R — стоимость сохранённого труда, а не дополнительный денежный расход проекта.
- При Z=0 и положительном D−O Θ=0. Отрицательные затраты/часы и неконечные значения отклоняются.

## Арифметика и показ

`Decimal` использует BigInt-числитель/знаменатель: десятичные значения и 52/12 представлены точно. Формулы, сравнение порогов, сортировка и сводные суммы не используют округлённый экранный результат. В ответе каждая величина содержит `exact` (`числитель/знаменатель`), `value` (приближённый JSON number) и `display`.

Округление half-up только при показе: часы 0,1; FTE 0,001; стоимость часа 0,01; рублёвые суммы до 100, от 100 000 — до 1 000; месяцы до целого. Потребитель должен показывать три сценария рядом, а не выдавать базовый за гарантированный результат. При смешанных статусах окупаемости нельзя строить конечный диапазон только из окупающихся сценариев.

Граница T6: H=41,25 даёт F_base=16,5 и среднюю ценность; H=41,2 даёт 16,48 и низкую. Оба экранных F могут равняться 16,5. Категорию определяет точное значение; будущему UI нужен доступ к исходным данным/формуле, а не изменение категории по округлённому числу.

## Оценки и приоритеты

Сложность: 6 составляющих из §5, пороги 4 и 7. Риск: последствия ошибки + человеческое суждение + персональные данные, пороги 2 и 3. Уверенность отдельно: измерено без неизвестных — высокая; оценка при ≤1 неизвестном — средняя; иначе низкая. Неизвестные персональные данные принудительно дают низкую уверенность по специальному правилу §5.

Ценность: точный F_base/h, границы 0,10 и 0,30. Матрица 3×3 хранится в конфигурации. Высокий риск понижает first до later; низкая уверенность first до preliminary. Все барьеры записывают коды `R-G1`…`R-G6` и перекрывают матрицу. Неизвестные компоненты без заданного веса не заменяются придуманным баллом.

Порядок: группа → F_base по убыванию → уверенность → сложность → риск → название (русская сортировка) → id для полного равенства. Недостаточные/исключённые строки не получают места в `ranking`. `recommendedId` указывает только на first; при отсутствии first возвращается отдельный `fallbackId` с причинами, без заявления «проверить первым». Исключённый процесс никогда не fallback.

| E2 | D=7 000 / 7 000 / 7 000; Θ=30 / 25 / 20; базовый срок >24 месяцев |
| E3 | D=7 203 / 11 760 / 17 860,5; Θ≈28,551 / 11,416 / 5,383; показ 29 / 11 / 5 |
| E4 | Без затрат: not-calculated |
| E5 | D=2 000, O=3 000: not-recoverable |

Пересечения и неизвестная независимость блокируют сводные H/C. Частные расчёты не изменяются, «доля пересечения» не выдумывается. Превышение h×B2 помечается W-CAPACITY и блокирует общий итог. По диапазону численности компании нельзя восстановить точный фонд команды; общей проверки загрузки общих исполнителей без их учёта нет. При смешении исторических ставок salary без начислений и полных ставок employers/hourly сводный C блокируется отдельно, H может оставаться показан.
