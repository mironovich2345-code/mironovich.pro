# Следующий этап

Расчётное ядро готово для вызова анкетой и сервером. В этой ветке не реализованы интерфейс, база, аккаунты, оплата, ИИ и деплой. Цена продукта 4 934 ₽ остаётся продуктовым контекстом, не финансовым коэффициентом.

## Сначала согласовать семантику

1. Утвердить зафиксированные в technical-audit.md трактовки G3, G5/G6, одновременных барьеров, неизвестных категорий и границ C1. Блокировки для текущих формул нет; изменения правил требуют версии модели и новых ожидаемых примеров.
2. Решить, как объединять несколько групп v4 в один процесс без потери ставок, календаря и длительности. Текущий чистый импорт сохраняет их раздельными строками. Старые строки с зарплатой без начислений должны показывать основание ставки.
3. Определить точный учёт общих исполнителей и общих отменяемых платежей. До этого общий денежный эффект процессов нельзя суммировать; независимость трудозатрат не доказывает независимость экономии.
4. Уточнить источники времени C2, название цифровых систем и необходимость дополнительных tie-break по A3/переделкам. Текущий порядок следует полной процедуре §5.

## Анкета и кабинет

- Использовать nullable/unknown контракты ядра, показывать ошибки по полям, сохранять черновик и пересчитывать только затронутый процесс/рейтинг.
- Показать допущения из конфигурации и ввод λ/h. В карточке каждой величины — входы и формула; в T6 объяснять категорию по неокруглённому FTE.
- Показывать три сценария, раздельные стоимость времени, ёмкость и прямое снижение платежей. Не формировать «общую экономию» суммой C, V_time, D и C5.
- Реализовать состояния недостаточных данных, подготовки, исключения, предварительной рекомендации и отсутствия окупаемости. Fallback не называть рекомендацией «проверить первым».
- План проверки процесса: хронометраж, выборка исключений, проверка человеком, ответственный. Матрица — гипотеза для пилота, не обещание результата.

## Хранение и перенос

- В отдельной задаче реализовать серверный черновик §7, защищённую cookie, срок жизни и проверку исходных параметров; числа результата всегда считать заново.
- Реализовать AnalysisSnapshot, историю версий, серверную принадлежность аккаунту, optimistic revision и удаление данных. Отдельно проверить сценарий T23: покупатель не может открыть чужой процесс.
- Оплату, регистрацию и проверку покупки делать в отдельном этапе с решениями владельца; не смешивать их с расчётной библиотекой.

## Проверка гипотез

На 5–10 клиентах измерить m/e/ρ, нагрузку на зарплату и фонд времени, реальный уровень сложности/риска и понятность первого приоритета. Менять конфигурацию после анализа этих наблюдений, а не подгонять контрольные тесты под желаемые цифры.

T22 (проверка чисел в ИИ-тексте) относится к будущему этапу ИИ. Расчётный модуль от ИИ не зависит; при его внедрении числа должны поступать из результата ядра, затем проходить отдельную проверку. Не подключать OpenAI API в рамках этой ветки.

Публикация, Railway-деплой, PR №9 и main в рамках этапа 1 не изменяются.
