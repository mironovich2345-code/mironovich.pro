# Контракты данных и границы интеграции

Публичная точка входа: `lib/business-map/index.ts`. Типы: `contracts.ts`; проверка входа: `validation.ts`; расчёт: `calculate.ts`; импорт исходных параметров: `transfer.ts`. Чистые функции могут вызываться сервером или локальным клиентом. Сервер на следующем этапе обязан повторно проверить вход и пересчитать результат.

## Вход

`BusinessMapInput = { company: Company; processes: Process[] }`.

Компания хранит A1–A4 (`industry`, `headcount`, `goal`, `systems`), необязательную зарплату A5 и переопределения `salaryLoad`/`monthlyHours`. Фонд часов процесса при импорте имеет приоритет над фондом компании. Численность компании — категория, не точное количество сотрудников и не финансовый множитель. Системы — непустой список стабильных кодов. Контекстные поля не повышают числовые показатели процесса.

| Часть Process | Поля | Семантика |
| --- | --- | --- |
| Идентификация | `id`, `name`, `description?` | Стабильный id, название ≤80, описание ≤300 символов |
| B2–B4 | `employees`, `operations`, `period`, `minutes`, `source` | Nullable числа; operations — общий объём команды за день/неделю/месяц. Неизвестное — null, не 0. Ноль операций допустим; длительность 1–600 минут |
| Пригодность | `mechanical`, `systems`, `regulation`, `exceptions`, `error`, `judgment`, `access`, `personalData` | Категории из §5; механическая доля/исключения — бакеты, не проценты по баллу. Для неизвестных категорий `unknown`, для неизвестных систем null |
| Уточнения | `minutesRange?`, `hourlyRate?`, `capacityRevenue?` | Диапазон длительности включает B4; ставка уже задана за час; дополнительный эффект — отдельная оценка пользователя |
| Пересечения | `independent`, `overlapsWith` | Независимость подтверждает пользователь. Пересечение в любой из двух сторон блокирует суммирование. Ссылки только на существующие процессы, без самоссылок |
| Денежное снижение | `cash?` | disposition, replaceableHours, replacementRate, cancelledPayments. Отсутствует — D=0; retained запрещает денежный эффект от внутренних часов |
| Затраты | `costs?` | implementation, training, licenses, maintenance, external — необязательные диапазоны `[min,max]`; неопределённое не равно нулю |
| Происхождение импорта | `periodsPerMonth?`, `monthlyHours?`, `rateSource?` | Сохраняют календарь, личный фонд часов и основание ставки калькулятора; не являются присланным результатом |

`systems` процесса — список кодов цифровых систем и/или `paper`, `voice`. Только последние два кода считаются недигитальными. Число систем определяется по уникальным кодам; неизвестное не обозначается строкой `unknown` в списке, для этого используется null. Продуктовый UI должен давать пользователю согласованный список систем.

Все категории пригодности присутствуют в контракте даже в незавершённом процессе: быстрый уровень заполняет их `unknown`/null, не выдумывая ответы. Невалидные значения возвращают ошибки, а не подменяются значениями по умолчанию.

## Результат

`BusinessMapResult` содержит `modelVersion`, все результаты процессов, `ranking` (только ранжируемые id), `recommendedId`, отдельный `fallbackId`, сводные H/C или null и `totalBlockers`. При `MIXED-COST-BASES` блокируется только C: независимые H остаются показаны, но зарплату без начислений нельзя складывать с полной стоимостью работодателя.

`ProcessResult` содержит H, w, C; ровно три сценария при достаточных данных; оценки ценности, сложности, риска и уверенности; пригодность; предварительную группу матрицы; итоговый статус; машинные коды причин; недостающие поля; предупреждения; флаг базовой окупаемости >24 месяцев. Отсутствующий сценарий — не сценарий с нулевым эффектом.

`Quantity = { value, exact, display }`: `exact` — строка рационального числа `n/d`, пригодная для JSON и будущих снимков; `value` — приближённое число для внешних потребителей, не основание для повторного расчёта; `display` округлён по модели. Нельзя считать от display или выдавать V_time за cashReduction.

`Scenario` разделяет H, F, R, FTE, V_time, D, C5, Z, O и payback. Срок — `calculated`, `not-calculated` или `not-recoverable`; неизвестные месяцы всегда null. `paybackRange` на уровне процесса содержит min/max только когда окупились все три сценария; смешанный/неизвестный результат не скрывается конечным диапазоном.

### Коды состояний

| Код | Значение |
| --- | --- |
| `R-G1` / `R-G2` | Не хватает быстрых данных / механической доли |
| `R-G3` / `R-G4` | Стандартизировать исключения / оцифровать вход |
| `R-G5` / `R-G6` | Исключение, нужна экспертная оценка |
| `R-MATRIX-{VALUE}-{COMPLEXITY}` | Исходная позиция в матрице |
| `R-HIGH-RISK` / `R-LOWCONF` | Понижение рекомендации из-за риска / уверенности |
| `R-MISSING-ASSESSMENT` | Недостаточно сведений для одной из оценок |
| `W-LEGAL-REVIEW` | Уточнить правовое основание обработки персональных данных |
| `W-LOW-REPEAT` / `W-CAPACITY` | Редкий процесс / превышен фонд времени участников |
| `W-OVERLAP` / `W-MISSING-RATE` / `W-LOW-CONFIDENCE` | Уточнить независимость / ставку / источник данных |
| `W-CALCULATOR-SALARY-NO-LOAD` | Историческая зарплатная ставка v4 без начислений |

Машинные коды должны переводиться в человеческие тексты будущим интерфейсом; поясняющий ИИ не вправе изменять числа или статус.

## Пример вызова

```ts
import { calculateBusinessMap, type BusinessMapInput } from "./lib/business-map/index.ts";

const input: BusinessMapInput = {
  company: { industry: "IT", headcount: "1-10", goal: "cost", systems: ["crm"], salary: 60000 },
  processes: [{
    id: "reports", name: "Ежедневный отчёт", employees: 3,
    operations: 10, period: "day", minutes: 12, source: "measured",
    mechanical: "from50to75", systems: ["crm"], regulation: "yes",
    exceptions: "from10to30", error: "minor", judgment: "rare",
    access: "available", personalData: "no", independent: true, overlapsWith: [],
  }],
};
const result = calculateBusinessMap(input); // H=42, не 126
```

## Проверка и перенос

`parseBusinessMap(unknown)` возвращает `{ok:true,value}` либо `{ok:false,errors}` с путями полей. Невалидные поля не модифицируются; вызывающая анкета сохраняет свой черновик и показывает ошибки. При неизвестных входах используются явные null/unknown. Неизвестные свойства компании, процесса, cash и costs отбрасываются. Совокупный результат, не представимый конечным JSON number, отклоняется с RangeError вместо Infinity/NaN. Даты и случайные значения в расчёт не добавляются — повторный вызов детерминирован.

`transferCalculator(unknown)` принимает существующий ToolContext. Сначала `parseToolContext` проверяет версию и белую схему, затем преобразуются только исходные параметры. Клиентские H/C, бюджет и результат игнорируются. Новый калькулятор проверяет преобразованный ввод ещё раз. Поддерживаются legacy labor, v3 cost-why и числовые данные v4 (включая known из diagnosis). v2 без однозначной миграции требует уточнения через v3/v4; качественная диагностика без чисел не становится вымышленным процессом.

Для v4 разные группы сотрудников переносятся отдельными строками с id `{groupId}-{task}`. Это сохраняет разные ставки/длительности, не усредняя их наугад. При превышении пяти строк перенос отклоняется с запросом выбрать процессы. Автоматическое объединение неоднородных групп в один продуктовый процесс — открытое решение следующего этапа; нельзя просто складывать уже округлённые результаты. Ставка v4 сохраняет основание `salary`/`employer`; исходный график не заменяется средним календарём.

Текущая функция не создаёт ссылок, cookie или доступа. Будущий HTTP-обработчик передаёт только исходные данные, пересчитывает их на сервере и хранит черновик по непрозрачному идентификатору в защищённой cookie, срок 24 часа [Г]. Никаких параметров компании/расчёта в URL и логах.

## Личный кабинет следующего этапа

`AnalysisSnapshot` задаёт JSON-конверт: `schemaVersion`, `accountId`, `analysisId`, `revision`, `createdAt`, input и result с версией модели. Это тип, а не реализованное хранилище. Даты и id назначает будущий сервер, вне чистой расчётной функции. При изменении модели сохраняется прежний снимок; пересчёт создаёт новый с новой версией.

Сервер сам устанавливает accountId из проверенной сессии, проверяет право на каждый процесс/анализ, лимит пяти активных процессов и конкурентную revision. Присланный accountId и сохранённый result не являются доказательством доступа или источником формул. База, регистрация, доступ, платежи, маршруты и OpenAI API в этой ветке отсутствуют.
