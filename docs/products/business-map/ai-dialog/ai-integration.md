# Серверная интеграция OpenAI

Реализован реальный HTTP-клиент официального [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs): `POST https://api.openai.com/v1/responses`, `text.format.type=json_schema`, `strict:true`, `store:false`, конфигурируемая модель. SDK и новые зависимости не добавлены. `store:false` отключает хранение Responses в продукте API, но не является обещанием Zero Data Retention или отсутствия журналов провайдера.

**Статус приёмки:** ключ в среде разработки не предоставлен. Официальный сетевой вызов с действительным ключом не выполнялся. Проверены реальный route/policy и адаптер с подменённым HTTP-транспортом: формат запроса, схема, валидация, отказ, ошибки, таймаут, бюджет. Моки и демо не являются проверкой качества модели. До владельческой проверки нельзя объявлять живую ИИ-интеграцию принятой.

| Переменная | Значение / назначение |
|---|---|
| NODE_ENV | `production` для Railway Preview |
| RAILWAY_ENVIRONMENT_NAME | строго `preview` |
| BUSINESS_MAP_PROTOTYPE | `1` |
| SITE_NOINDEX | `1` |
| BUSINESS_MAP_PREVIEW_USERNAME | ASCII `[A-Za-z0-9._-]`, 1–64 символа |
| BUSINESS_MAP_PREVIEW_PASSWORD | секрет Railway, 16–1024 символа без управляющих; предпочтительно случайный длинный пароль |
| BUSINESS_MAP_AI_ENABLED | строго `1`; `0` или отсутствие — офлайн |
| BUSINESS_MAP_AI_MODEL | ID доступной в проекте OpenAI модели с Responses и strict JSON Schema; обязателен, автоматического fallback нет |
| OPENAI_API_KEY | секрет только серверного OpenAI-проекта, не `NEXT_PUBLIC_*` |

Node 22, Build `npm run build`, Start `npm run start -- --hostname 0.0.0.0 --port $PORT`; healthcheck `/healthz`. Открывать HTTPS `/prototype/business-map`, Basic Auth. Для первой проверки выбрать **одну реплику** и задать лимит расходов проекта OpenAI. Не включать public API или production-флаги. Переменные задаёт владелец в отдельном Preview; в этой работе Railway не изменялся и деплой не запускался.

Локальный режим сохранён: `NODE_ENV=development BUSINESS_MAP_PROTOTYPE=1 npm run dev` без Railway-переменных. Диалог/ядро/демо работают, но ИИ POST намеренно запрещён даже в local dev. Для локальной проверки сервера используется production-сборка с профилем Preview и временными тестовыми credentials только в памяти процесса.

`AI Interpreter` извлекает сферу, число подразделений, системы, факты с дословными цитатами, гипотезы из ограниченного каталога, неизвестные/известные объёмы. Числа должны присутствовать в цитате; сложенные моделью командные объёмы и дополнительные финансовые поля отклоняются. Пересчёт per-person делает код после подтверждения. Нулевые/unknown поля не становятся данными. Все модельные предложения показываются для подтверждения.

`AI Advisor` возвращает только качественную проблему, подход, гипотезу, подготовку, метрики, риски и критерии пилота. Цифры, денежные значения, проценты, ссылки и неизвестные поля схемой/валидатором не допускаются. Подход должен входить в каталог сценария; критический риск допускает только организационную подготовку или отказ. Никаких расчётных результатов из LLM.

Передаются только текущее сообщение (до 4 000 символов), сфера, выбранный сценарий, категория риска, текущий вопрос и до 12 коротких подтверждённых текстовых фактов. Полная история, компания, зарплаты, расчётные финансовые результаты, Basic credentials в payload не передаются. Пользовательское сообщение может содержать добровольно введённые числа; интерфейс предупреждает о синтетических данных.

Лимиты в `config/business-map-ai.ts`: контекст 6 000, JSON-запрос 12 000 символов (поток также ограничен байтами), ответ 18 000, max output 2 200 токенов, 15 секунд на ответ, 8 запросов/минуту, 30 принятых вызовов/UTC сутки на процесс, 1 одновременно, 8 обращений из одной вкладки. Повторный requestId не вызывает провайдера повторно; бюджет списывается до вызова, в том числе при ошибке/отмене. Автоповторов нет. Клики/стандартные ответы используют правила; API нужен для свободного/нестандартного описания и отдельной кнопки объяснения плана.

Ошибка/отказ/неполная генерация/невалидная схема не попадает в карту, не печатается в логи и не выдаётся за успешный ответ. Можно продолжить без ИИ. При смене исходных данных запоздавший ответ игнорируется; отмена/сброс также аннулирует его поколение.

Владелец завершает приёмку: задать секреты в Preview, выбрать доступную модель, ввести синтетическое описание про три клуба, подтвердить/отклонить трактовку, проверить 4 × 10 и качественный план, сверить usage и настройки хранения в своём OpenAI-проекте. Значения ключа/пароля не включать в скриншоты, логи или issue.
