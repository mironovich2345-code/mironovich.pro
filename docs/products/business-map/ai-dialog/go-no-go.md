# Допуск после аудита

Дата решения: 15 ноября 2026. Это решение по локальной проверенной версии, не утверждение об обновлении Railway.

| Область допуска | Решение | Основание / условия |
|---|---|---|
| Локальный офлайн-прототип, синтетические данные, ведущий рядом | **GO** | Разрешённые дефекты исправлены; тесты, production HTTP и пять ширин проверены. Возможности показывать как правила/демо, а не ответы модели |
| Закрытый браузерный просмотр владельцем/модерируемая сессия предпринимателя без ИИ | **Условный GO** | Владелец обновляет только существующий Preview на итоговый SHA, меняет branch **и** pin, проверяет HTTPS Basic/cache/noindex, оставляет AI выключенным. Сейчас там старый SHA, поэтому результат аудита не описывает живую страницу |
| Реальная AI-диагностика с предпринимателями на вымышленных данных | **NO-GO сейчас** | Нет live-вызова, модели, token usage/latency и экспертной оценки настоящих ответов. Нужны выделенный ограниченный проект, владельческое обновление, успешный live-чек-лист А–Е, понятная мобильная работа и модерация первых сессий |
| Немодерируемое массовое тестирование / реальные данные | **NO-GO** | Общий Basic, in-memory квота, нет проверки приватности/ответственности и сквозного контроля расходов; семантика LLM не гарантируется схемой. Пользователь предупреждён только о синтетических данных |
| Публичная или платная версия 4 934 ₽ | **NO-GO** | Польза персонализации, самостоятельное заполнение полной карты и готовность платить не доказаны; отсутствуют предназначенные для следующего этапа сохранение/аккаунт/платёж и необходимые продуктовые/безопасностные решения. В рамках аудита они не разрабатываются |

## Условия снятия текущих блокеров

1. PREVIEW-01: владелец проверяет целевой project/environment/service, Source.branch=`feature/business-map-ai-dialog`, Source.commitSha=итоговый remote HEAD; в deployment виден тот же SHA, не `3bbf569…`. Только отдельный Preview; main/PR №9/production не затрагиваются.
2. NETWORK-01: живые HTTPS/Auth/RSC/assets/no-store/noindex проверены из разрешённой сети владельца. Доступ из среды аудита заблокировал её proxy, не Railway. Не путать SUCCESS старого deployment с этой проверкой.
3. AI-LIVE-01: отдельный ограниченный OpenAI-проект, реально доступная Responses+strict модель; измерены настоящие latency/input/output tokens, подтверждены извлечение А/В и качественный план, неизвестные и отказ от лишней автоматизации. Не принимать результаты transport stub как live.
4. DEVICE-01: физическая клавиатура телефона/IME, Safari или Android и ручная доступность пройдены по чек-листу; headless reflow не заменяет этот шаг.
5. PRODUCT-01: на модерируемых сессиях предприниматель без неверных финансовых выводов понимает проблему, источник/статус фактов, объясняет 168 часов и выбирает проверяемое действие. Заполнена отдельная матрица восьми критериев по настоящим ответам модели; не сводить приёмку к HTTP 200 и unit-тестам.

## Остановка тестирования

Остановить AI-тест при раскрытии секрета/данных, обходе Basic, неподтверждённых численности/финансовом обещании, автоматическом применении/возврате старого ответа, уверенном пилоте при W-CAPACITY/критическом риске, неожиданных расходах/ретраях или неясных настройках проекта. Сначала отключить AI, при проблеме доступа закрыть Preview владельческим действием. Нельзя решать проблему снятием Auth/noindex, перезапусками ради сброса квоты, открытием production или подменой результатов приёмки.

Критические дефекты в проверенном объёме не подтверждены; это не результат независимого pentest. Локальные блокеры DATA-01/DIALOG-03 устранены, но продукт целиком не объявляется готовым только на этом основании.
