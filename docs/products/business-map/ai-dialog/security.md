# Безопасность закрытого Preview

Работа базируется на защите этапа Preview. Новое исключение в middleware строго одно: **POST `/api/business-map/chat`**. Оно возможно только при полном Preview-профиле и корректном Basic Auth. Остальные `/api/*` и методы записи остаются закрыты; публичные формы не отправляются. API самостоятельно повторяет проверку окружения и credentials до чтения тела/вызова провайдера. GET/HEAD и дочерние пути ИИ-маршрута закрыты.

`RAILWAY_ENVIRONMENT_NAME=production` запрещает прототип и новый API независимо от NODE_ENV, флагов, пароля или ключа. API закрыт и в локальном dev; локальный HTML-режим сохранён. При отсутствии credentials всё закрыто, при неправильных — Basic challenge. Исключение `/healthz` отдаёт только готовность сервиса, не HTML/данные.

HTML, CSS/JS/chunks, RSC/prefetch и legacy Next data paths в Preview требуют аутентификацию. Не используется доверие к Referer, grant-заголовкам, localStorage, URL-токенам или клиентской проверке пароля. Новый API возвращает private/no-store, CDN/Surrogate no-store, noindex и Vary: Authorization на успешных и ошибочных ответах. После входа публичные страницы Preview также остаются закрыты для внешнего посетителя.

Дополнительные проверки API: POST, точный путь, JSON Content-Type, Origin совпадает с origin запроса, Sec-Fetch-Site не cross-site, ограничение длины до JSON parse и проверка каждого поля. Источник Origin отсутствует у допустимого серверного клиента; это не замена Basic. Публичный CORS не добавляется. Credentials проверяются существующей функцией с сравнением SHA-256 фиксированной длины. API-ключ и пароль не входят в клиентские props/bundle или ответы.

Защита промпта состоит из разграничения system/data, отсутствия инструментов/действий у модели, ограниченного каталога сценариев, strict JSON Schema, независимой серверной валидации и подтверждения пользователем. Модель не получает финансовое ядро. Цифры в извлечённых фактах/объёмах проверяются по цитатам; финансовые поля/проценты/цифровые прогнозы не допускаются. Качественный совет также проверяется на финансовые обещания. Это уменьшает последствия prompt injection, но не доказывает семантическую истинность любой фразы модели: пользователь должен проверить текст и границы пилота. Ответы рендерятся как обычный React text, не HTML/выполняемый Markdown.

Текст диалога, входные данные, API-ошибки провайдера, ключи и Basic credentials не логируются прикладным кодом. Лимитер хранит только счётчики, UTC-интервалы и случайные requestId; не хранит IP, сообщения или ответы. Отмена не гарантирует, что провайдер перестал обрабатывать уже отправленный запрос: бюджет списывается заранее.

**Граница защиты расходов:** лимит на процесс, не распределённый. Перезапуск обнуляет память; несколько реплик/сервисов имеют независимые бюджеты, а requestId может попасть на другую реплику. Поэтому использовать одну реплику, отдельный ограниченный OpenAI-проект и его бюджет. Это не полноценная защита от злоупотреблений для публичного продукта. Перед открытием широкой аудитории нужны единый лимитер, идентификация, аудит и отдельная проверка приватности.

Синтетические данные — обязательное ограничение интерфейса. Вкладка хранит состояние в React RAM; нет cookies приложения, local/sessionStorage, IndexedDB, DB, регистрации, оплаты или сохранения компании на сервере. Сервер обрабатывает переданный текст временно и отправляет минимальный контекст OpenAI при включённой функции; политику хранения OpenAI нужно проверить отдельно. Reload удаляет карту. В демо нет имитации успешного платежа.

`PublicSiteOnly` продолжает исключать аналитику, публичную навигацию и формы на `/prototype/business-map`. Публичные калькуляторы и их API не изменены. Никаких инфраструктурных изменений и самостоятельного деплоя не выполнялось.
