## OpenAI и безопасность: что доказано

- Отправляется официальный `POST /v1/responses`, заданная env-модель, `store:false`, `text.format=json_schema`, strict=true. Все поля объектов required, additionalProperties=false; неизвестные допускаются через null, tools отсутствуют. Структура проверена рекурсивно, но реальная совместимость выбранной модели пока неизвестна.
- System instructions отделены от сериализованных user data; история целиком, пароль и финансовые результаты не передаются. Сервер повторно валидирует ответ и цитаты. Трактовка показывается для подтверждения; после изменения фактов неподтверждённый результат и все зависимые AI-планы сбрасываются. Source rules/core/OpenAI/demo различается.
- При 429, 5xx, сетевом сбое, refusal, incomplete, плохом JSON/schema и тайм-ауте нет автоматического retry/применения содержимого. Исправлен timeout при полученных заголовках и зависшем теле. Ни исходная ошибка провайдера, ни секрет не возвращаются.
- Один вызов одновременно, 8/минуту, 30/UTC-сутки **на процесс**, 8 из вкладки. Бюджет занят до провайдера, включая неудачи; повтор requestId → 409; новый ID не обходит concurrency/daily. Рестарт, другая реплика и следующий UTC-день имеют отдельные бюджеты; reload снимает только клиентский лимит. Это не публичная система квот.
- API независимо от middleware закрыт вне Preview, включая local dev. Auth до чтения тела; JSON/Origin/Sec-Fetch-Site; пределы 4 000/6 000/12 000/18 000 символов и потоковые byte limits. Персонализированные ответы private/no-store, CDN/Surrogate no-store, Vary Authorization, noindex.
- В прикладном коде нет логирования текста/компании/секретов; React рендерит строки, не исполняемый HTML. PublicSiteOnly исключает публичные формы/аналитику. Нет БД, регистрации, платежей, нового AI SDK или внешнего сохранения карты.

Ограничения: проверка цитаты/цифры не доказывает правильную смысловую привязку и отсутствие качественной галлюцинации. Prompt injection проверен как граница инструкций/данных и схемы, а не как обещание полной устойчивости настоящей модели. У authenticated body reader есть лимит размера, но отдельного прикладного дедлайна получения тела до бюджетирования нет; базовая защита от перебора Basic не является полноценной публичной anti-abuse системой. Общий Basic не идентифицирует отдельных тестировщиков. `store:false` не равно Zero Data Retention. Поэтому реальные данные и публичное открытие запрещены.

## Как повторить

```sh
npm ci
npm test
npm run lint
npm run build
npm run typecheck
BUSINESS_MAP_HTTP_REPORT=docs/products/business-map/ai-dialog/acceptance/http-check.json node scripts/check-business-map-preview.mjs
python scripts/check-business-map-acceptance.py
```

Нужен Node 22, Python Playwright и Chromium. `CHROMIUM_PATH`/`NODE_BINARY` задают пути к бинарникам. Для обязательной повторной accessibility-проверки задать `AXE_SCRIPT=/путь/к/axe-core/axe.min.js`; без него runner честно пишет SKIPPED. Тестовые инструменты Playwright/axe были установлены вне репозитория, package.json/lock не менялись. Каждый browser/HTTP runner сам запускает локальный production-сервер, не подключается к Railway, создаёт credentials в памяти и останавливает свои процессы. Build нельзя выполнять параллельно с этими проверками. Live-runner отдельно, opt-in и только по следующему чек-листу.
