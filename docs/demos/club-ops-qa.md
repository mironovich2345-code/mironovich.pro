# CLUB OPS — интерактивная демонстрация (этап 2)

## Статус
- Отдельная демостраница: `/demos/club-ops`. Первоначально `noindex`.
- Функциональность — независимый учебный UI без подключения к исходному `clubops.ru`, клиентским системам, БД, счетам, платежам, CRM или API.
- Привязка публичной кнопки в карточке кейса заблокирована, пока `demoVerification.available` не будет явно подтверждено после QA.
- Не объединять PR с main и не разворачивать production без отдельного решения владельца.

## Три сценария

1. **Расходы — план/факт.** План 500 000 ₽, факт 610 000 ₽, перерасход 110 000 ₽. Пользователь двигает слайдеры ФОТ, аренды и маркетинга.
2. **Кассовый остаток.** 200 000 ₽ + 1 600 000 ₽ − 2 050 000 ₽ = −250 000 ₽. Пользователь меняет поступления и платежи. Уточнение: итоговый остаток не гарантирует отсутствие внутрипериодных разрывов.
3. **Стоимость продажи.** Директ: 120 000 ₽ / 12 = 10 000 ₽; VK: 90 000 ₽ / 5 = 18 000 ₽. Пользователь меняет количество продаж. Не называем результат ROI, полноценным CAC или подтверждённой эффективностью рекламы.

## QA для Codex
- `npm ci`, `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`.
- На локальной production-сборке проверить `/demos/club-ops` при 375/390/768/1024/1440 px.
- Сценарии: переключение кнопками мышью и клавиатурой, слайдеры, сброс, динамические расчёты, 0 продаж, нулевой дефицит и положительный остаток, ссылка на кейс и консультацию.
- `axe` WCAG 2 A/AA, доступность индикаторов и меток, focus, горизонтальный скролл, ошибки JS.
- Проверить SEO: `noindex`, отсутствие в sitemap до согласования; закрытые кейсы по-прежнему 404.
- Проверить, что браузерная демоверсия не отправляет сетевые запросы (кроме ресурсов сайта), ничего не пишет в storage, не использует реальные сведения.
- До публикации: проверить формулировки, права и согласовать включение CTA в `/projects/club-ops` через `demoVerification`, а также снятие `noindex` при желании.
