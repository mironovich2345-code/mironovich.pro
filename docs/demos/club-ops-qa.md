# QA: CLUB OPS — универсальная демонстрация управления филиалами

**Актуальное ТЗ:** [branch-network-demo-spec.md](./branch-network-demo-spec.md).

Предыдущий технический план на 3 финансовых калькулятора устарел. Он не определяет готовность PR #15. Ветка пока содержит этот упрощённый прототип: заменить его на приложение с **10 разделами**, сохраняя внешний вид CLUB OPS, а не стили рекламного лендинга MIRONOVICH.PRO.

## Техническая приёмка
- `npm ci`, `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`.
- В локальной production-сборке проверить маршрут `/demos/club-ops` на 375, 390, 768, 1024, 1440 CSS px.
- Проверить десять экранов, боковую и мобильную навигацию, активную вкладку, форму переключения компании/филиала/периода и имитацию ролей.
- Данные и математические связи с одного fixtures-источника. Пример: филиалы 1,8 + 1,35 + 1,05 млн = сеть 4,2 млн; план 9,6 млн, прогноз 8,4 млн, 87,5% исполнения. Проверить, что фильтр филиала согласован во всех разделах.
- Интерактивные сценарии: переходы в детализацию, фильтры расхождений ОФД/эквайринг/CRM, меняющиеся расчёты, списки счетов/расходов/возвратов, бюджеты и кассовый прогноз. Все изменения только в памяти браузера, сброс возвращает исходные показатели.
- Для ОФД показывать реализованный механизм исходного приложения (Taxcom API импорт/чеки/агрегаты), но не живые секреты, токены и реальные чеки. Для эквайринга/CRM только тестовые записи и чёткая пометка «демонстрационная сверка / возможное расширение».
- Нельзя выдавать «Подписанные документы» за существующую production-интеграцию электронных подписей: это макет будущего функционала, если данные об этом не подтверждены.
- Статусы оплат и возвратов в демо не вызывают API, почту, Telegram или банковские операции. Запрет сетевых запросов к внешним ресурсам. Параметры только локальные, не помещать конфиденциальные данные в query.
- Axe WCAG 2 A/AA, видимый keyboard focus, aria-состояния, no horizontal scroll, отсутствие runtime JS ошибок.
- `noindex` и отсутствие демомаршрута в sitemap до разрешения.
- Корпоративные черновики сохраняют 404; права на исходные UI/изображения должны быть подтверждены, клиентские данные/названия недопустимы.
- Провести ручную контент-проверку всех 10 экранов на слова «клуб», «фитнес», «абонемент», «персональная тренировка»: в интерфейсе демо допустимо только историческое название бренда **CLUB OPS**, остальные тексты — «филиал», «сеть филиалов» и нейтральные отраслевые категории.
- Подготовить 10 desktop-скриншотов (по одному на каждый экран) и 5 mobile-скриншотов разных разделов, отчёт тестов и таблицу «реальная функция / демоверсия / возможная доработка».
