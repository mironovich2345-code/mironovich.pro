## Как читать план

- **Запрос — предварительный.** Доступа к Яндекс Вордстату, Вебмастеру и
  Search Console нет, частотность не указана и не оценивалась. Перед написанием
  статьи запрос стоит проверить и при необходимости заменить.
- **Интент:** И — информационный (разобраться), К — коммерческий (выбрать
  решение или подрядчика), С — сравнение, П — практическая инструкция.
- **Приоритет:** P1 — первая волна (10 статей), P2 — вторая (24), P3 — по мере
  возможности (21).
- **CTA и услуга** — куда статья ведёт в конце: блок «Связанная услуга»
  подставляется автоматически по категории; текст CTA — общий «Обсудить задачу
  бесплатно».
- **Ограничения для всех статей:** без выдуманных кейсов, клиентов, цифр и
  результатов; без брендов CRM, если по ним нет подтверждённого опыта; без
  обещаний попадания в ответы ИИ-систем. Примеры — только типовые и помечены так.
- **Чтобы статьи не конкурировали между собой**, у каждой свой основной запрос;
  пересекающиеся темы связываются через поле `related`.

## Порядок работы над статьёй

1. Согласовать тему и проверить предварительный запрос.
2. Написать текст: ответ на вопрос в первых абзацах, H2 по структуре плана,
   типовые примеры помечены как типовые.
3. Проверить: нет выдуманных цифр, клиентов, результатов и обещаний.
4. Заполнить frontmatter: `category`, при необходимости `service` и `related`,
   `description` до 160 символов, обложка с `coverImageAlt`.
5. `status: draft` → проверка в `npm run dev` → согласование → `published`.
