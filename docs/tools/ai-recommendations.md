# ИИ-рекомендации v2: контракт, ограничения и включение

## Схема и потоки данных

`labor-cost` / `automation-cost` → локальные проверяемые формулы и каталог → полезный результат без заявки. Только отдельное действие с подтверждённым уведомлением вызывает `POST /api/tools/recommendation` → серверная валидация → OpenAI **Responses API** `/v1/responses` → строгий JSON Schema → повторная серверная проверка → карточки из каталога.

Запрос:

```json
{"noticeAccepted":true,"input":{"tasks":["reporting","transfer"],"employees":4,"systems":["tables"],"impact":"unknown"}}
```

Сервер **отвергает дополнительные поля**, включая description, measurements, contacts. В OpenAI не отправляются произвольный текст, имена, контакты, документы, пароли, зарплаты или подробные замеры. Текст «Другая задача» остаётся в памяти страницы и может быть отдельно отредактирован в согласованной заявке. Поэтому ИИ не анализирует содержание нестандартного описания — для него доступна категория other и рекомендация уточнить процесс. Это явное ограничение v2, а не обещание анализа любого текста.

Структурированный ответ модели:

```json
{"priorities":[{"task":"reporting","approach":"service"},{"task":"transfer","approach":"integration"}]}
```

Schema генерируется по выбранным task IDs; additionalProperties:false, strict:true. Модель предлагает порядок и подход из ограниченного списка. Сервер проверяет полный состав, отсутствие дублей, допустимость approach для каждого процесса и блокирует активную рекомендацию анализа звонков при неизвестном/повышенном риске. Пользовательские строки не попадают в prompt; модель не получает инструменты, браузер или документы. Это устраняет канал prompt injection через описание вместо ненадёжной попытки «очистить» произвольный prompt.

Карточки `{task,title,problem,solution,firstStep,type,reason,requirements,checks,measure,human}` формируются из проверяемого каталога после выбора модели. Поля с процентом экономии, бюджетом или сроками отсутствуют. LLM не пишет арифметику и не добавляет утверждения об API. Модель не является независимым аудитом или финансовым прогнозом.

## Данные и совместимость

Схема `tools-2.0.0`, transfer key `mrnv_tools_transfer_v2`, TTL 24 часа, sessionStorage текущей вкладки. Сохраняются только категории, число людей, типы программ, последствия и проверенные числовые замеры. Произвольный текст не сохраняется. Старые v1 ключи новым UI не читаются и безопасно игнорируются; прежние decoders/формулы/ToolContext поддерживаются для старых заявок и тестов.

Новая ветка ToolContext принимает v2 только с валидным input, игнорирует клиентские results/plans и заново вычисляет часы/стоимость и базовые карточки. Прежняя серверная проверка лидов, ограниченный парсер, honeypot, Origin, лимиты и отправка Telegram не удалены. Рекомендация модели намеренно не включается в заявку как доверенный результат. Описание пользователь может отдельно передать формой по существующему согласию.

Проверяемая формула для процесса: участники × повторения за период на участника × минуты / 60 × рабочие периоды в месяце. Ввод рабочих дней/недель обязателен для соответствующего режима. Для месяца множитель — ровно 1 и это следует из единицы измерения. Пустые параметры не превращаются в нули; частично заполненные замеры требуют исправления. Дробная запятая допускается, экспонента и бесконечность — нет. Числа участников не могут превышать команду.

Одинаковый task ID нельзя добавить дважды. Для сводного итога каждого измеренного процесса нужно подтверждение независимости операций. Более 200 часов на участника процесса или суммарно на сотрудника команды — предупреждение и запрет суммирования; 200 — диагностический порог, не юридическая норма времени. Более 744 часов/участника в месяц — отказ как физически невозможный месячный объём. Фактическое пересечение работ код не может узнать по категориям — его подтверждает пользователь. При неполных измерениях итог явно относится только к измеренным независимым процессам. Денежный итог отсутствует, если цена часа неизвестна хотя бы у одного из них. Ни высвобождение времени, ни реальные денежные сбережения не вычисляются без пилота/подтверждения.

## Серверные ограничения

- JSON только с того же Origin; cross-site отклоняется. Тело читается потоково: максимум 3 000 символов / 12 000 байт, включая запрос без Content-Length, с проверкой UTF-8.
- 2 запроса/мин на доверенный клиентский IP и 5/мин на весь процесс. По умолчанию IP-заголовкам не доверяем; применяется общий предел. Настройка RATE_LIMIT_CLIENT_IP — прежняя, только после проверки прокси.
- Две одновременные внешние операции. 30 зарезервированных внешних попыток за UTC-сутки **на экземпляр процесса**, включая ошибки и таймауты; резерв до await. Повторов API нет.
- Таймаут 12 секунд включает fetch, чтение и разбор ответа. AbortController и независимый Promise.race; клиент ждёт максимум 16 секунд.
- Ответ ограничен 16 000 символов / 64 000 байт и проверен повторно. Отказ, incomplete, плохой JSON, лишняя/повторная задача или неверный тип дают контролируемый ответ; базовые карточки остаются.
- max_output_tokens=1200, reasoning.effort=none; никаких инструментов/поиска. Модель — только gpt-5.4-mini или зафиксированный gpt-5.4-mini-2026-03-17. Отсутствие ключа/модели/разрешения даёт 503. store:false, Cache-Control:no-store. Описания, запросы, ответы и ключи приложение не логирует.

**Процессные счётчики не являются общим жёстким бюджетом аккаунта.** Рестарт сбрасывает их, несколько реплик суммируют квоты. До включения в production нужны отдельный проект OpenAI с ограниченным ключом, проверенный внешний общий лимитер/счётчик расходов и правила остановки, контроль числа реплик и мониторинг биллинга. Бюджетные уведомления в кабинете сами по себе не считать гарантированной блокировкой расходов. Сейчас production-доступ остаётся закрытым кодовым gate.

## Цена и проверка актуальности

Официальная карточка [GPT-5.4 Mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini), проверено 08.11.2026: вход $0.75 / 1 млн токенов, выход $4.50 / 1 млн, cached input $0.075 / 1 млн. Используем обычный foreground Responses, без Batch, priority и платных инструментов. Цена не включает налоги, конвертацию, инфраструктуру и другие запросы аккаунта. Региональный processing может иметь отдельную наценку.

Точный счёт = input_tokens × 0.75 / 1e6 + output_tokens × 4.50 / 1e6 по usage и актуальному тарифу; кеш специально не закладывается как гарантированный. Сериализованный запрос ограничен 10 000 байт (включая schema, model и инструкции); технический консервативный ориентир для текстового ввода с запасом на обёртки — 12 000 input tokens, максимум 1 200 output. При этих **условиях оценки**, верхний расчёт одного запроса $0.0144, 30 попыток — $0.432 на процесс в сутки; это не гарантированный лимит биллинга API и не прогноз реального трафика. Реальная токенизация/usage, доступность модели и региональные условия должны проверяться контролируемым staging-тестом после согласования. Живых платных API-вызовов в разработке не было; используются mocks, поэтому биллинг и реальная латентность не измерены.

Выбор более старой дешёвой модели не сделан автоматически: [deprecations](https://developers.openai.com/api/docs/deprecations) содержит запланированное отключение gpt-5-mini 11.12.2026; конфигурация закрепляет более актуальный snapshot. До включения перепроверить тариф/доступность в своём аккаунте и допустимые регионы [supported countries](https://developers.openai.com/api/docs/supported-countries).

## Юридическая готовность и порядок включения

Текущая конфигурация legal.published=false сохраняет старые действующие тексты; черновики содержат незаполненные места. Ни одна старая публикационная оговорка о Railway/Telegram не разрешает обработку через OpenAI автоматически. Для OpenAI подготовлено дополнение `docs/tools/openai-privacy-review.md`, которое **не является опубликованной политикой/согласием**. Сначала согласовать получателей/страны/основания, сроки, удаление, допустимость доступа по региону и связку с техническими журналами. Затем обновить публичные privacy/consent, сверить отдельное уведомление на форме, установить общий устойчивый бюджетный контроль и сделать staging-тест. Только после этого с отдельным разрешением на релиз менять gate/переменные и выкатывать production. В этой задаче это не выполнено и API остаётся off.

Официальные контракты: [Responses create](https://developers.openai.com/api/reference/resources/responses/methods/create), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses), [migration: text.format](https://developers.openai.com/api/docs/guides/migrate-to-responses), [data controls](https://developers.openai.com/api/docs/guides/your-data). store:false отключает хранение состояния Responses, **не обещает zero data retention** для abuse monitoring и не отменяет правовые основания передачи.

## Доступность UI

Текущий выпуск показывает только базовый результат, если серверная recommendationAvailable не подтверждает все условия. Server Components вычисляют её на каждый запрос; force-dynamic исключает статическое решение при build. В GuidedCalculator передаётся только boolean, по умолчанию false. При false нет DOM-контролов OpenAI и нет клиентского запроса проверки доступности. Сам API независимо применяет ту же policy-функцию, прежние ограничения и юридический gate; подмена свойства в браузере не даёт доступа к внешнему сервису. Подробнее: [availability-release.md](availability-release.md).
