Порядок результата: крупная месячная стоимость → часы и годовая оценка → открытая формула,

На телефоне месячная стоимость занимает полную строку. Результат остаётся доступен без формы.

## Реализация

- Оба URL/canonical сохранены. `/tools/labor-cost` обещает стоимость времени;
  `/tools/automation-cost` — причины проверить затраты. Обновлены FAQ/метаданные и карточки
  инструментов, включая каталог `/tools`; статьи и страницы услуг не менялись.
- Ввод — одна форма. Множественный выбор сохранён, рекомендуем начать с 1–3 процессов,
  но ограничение в три не введено. Команда по умолчанию 4, пресеты 4/10/25/50 и ручное число от 1.
- После выбора процесса сразу открыты участники, повторы, минуты, график и стоимость.
  Есть быстрые значения, точный ввод и десятичная запятая; preview обновляется во время ввода.
- Своя ставка часа либо полная месячная стоимость одного сотрудника и его отработанные часы.
  Зарплаты пустые. 22 дня / 4 недели и 160 часов явно отмечены как редактируемые допущения
  до ввода/подтверждения пользователем; признаки допущений сохраняются в контексте расчёта.
- Неизвестная ставка остаётся неизвестной. Отдельный интерактивный пример «при стоимости часа
  X ₽» не имеет выбранного X по умолчанию. Кнопки 300/600/1000 явно условные, не меняют
  фактическую ставку, заявку или storage. Неизмеренное время также не становится нулём.
- Часы, ₽/месяц, ₽/год каждого процесса находятся в открытых карточках, без details.
  Каталог «Готовый сервис» больше не формирует публичное заключение. Старый каталог оставлен
  для совместимости API, а не как основной ответ владельцу.
- Объяснения отвечают «почему проверить», а не «как разработать». Ошибки, повторный ввод
  и неэффективность не объявляются установленными фактами. Есть два проверяемых вопроса.
  Для неизвестного, нулевого или редкого объёма не обещается необходимость автоматизации.
- Один основной CTA «Разобрать эти затраты с экспертом»: реальные узкие места, целесообразность,
  приоритеты, требования, выбор решения и условия пилота. Первичная беседа бесплатна;
  подробный разбор — отдельный согласованный объём. Открытие формы не скрывает результат.

## Формулы и несколько процессов

```text
Операций/месяц = участников × повторов на участника за период × периодов/месяц
Часов/месяц = операций/месяц × минут на выполнение / 60
Ставка = своя ₽/час ИЛИ полная стоимость сотрудника/месяц / его часы/месяц
Стоимость времени/месяц = неокруглённые часы × неокруглённая ставка
Стоимость времени/год = показанная месячная стоимость × 12 при неизменной нагрузке
Стоимость выполнения = минут / 60 × ставка
```

Базовые формулы v2 используются через адаптер без изменения арифметики. Денежные результаты
округляются до копеек; ставка из месячной стоимости не округляется перед умножением.
Контроль: **3 × 20 × 3 × 22 / 60 = 66 ч; 66 × 600 = 39 600 ₽/мес;
39 600 × 12 = 475 200 ₽/год; 3 / 60 × 600 = 30 ₽/выполнение**.
Ни эта сумма, ни весь ручной труд не названы устранимыми потерями, доходом или экономией.
ROI, бюджет внедрения и процент автоматизации не подставляются.

Раздельные показатели есть всегда. Общие часы — только при полных замерах **всех** выбранных
процессов, подтверждённой независимости и разумной нагрузке. Общие рубли дополнительно требуют
всех ставок. При частичных замерах или пересечениях общий итог отсутствует. Если время всех
процессов известно, а ставка одного нет, допустимы общие часы, но общие рубли неизвестны.

Валидация: участников не больше команды, повторы целочисленные; отрицательные/NaN/Infinity/
экспонента отклоняются. Более 744 часов на участника/месяц отклоняется. Более 200 часов на
участника процесса или в среднем на сотрудника команды — предупреждение и запрет агрегации;
это диагностика правдоподобия, не юридическая норма. Фактические пересечения и распределение
людей программа не знает: требуется честное подтверждение владельца и проверка на консультации.

## Контекст заявки и безопасность

Отдельный `ToolContext` версии `tools-cost-3.0.0`: сервер валидирует исходные параметры,
способ задания ставки и допущения, отбрасывает клиентские итоги и пересчитывает часы/рубли/год.
Консультант получает исходную формулу, источник ставки, допущения и количественный контекст.
Для v3 расширен только ограниченный бюджет форматирования структурированного сообщения;
общая длина Telegram остаётся безопасной. Старые форматы не менялись.

HTTP-доставка, Telegram `ok`, Origin, bounded parser, honeypot, лимиты, контактная валидация,
согласие и юридические документы не менялись. `LeadForm` прежний, описание редактируемое;
контакты и расчёт отправляются только после отдельного согласия и отправки заявки.
Проверены 429/ошибка доставки с сохранением ввода и доступного исходного расчёта.

Финальные проверки прошли через настоящий локальный `/api/lead` с заглушкой Telegram:
серверный пересчёт месячной ставки, экранирование, игнорирование поддельного результата,
отсутствие условного сценария в фактической стоимости. Настоящих сообщений не отправляли.
Заглушка сохраняла только технические флаги, не контакты или тексты.

Перенос: отдельный `mrnv_tools_cost_v3`, TTL 24 часа в текущей вкладке. По явному переходу
записывается также совместимый v2 snapshot. Свободный текст и условные ставки в storage
не попадают. Проверяемый адаптер читает прежние v2 замеры; повреждённые/просроченные данные
не используются, ошибка storage не ломает локальный расчёт.

## Совместимость с PR #9

**PR #9 не объединён, не rebased и не перезаписан.** Его ИИ-компонент, endpoint, consent,
legal/provider gates и бюджет не копировались. OpenAI не нужен для получения денег.
Прежний `externalProcessingApproved=false` и оба флага денежной модели внедрения остаются false.

- `GuidedInput`, Task IDs, `GUIDED_VERSION`, формулы и storage v2 не изменены.
- `costToGuided()` даёт совместимый v2 snapshot; `guidedToCost()` импортирует прежние замеры.
- Parser и описание заявок продолжают принимать прежние v1/v2 контексты.
- `GuidedCalculator` сохранён как публичный адаптер; новая логика вынесена из него.
  Client-to-client `resultExtension(input: GuidedInput)` расположен после стоимости/объяснения
  и перед единственной консультацией. По умолчанию пуст, запросов не делает.
- `AutomationCalculator.tsx` и `ToolLead.tsx`, изменяемые PR #9, здесь не менялись.
  Новая консультация — отдельный компонент. Обе ветки меняют `GuidedCalculator.tsx`:
  автоматическое объединение нельзя считать готовой интеграцией.

При отдельном контролируемом объединении нужно сохранить серверную `processAnalysisAvailability()`
из PR #9, принять его `processAnalysisMode` в клиентском адаптере и разместить **его же**
`ProcessAnalysis` в `resultExtension`. Передавать только `snapshot.tasks`, как в PR #9,
а не финансовые данные. Не менять preview, consent reset, PII-проверки и серверные gates.
ИИ остаётся добровольным следующим действием, не условием выдачи основного результата.

После объединения отдельно повторить тесты обоих PR и проверить один основной CTA.
Эта работа проверяет совместимые контракты, **не выдаёт необъединённые ветки за уже проверенный
совместный релиз** и не включает OpenAI. Ветка PR #9 не трогалась.

## Воспроизведение и ограничения

Обычные проверки: Node 22, `npm ci`, `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`.
Для UI — Python Playwright и Chromium; optional `AXE_SCRIPT` указывает на локальный axe-core.
После сборки запустите отдельный локальный сервер с [тестовой заглушкой](../../../tests/fixtures/cost-why-telegram-stub.mjs):

```sh
TOOLS_V3_TEST_STUB=true TELEGRAM_BOT_TOKEN=LOCAL_COST_WHY_TEST_ONLY TELEGRAM_CHAT_ID=LOCAL_COST_WHY_TEST_ONLY NODE_OPTIONS=--import=./tests/fixtures/cost-why-telegram-stub.mjs npm start -- --port 3004 --hostname 127.0.0.1
# В другом терминале; при необходимости AXE_SCRIPT=/path/to/axe.min.js:
python scripts/test-cost-why-browser.py
```

Заглушка требует явного test mode и фиктивных значений, запрещена при Railway/VERCEL env,
блокирует внешние OpenAI/Telegram и пишет только технический JSON. Скрипт допускает только
localhost. Тестовые переменные заданы отдельному процессу; на рабочем Railway это не запускать.

Точность зарплат, графика, состава полной стоимости, реальных пересечений и причин
неэффективности автоматически не подтверждается. Стоимость не доказывает потери или окупаемость.
Chromium-эмуляция и Axe не заменяют физические телефоны, Safari/Firefox и полную экспертизу
доступности. Живая доставка Telegram и совместный релиз с PR #9 не проверялись.
Существующие предупреждения юридического release guard не обходились.

Версия готова к продуктовой приёмке. Merge, production deploy, Railway, рабочие секреты,
юридические документы и включение OpenAI в этом этапе не менялись.
