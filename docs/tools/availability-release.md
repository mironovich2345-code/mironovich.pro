# Версия без OpenAI: серверное управление доступностью

В текущей версии внешний ИИ остаётся выключенным. При недоступной интеграции посетитель не видит в GuidedCalculator ни блок «Приоритеты с OpenAI», ни кнопку, ни checkbox, ни сообщение о недоступной функции. Базовые рекомендации, расчёты, перенос между инструментами и форма заявки остаются доступны.

## Решение

- Доступность проверяется в Server Components по request-time process.env и неизменённому юридическому gate. Нужно одновременно: AI_RECOMMENDATIONS_ENABLED строго true, externalProcessingApproved строго true, непустой серверный ключ и разрешённая модель.
- Оба маршрута инструментов используют force-dynamic: решение не замораживается при сборке и не публикуется как статическая закешированная страница.
- Клиент получает единственное булево свойство openAiAvailable; по умолчанию оно false. Не передаются ключ, название модели, значения переменных, причины отказа или содержимое конфигурации.
- Серверный адаптер защищён import "server-only". Общая чистая policy-функция recommendationAvailable используется и рендером, и API; её можно тестировать без изменения настоящих настроек.
- При false блок не рендерится, а не скрывается CSS. Обработчик клиентского запроса дополнительно сразу выходит. Прямой поддельный запрос к API по-прежнему защищён серверными gate/валидацией/лимитами; видимость UI не считается средством авторизации.
- Юридический gate, .env.example и настройки Railway не изменялись. Внешние вызовы не выполнялись.

## Проверки

169 unit/contract tests (166 прежних + 3 availability tests), lint, typecheck и локальная build-сборка на Node 22. Проверки policy включают выключенный feature flag, юридический gate, отсутствие/пустоту ключа, неподдерживаемую модель и разрешённые синтетические fixtures. Fixtures не включают реальную интеграцию.

Браузерный тест проверяет отсутствие контролов OpenAI в DOM обеих форм и результатов; это также проверяется на 320/375/768/1024/1440 px. Счётчик обращений к /api/tools/recommendation должен оставаться равным нулю. Сохранены сценарии расчёта нескольких процессов, подтверждения независимости, переноса, клавиатуры и заявки с mocked-доставкой. Третий сценарий проверяет описание и полезный результат без OpenAI вместо попытки вызвать заведомо выключенную функцию.

Актуальные скриншоты и машинный отчёт обновляются тем же скриптом scripts/test-tools-browser.mjs. Историческое имя result-ai-fallback-375.png сохранено для существующих ссылок: теперь на этом снимке показан результат вообще без блока OpenAI.

Готовность относится к версии без внешнего ИИ. Merge и production deploy требуют отдельного разрешения. Предложение индивидуального ИИ-разбора остаётся проектом следующего этапа, не частью текущего выпуска.
