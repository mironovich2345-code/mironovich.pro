## Что покрывают новые unit/contract tests

1. 4 сотрудника, пресеты 4/10/25/50, ручной ввод и команда из одного человека; некорректные числа.
2. Несколько task IDs, отсутствие дублей, границы участников, невозможный объём работы.
3. Независимые замеры по процессам, стоимость только при указанной ставке, отсутствие выдуманного высвобождения и денежных сбережений.
4. Запрет сводного итога при неподтверждённой независимости/чрезмерной нагрузке; явные периоды для дня/недели.
5. Перенос категорий/сотрудников/числовых замеров, TTL и отказ от старого v1 в новом UI; произвольный текст в transfer не попадает.
6. Серверная валидация v2 ToolContext и пересчёт без доверия клиентским results; старые контракты остаются покрыты 148 прежними тестами.
7. Отсутствие ИИ-подхода для простого переноса/отчётности, проверка подходов по каталогу.
8. Отсутствие уведомления, prompt injection/контакты/description отклоняются до вызова API.
9. Выключенный feature flag, юридический gate и отсутствие ключа — fail closed.
10. Responses API / strict JSON Schema / store:false / max_output_tokens / server Authorization.
11. Некорректный JSON, incomplete, refusal, дубли и неподходящий approach.
12. Таймаут, upstream/local rate limits, общий дневной резерв и предел двух параллельных обращений.
13. Конкретный отдельный первый шаг для каждого процесса, без выдуманных финансовых обещаний.
14. Ограниченное потоковое тело, Origin, Next internal URL/proxy protocol; X-Forwarded-Host не принимается как доверенный.

Платные OpenAI-вызовы не выполнялись. Контракты провайдера тестируются подменённым fetch; реальную доступность модели, цену списания и задержку конкретного аккаунта надо проверить на staging после правового/бюджетного разрешения. Расчёт тарифов и ограничения — ai-recommendations.md.

## Заявки и безопасность

Дополнительно выполнены запросы к реальному локальному `/api/lead`: корректный v2 context → 503 not_configured (прошёл проверку, остановился на отсутствии Telegram settings); нет согласия → 422 consent_required; поддельное число сотрудников → 400 invalid_tool_context. Реальных сообщений Telegram не отправлялось. End-to-end доставка Telegram не подтверждена: для неё нужен отдельный согласованный staging-тест с настроенным ботом.

В `.next/static` не найдены OPENAI_API_KEY или тестовый ключ. Реальных ключей в исходниках/скриншотах нет. Приложение не логирует данные ИИ-запроса. Пределы на процесс не выдаются за устойчивый общий бюджет: до production нужны внешние общие ограничители и юридическое согласование; API пока выключен.

SKIP_VIEWPORTS=1 пропускает только начальные десять снимков, сквозные сценарии и пять ширин результата остаются.

## Финальная UX-доработка PR #7

Повторные проверки выполнены в той же ветке feature/tools-ai-guided-v2. Результат теперь начинается с короткого «С чего начать» и одного процесса: проблема, решение, первый практический шаг. Остальные задачи, проверки, критерии успеха, условия пилота и финансовые замеры закрыты по умолчанию. Причины выбора одинакового подхода объединяются в общем блоке; общие требования к пилоту и контролю человеком не повторяются в карточках. Детали и предупреждения расчёта не удалены, их можно раскрыть клавиатурой.

Причина красной рамки в прежнем result-beginner-375.png: глобальный :focus-visible применялся к программно фокусируемому h2 после клавиатурного запуска. Добавлено только scoped-правило .tool-result-heading:focus; общий фокус кнопок, полей, ссылок и summary не отключён. Браузерный тест проверяет фактический фокус на h2, computed outlineStyle=none, затем Tab и видимый outline раскрываемой секции. На пяти ширинах заголовок занимает не более двух строк и не создаёт горизонтального переполнения. На viewport 375×812 конец первого практического шага находится внутри окна. Проверена клавиатурная работа закрытых других задач и вложенных подробностей. Обновлены реальные скриншоты; два новых снимка показывают viewport и раскрытые детали.

При разрешённой сервером интеграции функция в UI называется «Приоритеты с OpenAI», действие — «Уточнить приоритеты с OpenAI». До согласия явно сказано: модель расставляет приоритеты и выбирает подход из каталога, но не анализирует произвольное описание бизнеса и не проводит индивидуальную ИИ-диагностику. Те же границы отражены у поля описания и в результате. Текущий whitelist и tests, запрещающие отправку description, сохранены. Предложение следующего этапа — отдельный документ individual-ai-next-stage.md; это не реализация и не разрешение на внешнюю обработку.

На этапе упрощения страницы результата конфигурация OpenAI, .env.example, серверный endpoint и правовой gate не менялись; заключительный этап добавил общую серверную policy доступности без изменения gate. Railway не настраивался, OpenAI не включался, живые API-вызовы не выполнялись. Merge и deployment не выполнялись.

## Заключительная проверка версии без OpenAI

[Серверная политика доступности](availability-release.md) и UI скрывают недоступную функцию целиком, без публичных секретных настроек. На формах и результатах обеих страниц проверяется отсутствие OpenAI-контролов в DOM и ноль ИИ-запросов. Кодовый юридический gate остался false. Базовые формулы и перенос не менялись. Предыдущие проверки уведомления/consent для будущей интеграции остаются в серверных unit tests; в текущем выключенном UI такие элементы не предлагаются посетителю.

Финальный проход: 15 проверок ширины (два входных экрана и результат на 320/375/768/1024/1440 px), три пользовательских сценария, 0 page errors, 0 обращений браузера к API рекомендаций, 0 нарушений Axe на двух экранах результата. HTTP-проверка подтвердила Cache-Control: private, no-cache, no-store на обеих страницах; серверные имена переменных и тестовый ключ отсутствуют в HTML и .next/static. Прямой запрос к выключенному endpoint даёт 503. Сборка помечает оба маршрута как dynamic. Эти проверки не являются разрешением на merge/deploy.
