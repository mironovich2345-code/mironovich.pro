# Индивидуальный ИИ-разбор процесса — реализация и приёмка

Дата: 08.11.2026, Europe/Moscow. Основание: [Issue #8](https://github.com/mironovich2345-code/mironovich.pro/issues/8).
Ветка `feature/individual-ai-analysis` создана от фактического `main`:
`b46c9c65dbf131517ef2b07bc7cf3b2c4f4eb86c` (релиз PR #7).
Рабочее дерево перед началом было чистым; предыдущие ветки повторно не переносились.

**Реализован серверный путь для настоящего анализа свободного текста через OpenAI Responses API.**
Он не сортирует каталог и не собирает итог из прежних рекомендаций: модель пишет собственное
понимание процесса, объяснение, действия, пилот, критерии и ограничения по строгой схеме.
Однако **живых вызовов модели в этой работе не было**. Доступ к production остаётся закрыт.
Синтетические ответы тестов и локальная демонстрация не выдаются за проверку качества живой модели.

## Сценарий и совместимость

На `/tools/automation-cost` сначала работает прежний бесплатный результат без внешнего API.
Когда сервер разрешит отдельную функцию, после него появится «Разобрать мою ситуацию с ИИ».
Если выбрано несколько задач, пользователь выбирает одну. Достаточно одного описания длиной
60–1800 символов. Два уточнения — инструменты и последствия ошибки, до 240 символов каждое —
добровольно раскрываются только если в описании не хватает деталей. Дополнительных раундов
вопросов модель не запускает.

Перед отправкой показывается точная строка `processText(input)`, которая станет `input`
запроса OpenAI. Категория, описание и заполненные уточнения видны целиком. Есть отдельное
уведомление, проверка текста и checkbox; изменение любого поля или возврат к редактированию
сбрасывает согласие. Без явной кнопки POST отсутствует. Согласие на заявку его не заменяет.
Уведомление имеет отдельную черновую версию `process-analysis-notice-draft-1`; оно не публикуется
в production и должно пройти юридическое согласование до снятия gate.

Заключение доступно без формы. Оно содержит решение «автоматизировать / пилот / пока не стоит»,
подход, гипотезы пользы, последовательность из 3–5 действий, проверки, пилот, критерии успеха,
риски и неизвестные обстоятельства. Есть одно действие «Обсудить внедрение» с прежней формой
заявки. Новый текст и ответ модели автоматически в заявку не добавляются; существующая форма
сохраняет самостоятельное редактирование и согласие. Сервер лидов продолжает доверять только
проверенным параметрам и своему пересчёту, а не результату модели.

Возврат к базовому результату сохраняет его и возвращает клавиатурный фокус. При отказе,
лимите, ошибке, таймауте или непроверенном ответе базовые карточки остаются на странице.
Расчётные формулы, денежная модель автоматизации, юридические документы и старый endpoint
`/api/tools/recommendation` не изменены. Прежние приоритеты OpenAI по-прежнему закрыты своим gate.

## Контракт и ограничения

- Новый endpoint: `POST /api/tools/process-analysis`, контракт `process-analysis-1`.
- Whitelist верхнего уровня: `version`, `noticeVersion`, `consent`, `input`.
  В `input` только `task`, `description`, `tools`, `consequence`. Массивы задач,
  дополнительные поля, файлы, контакты, замеры и клиентские результаты не принимаются.
- Только same-origin JSON UTF-8; cross-site отклоняется. Проверка реального Host следует
  существующей proxy-схеме; `X-Forwarded-Host` посетителя не используется.
- Ограничение запроса: 4000 символов / 16000 байт потока, строгий UTF-8, чтение не дольше
  5 секунд. Неправильный JSON и примитивы дают контролируемые 400, переполнение — 413.
- До внешнего вызова одинаковые локальная и серверная проверки выявляют типовые контакты,
  URL, номера документов/счетов, токены, пароли, некоторые имена, медицинские личные сведения,
  управляющие символы и явные инструкции модели. Подозрительный текст отклоняется с предложением
  исправить; модель не используется для «очистки».
- Текст передаётся как недоверенный `input` с отдельными системными правилами. Нет browsing,
  tools, доступа к CRM, файлам или действиям. Ключ только в серверном Authorization,
  cookies и IP посетителя не проксируются. Redirect внешнего запроса запрещён.
- `store:false`, `service_tier:default`, `reasoning.effort:none`, `max_output_tokens:1800`.
  Повторов нет. Таймаут 15 секунд включает fetch, чтение и проверку ответа, с AbortController
  и независимым Promise.race. Клиент ограничивает ожидание 22 секундами.
- Structured Outputs: `text.format.type=json_schema`, `strict:true`, обязательные поля,
  `additionalProperties:false`, ограниченные длины/массивы и enum. Оболочка Responses,
  snapshot, completed, usage и текст повторно проверяются на сервере.
- Запрещаются числовые обещания, финансовые оценки, гарантии, неподтверждённые утверждения
  об API, типовые автономные рискованные действия и противоречие «ждать, но запускать».
  При серьёзных/неизвестных последствиях не принимается решение о готовом запуске.
  Контроль человеком обязателен. Проверяется минимальная связь понимания с деталями ввода.
  Любое несоответствие даёт fallback, а не показ частично проверенного текста.

## Устойчивый контроль расходов

Выбран PostgreSQL с общей таблицей бюджета и журналом резервирований:
[схема](process-analysis-budget.sql), `lib/tools/process-analysis-budget.ts`.
Схема **не применялась к Railway или внешней базе**. Проверки выполнялись в одноразовом локальном
контейнере PostgreSQL 17; платные ресурсы не создавались.

Все реплики используют один `PROCESS_ANALYSIS_BUDGET_ID`. Строку с конечным периодом действия,
моделью, лимитом запросов и суммой финансирует только оператор после согласования. Приложение
не создаёт бюджет, не пополняет его и не меняет даты/максимумы. В транзакции `SELECT ... FOR UPDATE`
сериализует проверки и списание; до вызова модели резервируется полная верхняя оценка, затем
создаётся запись с UUID. Счётчики сохраняются после рестартов приложения.

Одновременно проверяются:

- конечный общий лимит запросов и зарезервированной суммы за профинансированный период;
- 30 внешних попыток за UTC-сутки и 5 за минуту на общий ledger;
- две активные операции на все реплики; аварийная lease истекает через 60 секунд;
- срок, разрешение, модель и размер резерва в общей строке.

Отсутствующая/просроченная строка, несовпадение конфигурации, ошибка TLS/БД или исчерпание
бюджета не допускают обращения к OpenAI. Резерв не возвращается при ошибке, отказе, обрыве
или неизвестном usage. Истечение lease освобождает конкурентность, но не потраченную квоту.
Usage за пределами проверенных границ отключает общую строку бюджета до ручной проверки.
Сбой записи outcome оставляет резерв потраченным. Если БД недоступна, следующие запросы закрыты.

Дополнительный процессный антиспам-лимитер не является финансовой защитой; финансовая защита
находится в PostgreSQL. Удалять ledger, восстанавливать его старую копию в активный сервис или
раздавать разным репликам независимые бюджеты нельзя: это нарушит общий предел. Runtime-роль
не должна иметь права удалять/создавать бюджеты, менять максимумы или схему; разрешения описаны
в SQL. Ключ OpenAI нужен от отдельного ограниченного проекта; этот ledger ограничивает данную
функцию, а не посторонние вызовы того же ключа.

### Модель, стоимость и наблюдаемость

Выбран только snapshot `gpt-5.4-mini-2026-03-17`. На 08.11.2026 его наличие подтверждено в
[официальном SDK OpenAI](https://github.com/openai/openai-python/blob/main/src/openai/types/shared_params/chat_model.py).
Контракты [JSON Schema](https://github.com/openai/openai-python/blob/main/src/openai/types/responses/response_format_text_json_schema_config_param.py)
и [Responses](https://github.com/openai/openai-python/blob/main/src/openai/types/responses/response_create_params.py)
также прочитаны из актуального официального SDK.

Сайты [модели](https://developers.openai.com/api/docs/models/gpt-5.4-mini) и
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)
недоступны из этой среды: proxy CONNECT 403. Доступность в конкретном аккаунте,
тариф, контекст и региональные условия **живым запросом не подтверждены**.

Кандидатный тариф из документации v2: вход $0.75 / миллион токенов, выход $4.50 / миллион.
В конфигурации задан кандидатный максимум контекста 400000 токенов. До отдельной проверки
поставщика/тарифа `providerAndPricingVerified=false` блокирует внешний вызов.
Резерв рассчитан с большим запасом на **весь** этот контекст и ограниченный выход, а не на
оценку токенизации пользовательского текста:

`400000 × 0.75 / 1000000 + 1800 × 4.50 / 1000000 = $0.3081` за попытку.

Реальные запросы намного меньше (сериализованное тело ограничено 24000 байт), но резерв
не уменьшается и скидка кеша не закладывается. Например, при явно профинансированных $5
пройдёт максимум 16 таких резервов ($4.9296), даже если лимит запросов выше. Это пример
работы ledger, **не созданный бюджет и не подтверждённая цена будущего вызова**. После проверки
реальных тарифов/контекста и возможных региональных надбавок их нужно согласованно зафиксировать
в коде и строке бюджета перед включением.

В синтетической оболочке тестов usage равен 2300 input / 950 output: арифметика даёт $0.006
по кандидатному тарифу. **Это фикстура, не измерение биллинга OpenAI.** Фактическая цена,
латентность, частота отказов и полезность ответа остаются предметом controlled staging.

Ledger хранит только случайный UUID, бюджет, технические даты, outcome, резерв, количества
токенов и расчёт usage в micro-USD. Содержания запросов/ответов, IP, контактов и visitor ID нет.
Для мониторинга суммируются `reserved_micro_usd`, `usage_micro_usd`, число попыток и outcomes;
по ним можно сравнить резерв с usage без журналирования текста. Драйверские и provider errors
наружу и в application logs не выводятся. Инфраструктурные access logs нужно отдельно проверить
перед staging: `store:false` не означает zero data retention у поставщика.

Новый управляемый PostgreSQL не заказывался. При использовании уже одобренного общего сервиса
дополнительная нагрузка — небольшие транзакции и журнал, но бесплатность не обещается.
Фиксированная инфраструктурная цена не определена без выбора провайдера, плана, региона,
хранилища, резервных копий и реплик. Пул ограничен тремя соединениями на экземпляр приложения.
Тариф и эксплуатацию общей БД нужно утвердить отдельно; локальные тесты не подтверждают SLA
или стоимость production-инфраструктуры.

## Threat model

| Угроза | Защита и проверка | Остаточная граница |
| --- | --- | --- |
| Подмена браузерного флага, отсутствие ключа/разрешения | Независимые серверные gate, exact snapshot, конфигурация БД; тесты отсутствующих условий | Разрешения снимаются только после отдельной приёмки |
| CSRF и сторонний сайт | Origin/Host, запрет cross-site, JSON | Прямой злоумышленник может имитировать заголовки; его ограничивает общий бюджет |
| Длинное/медленное тело, повреждённый UTF-8 | Потоковые пределы, таймаут, 400/413 | Антиспам приложения не заменяет защиту инфраструктуры от сетевого DoS |
| PII/секреты/документы в описании | Предупреждение, точный preview, отдельное согласие, локальный и серверный отказ до вызова | Regex не распознаёт все имена, обфускацию, коммерческие секреты или смысл личных сведений; гарантии анонимизации нет |
| Prompt injection и извлечение секретов | Недоверенный input, отдельные инструкции, фильтр явных атак, нет tools/соседних диалогов/ключа в prompt | Смысловую инъекцию нельзя полностью исключить; результат предварительный и контролируется человеком |
| XSS, SSRF, действие в рабочих системах | React text rendering, запрет разметки/URL, фиксированный endpoint с redirect:error, нет вызова сторонних API | Приложение ничего не исполняет по рекомендации модели |
| Неверный JSON, отказ, incomplete, неподходящий snapshot | Strict schema + серверная проверка envelope/содержания + клиентская проверка | Structured Outputs не доказывает правдивость или полезность |
| Придуманные деньги, API, автономное рискованное решение | Ограниченная схема, текстовые запреты, semantic boundaries, пилот/ожидание при риске | Автоматическая смысловая проверка неполна и может отклонить корректный ответ; нужен живой синтетический eval |
| Рестарт/гонки реплик/недоступная БД | Общая транзакционная строка, нерефандируемый резерв, fail closed; реальные PostgreSQL-тесты | Надёжность хранения и права оператора обязательны; откат ledger нарушит предел |
| Неизвестный счёт при таймауте | Резерв остаётся потраченным; повторов нет | Резерв консервативен; его связь с ценой зависит от проверенного тарифа/контекста |
| Утечка через аналитику/лид/хранилище | Новый текст только в памяти страницы, без URL/storage/аналитики; нет автоматического переноса в заявку | Инфраструктурные логи и договорные сроки поставщика требуют отдельной проверки |
| Случайное включение демонстрации | Только явный mock-флаг, loopback Host, запрет при Railway/VERCEL; исходящие вызовы отсутствуют | Mock не предназначен для публичного сервиса; в production переменная должна оставаться пустой |

- `npm run test:analysis-budget`: **11/11**, без пропусков; настоящий локальный PostgreSQL 17.
  Проверены параллельные пулы и независимые процессы приложения, гонки, restart без возврата
  резерва, минутный/суточный/денежный пределы, lease, trip, rollback и недоступность БД.
- `npm run lint`, `npm run typecheck`, `npm run build`: успешно. Сгенерировано 54/54 статических
  страницы; динамические инструменты и API собраны. Release guard не обходился.
- `npm audit --omit=dev`: 0 уязвимостей. Новые runtime-зависимости — `pg`; типы — dev-only.
- Chromium: 320/375/768/1024/1440 px; обе базовые формы и перенос, один выбранный процесс,
  локальный PII-отказ, preview/сброс согласия, явная отправка, результат/возврат и контактная форма.
  Пример **66 ч и 39 600 ₽/мес** сохранён. Горизонтального переполнения и ошибок JavaScript нет.
- Axe-core 4.10.3, WCAG 2 A/AA и 2.1 AA: в preview и результате на пяти ширинах — 0 нарушений.
  Это автоматическая проверка проверенных состояний, не полная сертификация доступности.
- Ошибки 429/502/503 проверены браузерными заглушками; 3 ожидаемые HTTP-ошибки консоли,
  неожиданных нет. Реальных заявок в Telegram и внешних запросов OpenAI не было.

модели на этих же искусственных ситуациях, включая отказы и ложные блокировки валидатора.

| Контроль | Напоминания, переходы согласования |
| Нестандартные | Учебная лаборатория, мастерская, выставка, кадровое решение — отложить, учебное медицинское расписание, редкий неустойчивый процесс — отложить |

## Воспроизведение и go/no-go

Обычные проверки: `npm ci`, `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`.
Для интеграционного теста нужна отдельная **локальная одноразовая** PostgreSQL-база:
задайте `PROCESS_ANALYSIS_TEST_DATABASE_URL`, затем `npm run test:analysis-budget`.
Тест откажется работать с нелокальным адресом; создаёт и удаляет только собственную случайную схему.

Для UI после сборки запустите два локальных сервера:

```sh
npm start -- --port 3001 --hostname 127.0.0.1
# В другом терминале, без изменения .env или production:
PROCESS_ANALYSIS_ENABLED=true PROCESS_ANALYSIS_MODE=mock npm start -- --port 3002 --hostname 127.0.0.1
# Нужны Python Playwright и Chromium; optional AXE_SCRIPT — путь к axe.min.js:
python scripts/test-process-analysis-browser.py
```

**Go:** ревью реализации, локального UI и контрактных/бюджетных тестов в Draft PR.
**No-go:** включение OpenAI в production и утверждение качества живого консультанта.
Для снятия блокировки требуются согласованные юридические основания и опубликованное
уведомление, проверка стран/контрагента/сроков/региональной доступности, реальных access logs,
актуального тарифа и контекста модели; ограниченный проект/ключ; одобренный общий PostgreSQL
с конечным бюджетом и правами; controlled staging на синтетических кейсах с реальным usage
и ручной рубрикой полезности. Лишь после этого — отдельное решение владельца об изменении
обоих кодовых gate и серверных переменных. Старое разрешение на выпуск legal-текстов не расширялось.

В данной работе оба новых gate `false`, `PROCESS_ANALYSIS_ENABLED` по умолчанию `false`;
ключи/бюджет не настроены. Production UI не показывает новый ИИ-контрол, API не вызывает модель.
Merge, деплой, Railway, рабочие секреты и опубликованные юридические документы не изменялись.
