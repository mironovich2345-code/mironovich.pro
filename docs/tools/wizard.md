# Пошаговый интерфейс (этап 3B)

Checkpoint первоначальных калькуляторов: `ecc429ccb602c3161b7f9fcd80fc64f84bebd890`.

Ручной труд: шесть шагов — процесс, сотрудники, частота/дни, длительность,
стоимость времени, потенциальная доля автоматизации. Месячные затраты и часы
преобразуются в ставку внутри `laborAnswers`. Неизвестная ставка передаётся как
`null`: часы считаются, денежные результаты не выводятся. Ноль остаётся известным
нулём. Скрытые поля другого способа ввода не используются. Название «другого»
процесса необязательно и не входит в канонический контекст заявки/хранилища.

Автоматизация: семь шагов, либо шесть для полностью ручной работы. В последнем
случае вопрос о подключении программ пропускается; число связей равно нулю по
смыслу ответа, старые API и число интеграций исключаются. Выбор программ и
действий множественный, вариант «вручную» исключает программы. Неизвестные
состояние данных и нагрузка остаются `unknown`; часы и сложность по числу часов
тогда не выдумываются. Рекомендация возможна по известным ответам, но требует
проверки при разборе.

`lib/tools/wizard.ts` преобразует ответы в существующие модели, которые повторно
валидируют параметры. ИИ запрашивается для смысловой обработки, ответов и
предложения решений; существующие правила модели определяют его уместность,
в частности документы/знания. Обычный перенос не включает ИИ автоматически.
Числовые формулы и коэффициенты для известных данных не менялись.
`approvedByOwner` и `publicPricingEnabled` по-прежнему false.

`Wizard` отвечает за текущий шаг, прогресс, валидацию и фокус. Ответы находятся
в родительских компонентах и сохраняются при возврате и редактировании результата.
Ошибкам выделено постоянное место. Полного сброса без подтверждения нет.
Результаты появляются только после последнего шага; на вопросах нет колонки
результатов. Денежная модель, проверки формы и серверный пересчёт сохранены.
