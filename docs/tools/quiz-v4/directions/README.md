# Два направления UX: A / B

9 ноября 2026 · ветка `feature/tools-quiz-v4` · **ожидают визуального утверждения**.

Перед изменениями изучены все 11 исходных скриншотов из родительской папки:
оба инструмента, desktop/mobile, график, зарплата и перенос расчёта. Исходники и
снимки предыдущего варианта сохранены. Рабочее приложение не редактировалось.

## Что упрощено в обоих вариантах

- Desktop: пять свёрнутых строк ручного труда — задача, сотрудники, частота,
  продолжительность, график и расходы. Открывается одна строка; изменения действуют
  сразу, без сохранения или подтверждения. Закрытие строки сохраняет ответы.
- Mobile: один основной вопрос; компактный прогресс без процентов; один живой
  промежуточный итог и «Продолжить» снизу. Нет повторяющегося заголовка страницы
  и постоянных технических предупреждений. Обычно семь вопросов, при нескольких
  процессах частота и длительность уточняются для каждого; число шагов обновляется.
- Сотрудники — только число с +/−. Частота — ползунок с точным числом. Длительность —
  популярные значения и «Другое» с точным вводом минут/часов. Зарплата — одно поле;
  вид суммы выбирается отдельно, без ползунка. Нет набора всех способов ввода сразу.
- График — компактный выбор. Месяц и фактические смены доступны в раскрытии;
  ориентировочный характер графика обозначен рядом и в результате. Для «Другой»
  ввод фактических смен раскрывается сразу.
- Результат — одна большая сумма, часы и годовая стоимость, два коротких статуса,
  «Почему такой вывод?» и один основной CTA. Метод расчёта и подробные ограничения
  доступны в раскрытии. Ошибки, превышение рабочего времени, вид месячной суммы
  и отличие стоимости времени от экономии остаются заметными.
- Второй инструмент: аналогичная компоновка; четыре вопроса при прямом входе.
  Известные данные из расчёта труда не спрашиваются повторно. Для проблемы времени
  и полного переноса остаются два вопроса; при неопределённой проблеме и переносе —
  один. Без переноса неопределённая проблема всё ещё требует выбора процесса.
- Непроверенные готовые продукты и проценты экономии не обещаются. Качественные
  статусы не означают подтверждённой применимости или индивидуального ИИ-анализа.

## Сравнение и рекомендация

| Критерий | A — Minimal Dark | B — Light Workspace |
| --- | --- | --- |
| Представление | Мягкая графитовая поверхность, светлый текст | Тёплая светлая рабочая область, тёмный текст |
| Связь с сайтом | Продолжает тёмный фон без заметного перехода | Тёмная шапка и окружение сохраняются; калькулятор выделен светлой областью |
| Впечатление | Сдержанный инструмент в общей атмосфере сайта | Ближе к привычному финансовому калькулятору, отдельное спокойное место для работы с числами |
| Акценты | Светлый красный показатель, красный CTA, мягкое выделение выбора | Глубокий красный показатель и CTA на светлой поверхности |
| Компромисс | Тёмная поверхность сохраняет более плотное общее впечатление | Переход от тёмного сайта к светлой области заметнее |
| Взаимодействие | Компактные строки и отдельные мобильные вопросы | То же взаимодействие и те же расчёты — сравниваем именно визуальное представление |

**Рекомендация — B.** Светлая рабочая область лучше отделяет расчёт от маркетинговой
страницы и ближе к запрошенному образу ипотечного калькулятора. A подходит,
если приоритетом останется непрерывность тёмного оформления. Это дизайнерская
рекомендация, а не вывод по конверсии или результат пользовательского A/B-теста.

```sh
python docs/tools/quiz-v4/directions/export-directions.py docs/tools/quiz-v4/directions/standalone
```

В экспорт включаются существующие шрифты без изменения и полные тексты их лицензий
Inter OFL / Roboto Condensed Apache 2.0. Новые шрифты не загружались. Экспорт не
обращается в сеть; HTML можно скачать и открыть локально в браузере.

## Проверка

```sh
AXE_PATH=/path/to/axe.min.js python docs/tools/quiz-v4/directions/check-directions.py
```

Нужны существующие Python Playwright и Chromium. Скрипт не устанавливает пакеты,
поднимает сервер только на loopback и сохраняет [машинный отчёт](checks.json).
`CHROMIUM_PATH` позволяет указать браузер. Без `AXE_PATH` используется локальный
`node_modules/axe-core/axe.min.js`, если он есть; выполненные аудиты указаны в JSON.

Проверены:

- Байтовое совпадение расчётных функций с исходным прототипом и сравнение
  результатов на 54 комбинациях: 6 графиков × 3 периода × 3 вида месячной суммы.
- Оба инструмента, оба направления, desktop/mobile: полное прохождение, возврат,
  мгновенный пересчёт, ползунок с клавиатуры, +/−, сохранение ответов при раскрытии.
- Все графики, фактические и приблизительные смены, диапазон начала цикла,
  недельные/месячные/сменные единицы без двойного множителя, отсутствие раннего
  округления ставки, перевод минут в часы.
- Неизвестная зарплата, зарплата и полные расходы, несколько процессов без общего
  итога, видимые ошибки дробного числа сотрудников и некорректных смен/месяца,
  очистка показателей при снятии выбора всех процессов.
- Прогресс 7/9 шагов в ручном труде, условные шаги второго инструмента, перенос
  расчёта без повторного опроса. На mobile в DOM виден один основной вопрос.
- Сумма и CTA помещаются в первом viewport результата на 1440/375 px.
- Горизонтальное переполнение обоих инструментов и тем на 320/375/768/1024/1440 px.
- Axe WCAG A/AA: на всех 24 снятых экранах нарушений не обнаружено.
- В пройденных сценариях нет JavaScript-ошибок, внешних запросов и POST-запросов,
  включая нажатие CTA. Заявки в прототипе не отправляются.
- Оба автономных HTML проходят расчёт и перенос во второй инструмент без сети.
  ESLint всего репозитория и синтаксические проверки новых JS/Python проходят.
