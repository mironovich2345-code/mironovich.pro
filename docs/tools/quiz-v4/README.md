# Калькуляторы v4 — адаптивный UX-прототип

Статус: **ожидает утверждения UX**. Основа — `main` на коммите
`bde2956a8e69db231f3265fcac354de29041a226`. Ветка — `feature/tools-quiz-v4`.
Изменения в этой версии ограничены прототипом и документацией. Рабочие маршруты,
расчёты v3, обработка заявок, согласия, Railway и отдельный PR #9 не изменены.

## Предлагаемое взаимодействие

**Desktop, от 901 px:** параметры слева, закреплённый результат справа.
Ползунки, переключатели, точные поля и быстрые значения обновляют показатели
сразу. Кнопки «Рассчитать» нет. Зарплата вводится только числом; график выбирается
карточками, фактические смены можно указать отдельно.

**Mobile:** четыре небольшие смысловые группы для ручного труда:

1. Работа и сотрудники — множественный выбор, начальные 4 человека, +/−, пресеты.
2. Повторения и время — период, частота, минуты или часы на выполнение.
3. График и рабочие часы — календарная оценка или фактические смены, часы в смену.
4. Зарплата или полные расходы — собственная сумма или «Не знаю».

Под текущей группой показан один главный промежуточный результат: участники,
операции/часы выбранного периода, часы за месяц, затем стоимость за месяц.
Показатели обновляются при изменении ответа; навигация назад сохраняет введённое.
После последней группы открывается полный результат с возможностью изменить ответы.

Второй инструмент использует ту же адаптивную схему. При прямом входе спрашивает
проблему, процесс, частоту проблемы и последствия. При переносе расчёта не
переспрашивает известные параметры. Для уже измеренной трудоёмкости и проблемы
«Много времени уходит на рутину» остаются два вопроса; прогресс пересчитывается.
Частота ошибок или задержек отличается от частоты операций и уточняется отдельно.

## Смысл результата и допущения

Главные показатели: стоимость времени в месяц, часы ручной работы в месяц,
годовая стоимость при той же нагрузке. Если зарплата неизвестна, суммы не
подставляются. Зарплата и полные расходы работодателя обозначаются отдельно.
Стоимость рабочего времени не является обещанием экономии.

Потенциал автоматизации и применимость готовых решений — качественные гипотезы.
Не утверждается наличие конкретной функции, интеграции, доступа или готового
продукта. Нет процентов автоматизации, цены разработки или прогноза экономии.
Консультация предлагается для проверки узких мест, целесообразности изменений,
выбора решения и условий пилота.

Для 5/2 и 6/1 календарная оценка исключает выходные, но не учитывает праздники и
отпуска. Для циклов 2/2, 3/3 и 3/2 показываются среднее и диапазон в зависимости
от начала цикла. Фактическое количество смен заменяет календарное допущение.
Повторы за смену масштабируются по сменам, за неделю — по дням месяца / 7,
за месяц — без дополнительного множителя. Ставка рассчитывается без раннего округления.
Несколько процессов сохраняют отдельные значения; общего итога без проверки
пересечений нет. Базовый режим применяет одну зарплату и график к выбранной группе.

Контрольный пример содержит **введённые тестовые данные**, а не значения по
умолчанию: 3 сотрудника × 20 повторений × 3 минуты × 22 фактические смены =
66 ч/мес. При 8-часовой смене и указанных полных расходах 105 600 ₽ ставка
равна 600 ₽/ч, стоимость — 39 600 ₽/мес и 475 200 ₽/год.

## Интерактивный просмотр

Исходник — [prototype.html](prototype.html), без зависимостей JavaScript.
Оба режима находятся в одном документе; переключение доступно в шапке.
Параметр `?mode=auto` открывает второй инструмент напрямую.
Использованы существующие локальные шрифты репозитория с его лицензиями.

Прототип не отправляет заявки, не подключает аналитику и не сохраняет ответы
во внешние системы или хранилище браузера.
CTA показывает сообщение о демонстрационном режиме. Ответы живут в памяти страницы.
Это проверка взаимодействия, а не новая production-версия калькуляторов.

## Проверки прототипа

Запуск в среде с Python Playwright и Chromium:

```sh
python docs/tools/quiz-v4/check-prototype.py
```

Скрипт поднимает локальный сервер на случайном порту, доступный только с loopback,
проверяет интерфейс и обновляет скриншоты с [отчётом JSON](prototype-check.json).
Путь к браузеру можно задать через `CHROMIUM_PATH`; к существующему Axe — через
`AXE_PATH`. Axe запускается, если файл доступен; выполненные проверки перечислены
в JSON. Автоматических загрузок зависимостей нет.

Пройдено: оба сценария на 1440/375 px, мгновенный пересчёт, отсутствие начальной
зарплаты, все шесть графиков, фактические смены и календарный диапазон,
единицы частоты, переключение минут/часов, клавиатура ползунка, точный ввод,
+/− и быстрые значения, неизвестная зарплата, различие зарплаты и полных расходов,
несколько процессов без суммирования, возврат назад, перенос между инструментами.
Переполнение дополнительно проверено на 320, 768 и 1024 px для состояния с
несколькими процессами. В проверенных сценариях нет JavaScript-ошибок и POST-запросов.
Axe WCAG A/AA не обнаружил нарушений на шести экранах, перечисленных в JSON;
это автоматическая проверка прототипа, не подтверждение полной доступности продукта.

## После утверждения

Окончательный дизайн ещё не подключён к приложению. После утверждения нужно
перенести интерфейс в существующие компоненты, сохранить серверный пересчёт и
совместимость контекста v3/PR #9, добавить восстановление в пределах вкладки и
навигацию браузером, расширенный режим групп сотрудников и проверки заявок.
Аналитика прохождения должна учитывать существующее согласие и передавать только
тип инструмента, этап и действие, без ответов, зарплат и финансовых значений.
Затем потребуются модульные тесты, lint, TypeScript, production build и полные
браузерные проверки рабочего приложения. Эти проверки не подменяются отчётом
прототипа и пока не заявляются как выполненные для v4.
