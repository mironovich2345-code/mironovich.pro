# React-калькуляторы v4 — направление B

11 ноября 2026. Реализованы обе страницы через существующий адаптер GuidedCalculator.
Desktop: пять раскрываемых строк, живой результат справа. Mobile: один вопрос,
условный прогресс, промежуточный результат, назад/вперёд. Контрольный пример:
3 × 20 × 3 мин × 22 фактические смены = 66 ч; 105600 / (22 × 8) = 600 ₽/ч;
39600 ₽/мес, 475200 ₽/год. Зарплата не подставляется, экономия не обещается.

Модель v4 использует действующий валидатор и расчёт v3, расширяя их графиками смен.
Существующие версии контекста и client resultExtension для PR #9 сохранены.
OpenAI не подключался; оба флага денежной модели автоматизации остались false.

CTA консультации появляется только после валидного содержательного результата.
Используется существующий LeadForm, его согласие, защита и состояния ошибок.
Передаются только разрешённые исходные поля; сервер повторно валидирует и пересчитывает.
Свободный текст не сохраняется в checkpoint и не попадает в аналитику. Числовое
состояние сохраняется в sessionStorage вкладки с TTL 24 часа; storage необязателен.
Аналитика этапов разрешена только при granted и содержит tool/step, без ответов.

Проверки: 214/214 unit tests, ESLint, TypeScript, production build — PASS.
Браузер: 320/375/768/1024/1440, полный ручной расчёт, клавиатура ползунка, перенос,
прямой вход во второй опрос, отсутствие раннего CTA, no overflow / JS errors.
Axe WCAG A/AA калькулятора: нарушений не обнаружено на пяти ширинах.
Реальный POST /api/lead прошёл согласие, серверную проверку и пересчёт. Только
доставка Telegram заменена тестовым preload с синтетическими credentials; внешних
сообщений не было. Подтверждены 39600/475200 и serverRecalculated.

[Машинный браузерный отчёт](react-browser-report.json), [скриншоты](react-screenshots/).
Сценарий: `TEST_BASE_URL=http://127.0.0.1:3031 AXE_PATH=/path/axe.min.js python docs/tools/quiz-v4/check-react.py`.
Сервер для сценария должен работать с tests/fixtures/cost-why-telegram-stub.mjs и
явными тестовыми credentials (см. защитные проверки внутри fixture). Никогда не
подключать fixture к production. Нужны существующие Python Playwright / Chromium.

Ограничения: расписание — календарная иллюстрация без праздников/отпусков, если
не заданы фактические смены; протокол маркирует основание расчёта. На экране один
процесс, остальные доступны отдельно; без подтверждения независимости итоги не
складываются. Серверная модель поддерживает группы, UI сознательно использует одну
общую группу. Результат не доказывает наличие продукта или устранимой экономии.
Сборка сообщает прежние юридические предупреждения и локальный fallback rate limit;
юридические документы и инфраструктура не менялись. Это не разрешение на релиз.
