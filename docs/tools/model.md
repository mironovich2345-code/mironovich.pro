# Модель инструментов — на утверждение владельцем

Версия: `automation-2026-11-07-draft-1`. Дата: 7 ноября 2026 года.
Источник: `config/automation-model.ts`. Все числа ниже — **начальные инженерные
гипотезы**, не исследование рынка, не тариф MIRONOVICH и не коммерческая оферта.
Владелец их пока не утвердил. `approvedByOwner = false` и
`publicPricingEnabled = false`: бюджет, денежные диапазоны регулярных расходов
и окупаемость в публичном интерфейсе и серверном описании заявки отключены.
Показанные часы также обозначены как гипотеза, требующая проверки.

## Трудоёмкость и ставка

| Этап | Начальный диапазон | Условие |
|---|---:|---|
| Анализ требований | 4–8 ч | Всегда |
| Проектирование | 4–12 ч | Всегда |
| Интеграции | 6–16 ч на связь | Число связей 0–20; до проверки API это условная оценка |
| Backend / настройка обработки | 8–24 ч | Всегда; для SaaS — настройка логики, не обещание собственной разработки |
| Frontend | 12–32 ч | Если нужен отдельный интерфейс |
| Подготовка документов | 8–24 ч | Если документы выбраны явно или процесс — документы |
| ИИ-компоненты | 16–48 ч | Только если ИИ запрошен и есть документы / поиск по знаниям |
| Тестирование | 20–35% | От суммы предыдущих этапов, до развёртывания |
| Развёртывание | 4–8 ч | Всегда |
| Ставка для проверки гипотезы | **3 000 ₽/ч** | Не опубликованный тариф; требует утверждения |

Доли тестирования применяются к соответствующим границам: 20% к минимальной,
35% к максимальной. Часы этапов округляются вверх до целого. Бюджет — сумма
часов × ставка; все денежные вычисления округляются до копеек.

| Фактор | Коэффициенты | Применение |
|---|---|---|
| Данные | чистые ×1; смешанные ×1,25; плохие ×1,6 | Анализ, проектирование, интеграции, backend, документы и ИИ |
| Нагрузка | до 100 операций/день ×1; 101–1 000 ×1,25; более 1 000 ×1,5 | Все базовые этапы; тестирование следует изменённому объёму |
| API отсутствует или неизвестен | ×2 | Только часы интеграций; реализуемость не подтверждена |
| Число сотрудников | Не умножает часы | Контекст задачи; роли, права и одновременная работа уточняются при разборе |

Сложность определяется по верхней границе часов: до 80 — низкая, до 200 — средняя, выше — высокая.

Нагрузка — грубая категория, а не нагрузочный тест. При отсутствии API модель
не доказывает возможность интеграции. Даже для рекомендуемого SaaS нужно
проверить наличие подходящего продукта. Коэффициенты не заменяют исследование.

## Ежемесячные расходы — отдельные гипотезы

| Статья | Начальный диапазон | Условие |
|---|---:|---|
| Инфраструктура | 1 000–4 000 ₽ | Умножается на коэффициент нагрузки |
| Внешние сервисы / API | 0–1 500 ₽ на интеграцию | Тарифы проверяются отдельно |
| ИИ при низкой нагрузке | 500–3 000 ₽ | Только если ИИ рекомендован |
| ИИ при средней нагрузке | 3 000–15 000 ₽ | То же |
| ИИ при высокой нагрузке | 15 000–60 000 ₽ | То же; без расчёта токенов это особенно неопределённо |
| Сопровождение | 2–6 ч × ставка | Если запрошено; это не SLA и не обещание включённых доработок |

## Ручной труд

Версия `labor-1.0.0`:

- Часы/мес = сотрудники × операции/день на сотрудника × минуты / 60 × дни.
- Стоимость/мес = часы × полная стоимость часа, округление до копеек.
- Стоимость/год = округлённая стоимость/мес × 12.
- Потенциально высвобождаемые часы = исходные часы × доля / 100.
- Стоимость этого времени = стоимость/мес × доля / 100.

Пример: 3 сотрудника × 20 операций × 3 минуты / 60 × 22 дня = **66 ч/мес**.
При 600 ₽/ч: **39 600 ₽/мес**, **475 200 ₽/год**.
При доле 50%: **33 ч/мес**, стоимость времени **19 800 ₽/мес**.
Это стоимость ресурса, а не гарантированная денежная экономия.
Нули разрешены. Неконечные числа, отрицательные значения, доля >100%,
дробное число сотрудников/операций/дней и превышение лимитов отклоняются.
При совокупном объёме >100 млн ч/мес или >1 трлн ₽/год нужно разбить процесс:
это защита точности вычислений, не оценка реального размера бизнеса.

## Окупаемость

Стоимость высвобождаемого времени никогда автоматически не становится денежной
выгодой. После утверждения модели доступны необязательные поля подтверждённой
пользователем денежной выгоды и остаточных затрат ручной работы.

Чистая выгода = денежная выгода − регулярные расходы − остаточный ручной труд.
Если она положительна во всём диапазоне, срок = бюджет / чистая выгода.
Минимум срока = минимальный бюджет / максимальная чистая выгода;
максимум — максимальный бюджет / минимальная чистая выгода. Срок округляется
вверх до 0,1 месяца. При неполных данных, нулевой или отрицательной чистой выгоде,
а также при выключенной денежной модели срок отсутствует. Это статический
сценарий без дисконтирования, налогов и периода выхода на плановую нагрузку.

## Перед включением денежной модели

1. Владелец проверяет диапазоны часов, ставку, коэффициенты и регулярные расходы.
2. Проверяет репрезентативные сценарии и пределы применимости, отдельно SaaS и API без доступа.
3. Утверждает новую версию/дату и выставляет оба флага: `approvedByOwner` и `publicPricingEnabled`.
4. Обновляются публичные пояснения и metadata, сейчас явно сообщающие об отключённых денежных оценках.
5. Повторяются тесты денежной модели, серверного пересчёта и браузерного интерфейса.

## Передача данных и заявки

Числовые параметры ручного труда переносятся через `sessionStorage` только
в текущей вкладке, со сроком 24 часа и проверкой версии. Название и свободный
текст не сохраняются. Очистка URL не менялась. При недоступном хранилище можно
продолжить без переноса. На сервер ничего не отправляется до отправки формы.

Заявка содержит только разрешённые параметры контекста, а показатели сервер
пересчитывает заново. Клиентские суммы, лишние поля и произвольные названия
не используются. Описание задачи передаётся как обычное редактируемое поле
формы; на сервере проверяются его тип/длина и экранируется HTML. Отдельные
секции Telegram-сообщения ограничены по длине без разрыва HTML-сущностей.
